description: NodeMP terms in plain language, with the Russian term and the explaining page - launcher, helper, client mod, content, directory, Test Drive, strict.
---

One line per term, the Russian term the Russian pages use, and the page that explains it. Every
page uses these words in exactly this sense; where the software itself prints another word (a log
line says `server browser`, a toast says `launcher` for the helper), the entry says so, and the
pages quote the software as it is. For how the parts fit together, read
[What is NodeMP](/introduction/what-is-nodemp/) first; the questions readers ask most are in the
[FAQ](/reference/faq/).

## For players

| Term | Russian | Definition | Explained on |
|---|---|---|---|
| **Launcher** | лаунчер | `nodemp-launcher.exe`, the Windows app you install: it signs you in (or lets you play as Test Drive), shows the server list, keeps the client mod current and starts a join with **Hold to play**. Version 1.1.6. It does not update itself: the [Download page](https://nodemp.com/download) shows the current version. | [Install the launcher](/players/install/) |
| **Helper** | хелпер | The part of the launcher that does the join itself: it starts BeamNG.drive, connects to the server and carries your traffic while you play. It is the same `nodemp-launcher.exe`, started a second time with `--helper` and without a window. The launcher's toasts call it "the launcher" (`The launcher stopped · …`, `Could not start the launcher · …`): they mean this process, not the window in front of you, and its log is `launcher.log`. Technically it holds the TLS 1.3 session with the server, downloads content and talks to the client mod over loopback TCP `4444` (commands) and `4445` (game traffic). A separately built `Node-Launcher.exe` exists only in developer builds. | [Troubleshooting](/players/troubleshooting/) |
| **Client mod** | клиентский мод | `NodeMP.zip`, the BeamNG mod that does the multiplayer work inside the game (BeamNG id `multiplayernodemp`, in `mods/multiplayer/` of the user folder). The launcher installs and updates it; you never copy it by hand. Version 1.5.0, built for BeamNG.drive 0.39.4.0. The website's "multiplayer mod" and "BeamNG mod" are this file. | [Install the launcher](/players/install/) |
| **Your mods** | ваши моды | The BeamNG mods you installed yourself, in `mods\` of the user folder. Not the client mod and not a server's content. They are switched off during a session unless you turn on *Use my local mods in multiplayer* and the server allows it; a strict session keeps them off. No verification level looks into `mods\`. | [Join a server](/players/join/#what-the-server-checks-on-your-pc) |
| **Content** | контент | The mod zips a server keeps in its `content/` folder and sends to joining players; the helper downloads them into `mods/multiplayer/` before the game enters the world. The launcher calls their total size *Required mods* (the filter) and *Content* (the panel), and the loading screen calls each file a `Resource` (`Downloading Resource 2/5`) - all the same files. `Stock content` and `Stock only` mean the server sends nothing extra; they say nothing about your install. | [Join a server](/players/join/#the-server-list) |
| **Directory** | директория | Not a folder: the NodeMP service at `https://api.nodemp.com`. It holds accounts and sign-in, issues join tickets, builds the server list from the servers' beacons, gives hosts their server keys and publishes the launcher and client mod releases. | [Framework overview](/framework/overview/) |
| **Server list** | список серверов | The list of online, listed servers in the launcher (**Servers**) and, read-only, at [nodemp.com/servers](https://nodemp.com/servers), built from the beacons servers send to the directory. The server's log line `listed in the server browser` means this list. | [Join a server](/players/join/#the-server-list) |
| **Account** | аккаунт | A NodeMP account, created at [nodemp.com](https://nodemp.com) or in the launcher. It gives you a fixed name that servers verify with the directory. Optional for playing; a host needs one (with a verified e-mail and a linked Discord account) to create a server key. | [Install the launcher](/players/install/#accounts) |
| **Test Drive** | Test Drive | Playing without an account: the directory mints a fresh `Guest…` name for every join, and you cannot choose it. One server setting decides whether that is allowed, and it shows up under several labels: *Test Drive allowed* / *Account required* in the server panel, the *No account needed* filter, `Guest · a new name each session, and servers may refuse it` under Settings → Account, and `[Directory] TestDrive` in the host's `server.toml`. Unlike a sign-in, Test Drive is not remembered: the sign-in window opens at every launcher start and you press **Continue as Test Drive** again. | [Install the launcher](/players/install/#accounts) |
| **Guest** | гость | A player in Test Drive, as servers and the directory see them: the `Guest…` name, `player.guest` in a plugin. The pages say "Test Drive" for the mode and "guest" for the person. | [Install the launcher](/players/install/#accounts) |
| **Join ticket** | билет на подключение | A one-shot token the launcher requests from the directory for one server and sends right after the handshake. The server redeems it with the directory and takes the verified name from the answer. A server without a server key does not check tickets and takes names as the launcher sends them. | [Framework overview](/framework/overview/) |
| **Hold to play** | Hold to play | The join button: press and hold for about a second. There is no separate *Play* button. | [Join a server](/players/join/#joining) |
| **Direct Connect** | Direct Connect | The launcher form that joins a server by `host:port` (or `[addr]:port` for IPv6) instead of picking it from the list - for a private server, or one without a server key. The first join remembers the server's certificate (its fingerprint) and later joins refuse a server whose certificate changed. | [Join a server](/players/join/#direct-connect) |
| **Verification level** | уровень проверки | How much of your BeamNG install a server checks before it lets you in: `[General] VerifyGame` is `off`, `size` (the default), `scripts`, `full` or `strict`. Every level compares your game files with a list; only `strict` also looks at your user folder. | [Join a server](/players/join/#what-the-server-checks-on-your-pc) |
| **Strict server** | строгий сервер | A server with `VerifyGame = "strict"`: it compares your whole game folder, every game archive's table of contents and your BeamNG user folder with a reference manifest of a clean install before every join and again during the session. "Strict" in a toast means this. RU pages write the value as `strict` and the adjective as «строгий». | [Strict servers](/players/troubleshooting/#strict-servers) |
| **Reference manifest** | эталонный манифест | A file that describes a clean BeamNG install of one game version: every file's size and, for the code and the binaries, its SHA-256, plus the table of contents of every archive. The host generates it with `Node-Server --gen-integrity`; a strict server sends it to your launcher, which caches it and compares your install with it. Toasts call it "this server's reference", the join step `Downloading the server's integrity manifest`. Nothing is written into your game. | [Strict verification](/hosting/strict-verification/) |
| **Strict session** | строгая сессия | Something else than a strict server: a set of in-game rules a server resource switches on per player through `session:config.strict` - no free camera, no switching into other cars, local mods off, and so on. A strict server usually runs strict sessions too, but the two are separate mechanisms. | [Client scripting](/plugins/client-scripting/#strict-sessions-sessionconfigstrict) |
| **Fingerprint (TLS)** | отпечаток (TLS) | The SHA-256 of a server's self-signed TLS certificate, logged at every server start. Listed servers hand it to launchers through the directory; Direct Connect pins it on first use in `known_servers.json`. `[Directory] Fingerprint` in `server.toml` pins the *directory's* certificate, not the server's. | [Registering your server](/hosting/registering/) |

## For hosts

| Term | Russian | Definition | Explained on |
|---|---|---|---|
| **Host** | хост | The person who runs a `Node-Server`. Toasts and refusals say "ask the host"; these pages say "host", never "hoster". | [Quick start](/hosting/quick-start/) |
| **Server key** | ключ сервера | A **Host ID** and a **Host secret**, created at [nodemp.com/hosts](https://nodemp.com/hosts) and set as `[Directory] HostId` and `HostSecret` in the existing `[Directory]` table of `server.toml`. With `Url` they let the server open a host session with the directory, send beacons and redeem join tickets. Creating one needs an account with a verified e-mail and a linked Discord account. | [Registering your server](/hosting/registering/) |
| **Beacon** | маяк | The report a registered server sends to the directory every 15 s by default: name, map, players, capacity, content names and size, the `Public` and `TestDrive` flags and the version. The server list is built from beacons; when they stop, the listing lapses. | [Registering your server](/hosting/registering/) |
| **Working directory** | рабочий каталог | The folder the server is started in: `server.toml`, `resources/`, `content/`, `storage/`, `bans.json` and `logs/` live there. The executable's own folder holds `tools/`, `modules/` and the TLS files. | [Running the server](/hosting/running/) |
| **Ban book** | список банов | `bans.json` in the working directory: one JSON object whose keys are a banned IP address or `nodemp:<account id>`. Read once at the first ban check after a start, written on every new ban; a ban is lifted with the server stopped, by `Node-Server --bans list` / `--bans remove` or by editing the file. | [Running the server](/hosting/running/#bans) |

## For plugin authors

| Term | Russian | Definition | Explained on |
|---|---|---|---|
| **Plugin** | плагин | The umbrella word for everything a host adds to the server's behaviour: a resource or a native module. The server's own log lines use it for the whole subsystem (`plugin worker job stalled …`, `plugin job queue full`); a metrics key is `plugin`. | [Plugin overview](/plugins/overview/) |
| **Resource** | ресурс | A folder under `resources/` in the server's working directory: an optional `resource.toml`, a server half (`server/main.lua`, or JavaScript with the `js-host` module) that uses the `node` API, and an optional client half under `client/` that is streamed to every player on join. Chat, permissions, game modes and admin commands are resources. | [Resources](/plugins/resources/) |
| **Native module** | нативный модуль | A shared library (`.dll` or `.so`) in `modules/` next to the server executable. It exports `node_plugin_abi`, `node_plugin_init` and `node_plugin_shutdown` and calls the server through the `NodeApi` table declared in `node.h`. | [Native modules](/plugins/native-modules/) |
| **Language host** | языковой хост | A native module that registers a resource `type` and runs resources of that type. `js-host` registers `type = "js"`; without it such resources are skipped. | [Native modules](/plugins/native-modules/) |
| **Module (four senses)** | модуль | The word appears in four places and means four things: a **native module** (above); the **module channel**, a numbered binary channel between a client and the server (`node.modules.on`, `node.sendModule`, `Module` frames); the client mod's **module framework** (`NodeMP.modules`), optional features inside the client mod; and the **language host** modules such as `js-host`. The pages say which one they mean. | [Events](/plugins/events/#the-module-channel) |
| **Wire event** | сетевое событие | A named `Event` frame between a client script and the server: `node.emitServer(name, data)` upwards, `player:send` and `node.broadcast` downwards. Names are `<domain>:<verb>` in lowercase (`chat:send`); camelCase names are server-side hooks that never cross the wire. The API reference calls this kind `client`. | [Events](/plugins/events/) |
| **Event kinds** | виды событий | The guides say *engine event*, *vehicle notification*, *cancellable request*, *wire event*, *bus message*, *module channel*; the [API reference](/plugins/api/events/) and `api.toml` say `builtin`, `notify`, `cancellable`, `client`, `bus`, `module`, and `special` for the relay filter `relayRequest`. Error lines use their own words: `error in event '…'` for an engine or wire event handler, `error in resource event '…'` for a bus handler, `error in timer callback`, `error in async task`. | [Events](/plugins/events/) |
| **Bus** | шина | The channel between resources on one server: `node.bus.emit(name, data)` and `node.bus.on(name, fn)`. The chat helpers speak over it: `player:tell` and `node.chat.say` emit `chat:say`, `node.commands.add` listens for `chat:command`, and the `chat` resource answers both. | [Events](/plugins/events/#between-resources-nodebus) |
| **Relay** | ретрансляция | Forwarding one player's traffic to the others. The core relays vehicle state itself; client events are server-terminal and reach other players only through a resource that forwards them (the client mod's own fire, grabber, triggers and vehicle policy are typed packets the core relays itself). A relay filter (`node.relay.filter` or the `relayRequest` hook in Lua, `register_relay_filter` in C) can veto any relayed packet per recipient. | [Framework overview](/framework/overview/) |
| **Category / subtype** | категория / подтип | The two bytes that identify every packet of wire protocol v22: one of eight categories (`Handshake`, `Session`, `Content`, `Vehicle`, `State`, `Event`, `Command`, `Module`) and a subtype within it. Every table on the protocol page is keyed by this pair. | [Wire protocol](/plugins/protocol/) |
| **Obfuscation level** | уровень обфускации | How much a resource's client Lua is transformed before delivery: `none`, `light` (the default), `medium` or `strong`, set per resource with `[client] obfuscation`. `[Resources] Obfuscate = false` turns it off for the whole server. Prometheus, the obfuscator, is a Lua program shipped under `tools/`; it has nothing to do with the monitoring system of the same name. | [Resources and content](/hosting/resources/) |
| **Examples** | примеры | The example resources the guides name - `chat`, `demo-numbers`, `vehicle-cleanup`, `gatekeeper-example`, `nodegrab-allow`, `devapi-example`, `session-report`. They ship in the release archive under `examples/`, with an `examples/README.txt` that says what each one does; `examples/chat` is the one the chat helpers of every other resource rely on. | [Resources and content](/hosting/resources/#installing-a-resource) |
| **Authority / driver / spawner** | авторитет / водитель / спавнер | Three roles per vehicle. The **spawner** created it and may delete it. The **driver** sits in it and sends its inputs. The **sync authority** is the client whose simulation counts and who streams the vehicle's state (control mode `S` for an empty or foreign car); the server assigns driver and authority and stamps both with a seat epoch. | [How synchronization works](/framework/sync/) |
