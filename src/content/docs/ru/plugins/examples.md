В каждой загрузке сервера рядом с исполняемым файлом лежит папка `examples/`. Каждая папка в ней —
готовый ресурс: прочитать можно за несколько минут, а задуманы они для того, чтобы их копировали и
переделывали. Их список — в `README.txt`, версия — в `EXAMPLES_COMMIT`.

## Как поставить

Скопируйте **всю папку** в `resources/` рядом с `server.toml` и перезапустите сервер. Лог это
подтвердит:

```
demo-numbers v1.0 loaded — lua · server 1 file · 1 client file
```

`resource.toml` и `server/main.lua` каждого примера рассказывают, что он делает и какие ключи
`[config]` принимает. Пока пример не поставлен, он ничего не меняет, а те, что с правилами (как
`vehicle-cleanup`), не делают ничего, пока правила не включены.

## chat-commands

Образец команд чата с сервера 1.8.0, когда у самого сервера своих команд не осталось. Один
обработчик `chatMessageRequest` ищет первое слово строки со `/` в таблице команд, выполняет
найденную и отвечает `{ handled = true }`; все остальные строки проходят нетронутыми. Новая команда —
это новая функция в таблице:

<!-- doctest: skip an excerpt of examples/chat-commands/server/main.lua -->
```lua
-- /time: the server's clock
function commands.time(player)
    player:tell("Server time: %s", os.date("%H:%M"))
end
```

`/help` перечисляет имена из таблицы, так что новая команда появится там сама.
[Чат → Команды](/ru/plugins/chat/#команды) объясняет устройство.

## vehicle-cleanup

Сервер никогда сам не удаляет машину игрока: когда кто-то уходит, его машины остаются в мире без
хозяина. Этот ресурс добавляет привычные правила уборки, и все они в нём выключены. Включите нужные
в его `resource.toml`:

```toml
[config]
deleteIdleAfterSeconds = 600     # nobody drove it for 10 minutes
deleteOnSpawnerDisconnect = true # its owner left and nobody drives it
maxWorldVehicles = 20            # over 20 cars, the longest idle go first
includeUnicycles = false         # walking players are never touched
checkIntervalMs = 5000           # how often the rules are checked
```

Две вещи из него стоит перенести в свои ресурсы. Настройки получают значения по умолчанию одной
строкой, так что владелец сервера пишет только то, что меняет:

<!-- doctest: server {"config": {"deleteIdleAfterSeconds": 600}} -->
```lua
local defaults = { deleteIdleAfterSeconds = 0, checkIntervalMs = 5000 }
local config = setmetatable(node.config, { __index = defaults })

node.log("idle limit %d s, checked every %d ms", config.deleteIdleAfterSeconds, config.checkIntervalMs)

-- expect: idle limit 600 s, checked every 5000 ms
```

А правила проверяются по таймеру над `node.vehicles.all()`, а не по событиям: «никто не ездил десять
минут» всё равно приходится проверять снова и снова. Машину, за рулём которой кто-то сидит, правила
не трогают никогда.

## gatekeeper-example

Запросы — это события, в которых ваш ресурс может сказать своё слово до того, как что-то случится.
Здесь показаны три вида «нет»:

- **На входе.** `playerConnectRequest` отказывает имени из чёрного списка с причиной, которую игрок
  увидит в лаунчере.
- **Лимит.** `vehicleSpawnRequest` отказывает в третьей машине с
  `"Vehicle limit reached (2 per player)"`.
- **Чужая машина.** `vehicleCouplerRequest` не пускает игроков к дверям машин, которые заспавнили не
  они.

Ещё он следит за `vehicleEdited`, `vehicleReset` и `vehiclePainted`, за которыми можно только
наблюдать: к тому времени, как сервер о них узнаёт, игра игрока их уже сделала.
[События → Запросы](/ru/plugins/events/#запросы-как-сказать-нет) — все запросы и что делает отказ.

## demo-numbers

Самый быстрый способ проверить, что игрок вообще достаёт до плагинов вашего сервера. Его клиентская
часть раз в секунду отправляет число, а серверная печатает каждое:

```
demo-numbers · Player#0 Alice joined - expecting a number every second
demo-numbers · Player#0 Alice -> 1
demo-numbers · Player#0 Alice -> 2
```

Числа в консоли значат, что работает вся цепочка: игра, клиентский мод, лаунчер, соединение и ваш
ресурс. Увидели — уберите его.

## seat-demo

Пересаживает игроков с сервера. Его клиентская часть добавляет в Lua-консоль игры таблицу
`SeatDemo`: `SeatDemo.swap()` меняет вас местами с другим водителем, `SeatDemo.eject()` высаживает,
`SeatDemo.seat(id)` сажает за руль машины `id`. Каждый вызов превращается на сервере в
`player:seat`, `player:unseat` или `player:swapWith`.

## nodegrab-allow

Захват узлов, которым игроки хватают и тянут части машин, экспериментальный и закрыт дважды:
владелец сервера должен поставить `[Experimental] NodeGrab = true`, а ресурс — разрешить каждый
захват в `vehicleNodeGrabRequest`. Без обработчика любой захват отклоняется. Этот ресурс разрешает
все; в его комментариях показано, как разрешить только часть, например не трогать машину, за рулём
которой сидит сам игрок.

## devapi-example и freeroam-example

`devapi-example` — экскурсия: он регистрирует обработчики сетевых событий `dev_*`, по одному на
каждую часть API (сведения о сервере, игроки, баны, спавн, хранилище, корутины, HTTP, файлы, шина,
фильтр ретрансляции), и ничего не делает, пока клиент такое событие не пришлёт. Читайте его рядом
со [справочником Lua API](/ru/plugins/api/lua/).

`freeroam-example` — первый ресурс, очень похожий на тот, что в
[Первом ресурсе](/ru/plugins/getting-started/): приветствия, ping, на который отвечают pong,
таймеры. У него нет `resource.toml` — это показывает, что папки с `server/main.lua` достаточно.

## session-report

Ведёт запись каждой сессии (когда игрок зашёл, сколько ездил, сколько машин заспавнил, сколько
проехал) и раз в минуту пишет её в `session-report.json`. Написан на JavaScript, и ему нужен модуль
`js-host` в `modules/`; без него сервер пишет в лог, что тип `"js"` никто не обслуживает, и
пропускает папку ([Ресурсы на JavaScript](/ru/plugins/js-host/)).

## Собираются из исходников

Несколько плагинов в архиве нет, потому что это нативные модули, которые собирают из исходников:
`dimensions` (параллельные миры, управляется по [шине](/ru/plugins/bus/#нативные-модули-на-шине)),
`js-host` (ресурсы на JavaScript), `beammp-compat` ([плагины BeamMP как есть](/ru/plugins/migrating/))
и `plugin-example` — самый маленький нативный модуль, с которого удобно начать свой
([Нативные модули](/ru/plugins/native-modules/)). Исключение — модуль базы данных: он лежит в
`modules/` ([База данных](/ru/plugins/database/)).
