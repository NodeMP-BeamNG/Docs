Плагин — это папка в `resources/`. Сервер загружает все такие папки при запуске.

## Файлы

| Путь | Что это |
|---|---|
| `resource.toml` | Описание ресурса. Необязательно: без него имя берётся из папки, а остальное — по умолчанию, как ниже. |
| `server/main.lua` | Точка входа серверной части. |
| `server/*.lua` | Остальной серверный код, подключается через `require` ([ниже](#несколько-файлов)). |
| `client/**/*.lua` | Клиентская часть: передаётся каждому игроку при входе и выполняется в игре. |
| `client/lua/vehicle/*.lua` | Клиентские файлы, которые выполняются внутри машин игрока ([Клиентские скрипты](/ru/plugins/client-scripting/#файлы-которые-выполняются-в-машине)). |
| всё остальное | Ваши данные: читайте и пишите их через `node.fs`. |

Папку, в которой нет ни серверной точки входа, ни клиентских файлов, сервер пропускает.

## resource.toml

```toml
name = "race"
version = "1.2"

[server]
main = "server/main.lua"

[client]
files = ["main.lua", "ui.lua"]
obfuscation = "medium"

[config]
laps = 3
```

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `name` | имя папки | Имя ресурса в логе, в команде `reload` и шине. |
| `version` | нет | Показывается в логе рядом с именем. |
| `type` | `"lua"` | Чем выполнять серверную часть. Для `"js"` нужен модуль `js-host` ([Ресурсы на JavaScript](/ru/plugins/js-host/)). |
| `[server] main` | `"server/main.lua"` | Точка входа, путь от папки ресурса. |
| `[client] files` | все `.lua` в `client/` | Какие клиентские файлы отправлять, путь от `client/`. |
| `[client] obfuscation` | `"light"` | Насколько запутывать клиентские файлы: `"none"`, `"light"`, `"medium"` или `"strong"`. |
| `[config]` | пусто | Собственные настройки ресурса, доступны как `node.config`. |

Пути, которые ведут за пределы папки ресурса, сервер отклоняет. Если `resource.toml` не читается,
сервер пишет об этом в лог и загружает ресурс со значениями по умолчанию.

## Окружение Lua

Серверная часть работает на Lua 5.4 со стандартными библиотеками. Поверх них есть одна глобальная переменная — `node`, весь API ([справочник](/ru/plugins/api/lua/)). У каждого ресурса своё состояние Lua, глобальных переменных другого ресурса он не видит.

Lua-модули на C загрузить нельзя: сервер не подгружает в ресурс нативные библиотеки. Для того, что не под силу Lua, есть [нативные модули](/ru/plugins/native-modules/).
На диске ресурсу доступна только его собственная папка. Так ресурс, скачанный у кого-то, не прочитает
`server.toml`, не удалит файлы и не запустит программы на машине хоста:

| Что | В ресурсе |
|---|---|
| `io.open`, `io.lines`, `os.remove`, `os.rename`, `dofile`, `loadfile`, `require`, `package.searchpath` | Файлы внутри папки ресурса. Путь считается от этой папки; путь от папки сервера (`resources/race/data.json`) или абсолютный тоже подходит, если ведёт внутрь. За её пределами: `nil, "…: outside the resource folder"`. |
| `os.time`, `os.clock`, `os.date`, `os.difftime`, `io.write` | Как обычно. |
| `os.getenv` | `nil` для любой переменной: в окружении лежат секреты сервера. |
| `os.execute`, `io.popen`, `os.exit`, `os.setlocale`, `os.tmpname`, `io.read`, `io.input`, `io.output` | Вызывают ошибку с подсказкой про `[resources] trusted`. |
| `load` | Только текст: скомпилированные куски не загружаются. |
| `debug` | Только `traceback` и `getinfo`. |

То же действует внутри `node.job` и `node.await`. Если ресурсу действительно нужно больше, хост
вписывает его в `server.toml`, и он получает всю стандартную библиотеку, а пути считаются от папки
сервера:

```toml
[resources]
trusted = ["backup"]
```

<!-- doctest: server -->
```lua
local ok, err = pcall(os.execute, "echo hi")
node.log("%s", err)

-- expect: os\.execute is not available to resources
```

Lua-модули на C загрузить нельзя: сервер не подгружает в ресурс нативные библиотеки. Для того, что не
под силу Lua, есть [нативные модули](/ru/plugins/native-modules/).

## Несколько файлов

`require` ищет по `package.path`, а он начинается с папки сервера, не ресурса. Добавьте в начало свою папку — один раз, в начале `main.lua`:

<!-- doctest: server {"files": {"server/util.lua": "local M = {}\nfunction M.add(a, b)\n    return a + b\nend\nreturn M\n"}} -->
```lua
local here = debug.getinfo(1, "S").source:sub(2):match("^(.*)[/\\]")
package.path = here .. "/?.lua;" .. package.path

local util = require("util")
node.log("2 + 3 = %d", util.add(2, 3))

-- expect: 2 \+ 3 = 5
```

`server/util.lua` — обычный модуль: он возвращает таблицу.

<!-- doctest: server -->
```lua
local M = {}

function M.add(a, b)
    return a + b
end

return M
```

## Перезагрузка

Команда `reload <имя>` в консоли сервера или `node.resources.reload(name)` из кода заменяет работающий ресурс без перезапуска сервера:

1. Срабатывают обработчики `resourceUnload` ресурса с причиной `"reload"`.
2. Его обработчики, таймеры и корутины снимаются, а вместе с ними и состояние Lua.
3. Папка загружается заново, и `main.lua` выполняется сначала.

Что остаётся: `node.storage`, файлы в папке и все остальные ресурсы. Всё, что лежало в переменных Lua, пропадает, поэтому важное держите на диске. `resourceUnload` — последний момент, чтобы записать данные:

<!-- doctest: server+client -->
```lua
local joins = node.storage.get("joins", 0)

node.on("playerJoined", function()
    joins = joins + 1
end)

node.on("resourceUnload", function(reason)
    node.storage.set("joins", joins)
    node.log("joins so far: %d (%s)", joins, reason)
end)

-- expect: joins so far: 1 \(shutdown\)
```

Обработчик `resourceUnload` срабатывает с причиной `"shutdown"`, когда сервер останавливается. Не запускайте в нём ничего, только сбор данных и запись на диск, всё остальное не гарантируется.

Клиентские файлы сервер упаковывает один раз, при запуске. Перезагрузка плагина не отправляет новые клиентские файлы, перезапуск сервера — отправляет.

## Ошибки

Ошибку в обработчике сервер пишет в лог с именем ресурса, файлом, строкой и трассировкой. Обработчик снова вызовется на следующем событии, остальной ресурс продолжает работать. Ошибка на верхнем уровне `main.lua` прерывает остаток этого файла, а ресурс остаётся загруженным с тем, на что успел подписаться до ошибки.

Пишите в лог через `node.log`, а проблемы отмечайте `node.log.warn` и `node.log.error`. Все три принимают аргументы как `string.format`.
