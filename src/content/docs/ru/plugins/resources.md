Ресурс — одна папка в `resources/` рядом с `server.toml`. На этой странице — что сервер делает с
этой папкой: что где лежит, что меняет каждый ключ манифеста, когда читаются файлы и что переживает
перезагрузку. Как ставить ресурсы на сервер, рассказано в разделе [Ресурсы и моды](/ru/hosting/resources/).

## Структура

```
resources/
└── race/
    ├── resource.toml               # необязательный манифест
    ├── server/
    │   ├── main.lua                # точка входа сервера
    │   └── util.lua                # другие серверные файлы, через require
    ├── client/
    │   ├── main.lua                # игровой скрипт, уходит игрокам
    │   └── lua/
    │       ├── ge/extensions/      # уходят первыми
    │       └── vehicle/            # выполняются внутри машин игроков
    └── data/
        └── tracks.json             # ваши данные, читаются через node.fs
```

Для сервера что-то значат только манифест, точка входа и `client/`. Всё остальное в папке — ваше:
читайте и пишите через `node.fs`. Состояние, которое должно пережить перезапуск, храните в
`node.storage` — оно лежит вне папки ([Хранилище и файлы](/ru/plugins/storage/)).

### Несколько серверных файлов

Серверная часть начинается с одного файла. `require` в Lua ищет относительно рабочей папки сервера,
а не вашей папки, поэтому сначала добавьте свою папку в путь:

<!-- doctest: server {"files": {"server/util.lua": "return { greet = function() return \"hello from util.lua\" end }"}} -->
```lua
local here = debug.getinfo(1, "S").source:sub(2):match("^(.*)[/\\]") -- .../resources/race/server
package.path = here .. "/?.lua;" .. package.path
local util = require("util") -- server/util.lua
node.log(util.greet())

-- expect: hello from util.lua
```

`require` загружает только файлы Lua: загрузка библиотек на C внутри ресурсов отключена. Нативному
коду место в [нативном модуле](/ru/plugins/native-modules/). Клиентским файлам этот приём не нужен:
в клиентской части `require("lib/helpers")` сначала ищет среди файлов самого ресурса.

## resource.toml

Все ключи необязательны. Папка без манифеста — Lua-ресурс с именем папки, точкой входа
`server/main.lua` и всеми `.lua` из `client/`, которые уходят игрокам.

```toml
name = "race"
version = "1.0"
type = "lua"

[server]
main = "server/main.lua"

[client]
files = ["main.lua", "lua/vehicle/horn.lua"]
obfuscation = "light"

[config]
laps = 3
startDelaySec = 10
```

| Ключ | По умолчанию | Что меняет |
|---|---|---|
| `name` | имя папки | Метка ваших строк в логе, имя хранилища `node.storage` и имя, под которым игра игрока сохраняет ваши скрипты. Латинские буквы, цифры, `_`, `-` и `.`, начиная с буквы или цифры: хранилище отказывается от других символов, а игра — от посылки с таким именем. |
| `version` | пусто | Видна в строке загрузки: `race v1.0 loaded — lua · server 1 file · 1 client file`. |
| `type` | `"lua"` | На каком языке серверная часть. Любое другое значение требует нативного модуля, который научит сервер этому языку; без него папка пропускается: `race · resource type 'js' has no language host loaded, skipping (a native module in modules/ must register one)`. |
| `[server] main` | `"server/main.lua"` | Точка входа относительно папки. Должна оставаться внутри папки. Если файла нет, ресурс только клиентский — это нормально. |
| `[client] files` | все `.lua` из `client/` | Какие файлы отправлять, относительно `client/`, в этом порядке. Без ключа первыми идут файлы прямо в `client/lua/ge/extensions/`, остальные — по алфавиту. Путь, выходящий из папки, пропускается с предупреждением. |
| `[client] obfuscation` | `"light"` | `none`, `light`, `medium` или `strong` ([ниже](#обфускация)). `off` и `false` значат `none`; `high` и `full` — `strong`; всё прочее — `light`. |
| `[config]` | нет | Ваши настройки. Сервер их не читает; вы получаете их как `node.config` ([Настройки](#настройки)). |

Если манифест не разбирается, сервер об этом пишет (`race · failed to parse resource.toml (...), using defaults`),
и папка загружается со значениями по умолчанию.

## Порядок загрузки

При запуске сервер загружает нативные модули из `modules/`, затем папки из `resources/` по одной,
**в произвольном порядке**. Никогда не рассчитывайте, что другой ресурс загрузился раньше вашего:
общайтесь с ним через [шину](/ru/plugins/bus/) и будьте готовы к тому, что ответа нет. Для каждой
папки:

1. Читается манифест.
2. Клиентские файлы читаются, обфусцируются и упаковываются для отправки.
3. Папка без точки входа и без клиентских файлов пропускается.
4. Точка входа выполняется один раз, сверху вниз. `node` и `node.config` к этому моменту готовы.
   Здесь вы подписываетесь на события, запускаете таймеры и загружаете данные.
5. Печатается строка загрузки.

Затем строка `1 resource · 1 module loaded` подводит итог, и запускается рабочий поток: срабатывают
таймеры, каждые 100 мс идёт `serverTick`, игроки могут заходить. Каждый входящий игрок получает
клиентские файлы всех ресурсов вместе с картой, до входа в мир
([События → Вход по шагам](/ru/plugins/events/#вход-по-шагам)).

## Клиентская часть

Файлы из `client/` выполняются в игре у игроков. Файл, путь которого начинается с `lua/vehicle/`,
выполняется внутри машин игрока; все остальные — в самой игре. Полный клиентский API — на странице
[Клиентские скрипты](/ru/plugins/client-scripting/); здесь важно, как файлы доставляются:

- Они упаковываются **один раз, при запуске сервера**. Изменения в `client/` требуют перезапуска, а
  игроки, которые уже в сессии, остаются с тем, что получили.
- Отдельный файл больше 900 КБ пропускается, сервер называет его в консоли. Игра принимает до 8 МБ
  и 512 файлов на ресурс.
- Они компилируются в памяти под именем вашего ресурса и никогда не пишутся на диск игрока, поэтому
  ресурс не может подменить файл игры или клиентского мода — он добавляет код рядом с ними.
- Сервер не выполняет клиентские файлы, но разбирает их и сообщает о файле, который не
  компилируется:
  `race · client file 'main.lua' has a syntax error: main.lua:1: unexpected symbol near '=' (the file ships anyway; the game's Lua will very likely refuse it too)`.

### Обфускация

Если сервер её не отключил (`[Resources] Obfuscate = false`), каждый клиентский файл перед упаковкой
обфусцируется на уровне, который задаёт `[client] obfuscation`:

- `light` переименовывает локальные переменные и прячет строковые константы. Безопасен для кода,
  который работает каждый кадр.
- `medium` добавляет косвенность для локальных переменных и переписывает числа.
- `strong` вдобавок оборачивает весь файл. Для меню и одноразовой настройки.

Глобальные имена и ключи таблиц никогда не переименовываются, так что `M.onUpdate` и хуки игры
продолжают работать. Пока разрабатываете, ставьте `none` — тогда номера строк в `beamng.log` игрока
совпадают с исходником. Файл, с которым обфускатор не справился, уходит как есть с предупреждением;
из-за обфускации вход не срывается никогда.

Обфускация делает клиентский код труднее для чтения и копирования, но не секретным: всё, что
выполняется на ПК игрока, этот игрок может прочитать. Правила и всё, что стоит защитить, держите на
сервере.

## Настройки

Таблица `[config]` в манифесте — ваша. `node.config` содержит её как есть (строки, числа, логические
значения, массивы и вложенные таблицы) или пустую таблицу, если её нет. Подложите под неё значения
по умолчанию, чтобы владелец сервера писал только то, что меняет:

<!-- doctest: server {"config": {"laps": 5}} -->
```lua
local defaults = { laps = 3, startDelaySec = 10, announce = true }
local config = setmetatable(node.config, { __index = defaults })

node.log("%d laps, start in %d s", config.laps, config.startDelaySec)

-- expect: 5 laps, start in 10 s
```

`node.config` читается один раз, при загрузке ресурса; перезагрузка читает его заново.
`node.resources.manifest()` перечитывает `resource.toml` с диска и возвращает его целиком (`name`,
`version`, `type`, `server`, `client`, `config`) или `nil`, если файл не разбирается, — на случай,
когда нужны новые настройки без перезагрузки.

## Перезагрузка

`reload race` в консоли сервера или `node.resources.reload("race")` из кода перезагружает один
ресурс без перезапуска сервера. Перезагрузка сбрасывает всё, что настроила серверная часть
(обработчики событий, подписки на шину, фильтры ретрансляции, таймеры, корутины и всё состояние Lua),
и снова запускает точку входа. Консоль пишет `race reloaded — lua`.

| Переживает перезагрузку | Не переживает |
|---|---|
| `node.storage`, файлы в вашей папке, другие ресурсы, игроки и их машины | Переменные Lua, обработчики, таймеры, корутины |

`node.config` читается заново, так что новые настройки вступают в силу. Клиентские файлы заново не
упаковываются (для этого нужен перезапуск). HTTP-запрос или фоновая задача, которые уже идут,
доработают, но их колбэк уйдёт в никуда.

`node.resources.reload` возвращает `true`, когда запрос принят. Сама перезагрузка выполняется сразу
после того, как текущий обработчик вернёт управление, поэтому ресурс может спокойно перезагрузить
себя из команды чата. `false` — ресурса с таким именем нет.

### Сохранить перед выгрузкой

`resourceUnload` выполняется в старом экземпляре прямо перед тем, как его состояние сбросят, и
только в выгружаемом ресурсе. Аргумент — `"reload"` при перезагрузке и `"shutdown"` при остановке
сервера (после `serverShutdown`):

<!-- doctest: server+client -->
```lua
local session = { started = node.server.uptime(), joins = 0 }

node.on("playerJoined", function() session.joins = session.joins + 1 end)

node.on("resourceUnload", function(reason)
    node.storage.set("lastSession", { reason = reason, joins = session.joins })
    node.log("%s after %d join(s)", reason, session.joins)
end)

-- expect: shutdown after 1 join\(s\)
```

Запишите нужное и выходите. Запись в `node.storage` здесь сохраняется, и новый экземпляр её прочтёт.
Колбэки, таймеры и корутины, запущенные здесь, не выполнятся никогда, так что после `await` ничего
не ставьте. Не перезагружайте себя из этого обработчика: при перезагрузке это поставит в очередь
следующую — и так без конца.
