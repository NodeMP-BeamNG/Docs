Нативный модуль — это библиотека, `.dll` на Windows или `.so` на Linux, в папке `modules/` рядом с
программой сервера. С сервером она общается через таблицу функций на C, `NodeApi`, описанную в одном
заголовке, `node.h`. Модули загружаются раньше ресурсов.

Пишите модуль, когда Lua не успевает: код, который выполняется на каждый пакет, или библиотека, которая
есть только на C. Для правил игры и команд ресурс на Lua проще и надёжнее: ошибка в Lua — строка в
логе, ошибка в модуле может уронить сервер.

## Три функции

Модуль экспортирует ровно три функции:

| Функция | Когда сервер её вызывает |
|---|---|
| `node_plugin_abi()` | Первой, раньше всего остального: под какую версию ABI собран модуль. |
| `node_plugin_init(api)` | Один раз, при загрузке. `0` — загрузиться, что угодно другое — отказаться. |
| `node_plugin_shutdown()` | Когда сервер останавливается. |

Модуль, который здоровается с каждым игроком в логе:

```c
#include "node.h"
#include <stdio.h>

static const NodeApi* api;

static void on_joined(int player_id, void* user) {
    char name[64], line[128];
    if (api->get_player_name(player_id, name, sizeof name) < 0) return;
    snprintf(line, sizeof line, "hello, %s", name);
    api->log_info(line);
}

NODE_PLUGIN_ABI()

NODE_EXPORT int node_plugin_init(const NodeApi* a) {
    api = a;
    api->register_builtin_event("playerJoined", on_joined, NULL);
    return 0;
}

NODE_EXPORT void node_plugin_shutdown(void) {
    api->unregister_builtin_event("playerJoined", on_joined, NULL);
}
```

`node.h` — один заголовок на C: без библиотеки импорта и без внутренностей сервера. Подойдёт любой
компилятор C или C++. На Windows собирайте со статической библиотекой C, чтобы DLL ничего не требовала
рядом с собой.

## Версии ABI

Версия ABI записывается как `старшая.младшая`; этот сервер говорит на 2.5. `NodeApi` — структура,
которую читают по смещениям, поэтому её раскладка — договор: новые функции добавляются только в конец,
и от этого растёт младшая версия.

- **Другая старшая версия** — отказ при загрузке, раньше, чем модуль чего-то коснётся:
  `module '…' was built against SDK ABI 1.12, this server speaks 2.5 -- refusing to load it. Rebuild the module.`
- **Младшая версия старее** — модуль загрузится: всё, что он знает, лежит там, где он ожидает.
- **Младшая версия новее** — модуль загрузится с предупреждением: он может вызвать функции, которых у
  этого сервера нет. Прежде чем вызвать функцию, добавленную позже нужной вам версии, проверьте
  `api->struct_size`.

Ресурсы на Lua и JavaScript при обновлении сервера пересобирать не нужно.

## Возвращаемые значения

- Действие возвращает `0` при успехе и `-1` при ошибке. Вопрос возвращает `1` — да, `0` — нет.
- Функция, которая заполняет буфер, возвращает число записанных байтов или `-1`, если буфер мал.
  С буфером `NULL` она возвращает нужную длину без завершающего нуля.

## Потоки

- Любую функцию `NodeApi` можно вызывать из любого потока, в том числе из потоков самого модуля.
- Колбэки (события, таймеры, задачи, HTTP, шина) выполняются на единственном рабочем потоке сервера,
  по одному, как обработчики Lua. Блокировка в одном из них задерживает все ресурсы.
- Исключение — фильтр ретрансляции: он выполняется на сетевых потоках, на каждый пакет, и должен быть
  быстрой функцией от данных самого модуля. Менять из него состояние сервера нельзя.
- Долгую работу отдают `submit_job`: она выполнит её в фоновом потоке и вызовет вас обратно на рабочем.

## Что умеет только модуль

- **Фильтровать ретрансляцию на горячем пути.** `register_relay_filter` спрашивают, пакет за пакетом,
  может ли один игрок видеть то, что шлёт другой. Lua тоже так умеет, но модуль делает это, не уходя с
  сетевого потока.
- **Запускать другой язык.** `register_language_host` занимает `type` ресурсов: такие ресурсы сервер
  передаёт модулю, и тот их загружает и выполняет. Так `js-host` запускает `type = "js"`
  ([Ресурсы на JavaScript](/ru/plugins/js-host/)).
- **Глушить строки лога.** Приёмник лога, заданный через `set_log_sink`, видит каждую строку и может
  её отбросить.

С ресурсами модули общаются по [шине](/ru/plugins/bus/) (`emit_resource_event`,
`register_resource_event`, там они видны как `"native"`), а со своими клиентскими частями — по
нумерованным двоичным каналам (`register_module_channel`, `send_module`). Добавлять функции в Lua модуль
не может: всё, что он предлагает ресурсам, идёт по шине, как у [модуля db](/ru/plugins/database/).

## Установка модуля

Скопируйте библиотеку в `modules/` рядом с программой и перезапустите сервер. В логе будет каждый
загруженный модуль и причина отказа для каждого, кого сервер не принял. В Docker эта папка внутри
образа, так что для нового модуля нужно собрать свой образ на основе релизного.

Все функции с описанием — в [справочнике C API](/ru/plugins/api/c/).
