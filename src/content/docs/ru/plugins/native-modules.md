Нативный модуль — библиотека, `.dll` на Windows или `.so` на Linux, в папке `modules/` рядом с программой сервера. С сервером она общается через таблицу функций на C, `NodeApi`, описанную в одном заголовке, `node.h`. Модули загружаются раньше плагинов.

Пишите модуль, когда Lua не успевает: код, который выполняется на каждый пакет, или библиотека, которая есть только на C. Для правил игры и команд плагин на Lua проще и надёжнее: ошибка в Lua — строка в логе, а ошибка в модуле может уронить сервер.

## Три функции

Модуль экспортирует ровно три функции:

| Функция | Когда сервер её вызывает |
|---|---|
| `node_plugin_abi()` | Первой, раньше всего остального: под какую версию ABI собран модуль. |
| `node_plugin_init(api)` | Один раз, при загрузке. `0` загружает модуль, любое другое значение отказывает. |
| `node_plugin_shutdown()` | Когда сервер останавливается. |

Модуль, который здоровается с каждым игроком в логе:

```c
#include "node.h"
#include <stdio.h>

static const NodeApi* api;

static void on_joined(int player_id, void* user) {
    char name[64], line[128];
    if (api->get_player_name(player_id, name, sizeof name) < 0) return;
    snprintf(line, sizeof line, "hello, %s", name);
    api->log_info(line);
}

NODE_PLUGIN_ABI()

NODE_EXPORT int node_plugin_init(const NodeApi* a) {
    api = a;
    api->register_builtin_event("playerJoined", on_joined, NULL);
    return 0;
}

NODE_EXPORT void node_plugin_shutdown(void) {
    api->unregister_builtin_event("playerJoined", on_joined, NULL);
}
```

`node.h` — один заголовок на C, без библиотеки импорта и без внутренностей сервера. Подойдёт любой компилятор C или C++. На Windows собирайте со статической библиотекой C, чтобы DLL ничего не требовала рядом с собой.

## Версии ABI

Версия ABI записывается как `старшая.младшая`, её задают `NODE_ABI_VERSION_MAJOR` и `NODE_ABI_VERSION_MINOR` в `node.h`. `NodeApi` — структура, которую читают по смещениям, поэтому её раскладка договор: новые функции добавляются только в конец, и от этого растёт младшая версия.

| Модуль собран | Что делает сервер |
|---|---|
| С другой старшей версией | Отказывает при загрузке, раньше, чем модуль чего-то коснётся: `module '…' was built against SDK ABI 1.12, this server speaks 2.8 -- refusing to load it. Rebuild the module.` |
| С более старой младшей версией | Загружает: всё, что модуль знает, лежит там, где он ожидает. |
| С более новой младшей версией | Загружает с предупреждением: модуль может вызвать функции, которых у этого сервера нет. Если модуль должен работать и на таком сервере, перед вызовом новой функции проверьте `api->struct_size`. |

Плагины на Lua и JavaScript при обновлении сервера пересобирать не нужно.

## Возвращаемые значения

- Действие возвращает `0` при успехе и `-1` при ошибке. Вопрос возвращает `1` для «да» и `0` для «нет».
- Функция, которая заполняет буфер, возвращает число записанных байтов или `-1`, если буфер мал. С буфером `NULL` она возвращает нужную длину без завершающего нуля.

## Потоки

- Любую функцию `NodeApi` можно вызывать из любого потока, в том числе из потоков самого модуля.
- Колбэки (события, таймеры, задачи, HTTP, шина) выполняются на единственном рабочем потоке сервера, по одному, как обработчики Lua. Блокировка в одном из них задерживает все плагины ([Таймеры и корутины](/ru/plugins/concurrency/)).
- Приёмник лога (`set_log_sink`) выполняется на том потоке, который написал строку, и не должен блокироваться.
- Фильтр ретрансляции выполняется на сетевых потоках, на каждый пакет, и должен быть быстрой функцией от данных самого модуля. Менять из него состояние сервера нельзя.
- Рабочую функцию `submit_job` сервер выполняет в фоновом потоке и вызывает вас обратно на рабочем.

## Что умеет только модуль

- Фильтровать ретрансляцию на горячем пути. Фильтр из `register_relay_filter` сервер спрашивает, может ли один игрок видеть пакет другого, и запоминает ответ. Lua тоже так умеет, но модуль отвечает, не уходя с сетевого потока.
- Запускать другой язык. `register_language_host` занимает `type` плагинов: такие плагины сервер передаёт модулю, и тот их загружает и выполняет. Так `js-host` запускает `type = "js"` ([Плагины на JavaScript](/ru/plugins/js-host/)). Языковой хост на Lua 5.4 может дать плагину ту же песочницу, что и сервер: для этого в sdk есть `lua_sandbox.hpp`, а `is_resource_trusted` говорит, вписан ли плагин в `[resources] trusted`.
- Глушить строки лога. Приёмник лога, заданный через `set_log_sink`, видит каждую строку и может её отбросить. Приёмник у сервера один: следующий `set_log_sink` заменяет предыдущий.

С плагинами модули общаются по [шине](/ru/plugins/bus/) (`emit_resource_event`, `register_resource_event`, там они видны как `"native"`), а со своими клиентскими частями по нумерованным двоичным каналам (`register_module_channel`, `send_module`). Модуль может и спросить плагины: `call_resource_event` сразу запускает их обработчики и до возврата передаёт каждый ответ в колбэк. Вызывать её нужно из колбэка, на рабочем потоке. Модуль, подписанный на имя, такой вопрос видит, но ответить на него не может ([Шина](/ru/plugins/bus/#запрос-и-ответ)). Добавлять функции в Lua модуль не может: всё, что он предлагает плагинам, идёт по шине, как у [модуля db](/ru/plugins/database/).

## Установка модуля

Как поставить модуль на сервер, описано на странице [Плагины на сервере](/ru/hosting/resources/#нативные-модули). При запуске сервер пишет в лог `<файл> initialized` для каждого загруженного модуля и причину отказа для остальных.

Все функции с описанием перечислены в [справочнике C API](/ru/plugins/api/c/).
