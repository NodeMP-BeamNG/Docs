Несколько правил действуют во всём API. Если их знать, справочник не придётся читать по каждому вызову.

## Как вызовы сообщают о неудаче

- Вызов, который что-то делает, возвращает `true` или `false`: `player:kick` вернёт `false`, если игрока нет.
- Вызов, который может не получиться по разным причинам, возвращает `nil` и причину коротким словом: `player:spawnVehicle` вернёт `nil, "max_cars"`, а `node.fs.stat` вернёт `nil, "not found"`.
- Вызов, который что-то читает, возвращает `nil`, если читать нечего: `node.players.find` для неизвестного имени, `vehicle:transform()` до первой позиции.
- Ошибку вызов бросает, только если его используют неправильно, например передают обработчиком не функцию. Такая ошибка указывает на вашу строку.

<!-- doctest: server -->
```lua
local ok, why = node.players.get(999):verify("size")
node.log("verify: %s (%s)", tostring(ok), tostring(why))

-- expect: verify: nil \(unknown player\)
```

## Ошибки в обработчиках

Ошибку в обработчике, таймере или корутине сервер пишет в лог с именем плагина, файлом, строкой и трассировкой. Первая строка называет, где случилась ошибка:

| Где | Начало строки |
|---|---|
| Событие, которое передаёт только игрока или машину, и запрос | `error in builtin 'playerJoined'` |
| Событие с данными: уведомление, `playerLeft` | `error in event 'vehicleEdited'` |
| Сетевое событие | `error in event 'greeter:hello'` |
| Сообщение шины | `error in resource event 'score:add'` |
| Запрос по шине (`node.bus.call`) | `error in resource call 'shop:price'` |
| Таймер | `error in timer callback` |
| Корутина | `error in async task` |
| Верхний уровень `main.lua` при загрузке | `error in '<путь к main.lua>'` |

Ошибка прерывает только этот вызов: остальные обработчики плагина работают, а этот снова вызовется на следующем событии. Поэтому `pcall` вокруг всего обработчика не нужен, но то, на что он опирается, проверяйте: например, есть ли у игрока `accountId`.

## Какие id живут долго

| Id | Сколько живёт |
|---|---|
| `player.id` | Сессию. Освобождается, когда игрок уходит, и достаётся следующему. |
| `vehicle.id` | Пока работает сервер. До перезапуска не повторяется. |
| `player.accountId` | Всегда. Один и тот же аккаунт на любом сервере и при любом визите. |

Всё, что касается игрока, сохраняйте по `accountId`. У гостя его нет, а имя гостя в следующий раз может взять кто-то другой.

## Версии

| Вызов | Что даёт |
|---|---|
| `node.server.version()` | Версию сервера. |
| `node.server.protoVersion()` | Версию сетевого протокола, на которой говорит сервер. |

<!-- doctest: server -->
```lua
local version = node.server.version()
node.log("server %s, protocol %d", version, node.server.protoVersion())

-- expect: server \S+, protocol \d+
```

Чтобы вызвать функцию только там, где она есть, проверьте её наличие: `if node.server.shutdown then … end`. Версию протокола сравнивайте с `protoVersion()`, а не с числом, вписанным в код. Сервер сам отключает мод, который назвал в `session:hello` другую версию протокола.

## Память и время

Два вызова показывают, во что обходится плагин:

- `node.server.memory()` даёт `{ lua, luaAll, process }` в байтах: состояние Lua этого плагина, всех плагинов вместе и весь сервер.
- `node.server.handlerStats()` показывает, сколько работают обработчики этого плагина: `count` запусков, время `min`, `max`, `mean` и `stddev` в миллисекундах и `over`, то есть сколько запусков перешли порог в 250 мс.

<!-- doctest: server -->
```lua
local function reportUsage()
    local mem = node.server.memory()
    local stats = node.server.handlerStats()
    node.log("lua %d KB, %d runs, slowest %s ms",
        mem.lua // 1024, stats.count, tostring(stats.max))
end

node.after(1000, reportUsage)

-- expect: lua \d+ KB, \d+ runs
```

Число `lua`, которое растёт весь вечер, указывает на таблицу, которую никто не чистит. `max`, который подбирается к 250 мс, — повод разделить обработчик или перенести его в корутину ([Таймеры и корутины](/ru/plugins/concurrency/)).
