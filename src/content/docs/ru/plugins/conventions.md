Несколько правил действуют во всём API. Если их знать, не придётся читать справочник по каждому
вызову.

## Как вызовы сообщают о неудаче

- Вызов, который что-то делает, возвращает `true` или `false`: `player:kick` вернёт `false`, если
  игрока нет.
- Вызов, который может не получиться по разным причинам, возвращает `nil` и причину коротким словом:
  `player:spawnVehicle` — `nil, "max_cars"`, `node.fs.stat` — `nil, "not found"`.
- Вызов, который что-то читает, возвращает `nil`, если читать нечего: `node.players.find` для
  неизвестного имени, `vehicle:transform()` до первой позиции.
- Ошибку вызов бросает, только если его используют неправильно, например передают обработчиком не
  функцию. Такая ошибка указывает на вашу строку.

<!-- doctest: server -->
```lua
local ok, why = node.players.get(999):verify("size")
node.log("verify: %s (%s)", tostring(ok), tostring(why))

-- expect: verify: nil \(unknown player\)
```

## Ошибки в обработчиках

Ошибку в обработчике, таймере или корутине сервер пишет в лог с именем ресурса, файлом, строкой и
трассировкой. Она прерывает только этот вызов: остальные обработчики ресурса работают, а этот снова
вызовется на следующем событии. Поэтому обработчику, который спотыкается о плохие данные, не нужен
`pcall` вокруг всего, но то, на что он опирается, стоит проверять — например, что `player.accountId`
вообще есть.

## Имена

| Что | Правило | Примеры |
|---|---|---|
| События сервера | `<кто><что сделал>` | `playerJoined`, `vehicleSpawned` |
| Запросы, которые можно отклонить | `<кто><действие>Request` | `vehicleSpawnRequest`, `chatMessageRequest` |
| Сетевые события и сообщения шины | `<ресурс>:<что>`, строчными | `race:start`, `score:add` |
| Ключи хранилища | на ваш выбор; префикс разводит их | `visits:42`, `settings` |

Имена событий, которые начинаются с `node:`, принадлежат серверу. Имя ресурса в начале ваших имён не
даёт двум ресурсам отвечать на чужие сообщения.

## Какие id живут долго

| Id | Сколько живёт |
|---|---|
| `player.id` | Сессию. Освобождается, когда игрок уходит, и достаётся следующему. |
| `vehicle.id` | Пока работает сервер. До перезапуска не повторяется. |
| `player.accountId` | Всегда. Один и тот же аккаунт на любом сервере и при любом визите. |

Всё, что касается игрока, сохраняйте по `accountId`. У гостя его нет, а его имя в следующий раз может
принадлежать кому-то другому.

## Версии

| Вызов | Что даёт |
|---|---|
| `node.server.version()` | Версию сервера. |
| `node.server.protoVersion()` | Версию сетевого протокола, на которой говорит сервер. |

<!-- doctest: server -->
```lua
local version = node.server.version()
node.log("server %s, protocol %d", version, node.server.protoVersion())

-- expect: server \S+, protocol \d+
```

Новые релизы добавляют функции и события, а то, что делают существующие, без упоминания в описании
релиза не меняют. Чтобы вызвать функцию только там, где она есть, проверьте её наличие:
`if node.server.shutdown then … end`. Версию протокола сравнивайте с `protoVersion()`, а не с числом,
вписанным в код.

## Память и время

Два вызова показывают, во что обходится ресурс:

- `node.server.memory()` даёт `{ lua, luaAll, process }` в байтах: состояние Lua этого ресурса, всех
  ресурсов вместе и весь сервер.
- `node.server.handlerStats()` показывает, сколько работают обработчики этого ресурса: `count`, `mean`,
  `max` в миллисекундах и `over` — сколько запусков перешли порог в 250 мс.

<!-- doctest: server -->
```lua
node.after(1000, function()
    local mem = node.server.memory()
    local stats = node.server.handlerStats()
    node.log("lua %d KB, %d runs, slowest %s ms",
        mem.lua // 1024, stats.count, tostring(stats.max))
end)

-- expect: lua \d+ KB, \d+ runs
```

Число `lua`, которое растёт весь вечер, указывает на таблицу, которую никто не чистит. `max`, который
подбирается к 250 мс, — повод разделить обработчик или перенести его в корутину.
