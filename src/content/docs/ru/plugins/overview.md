Сервер NodeMP занимается инфраструктурой: принимает игроков, владеет реестром машин,
ретранслирует состояние и передаёт клиентские скрипты. Всё, в чём есть правило, - чат, права,
игровые режимы, экономика, параллельные миры - это **плагин**. Плагин - это либо **ресурс**
(папка с Lua или JavaScript в `resources/`), либо **нативный модуль** (разделяемая библиотека в
`modules/`). Эта страница - карта раздела; архитектура вокруг сервера описана в
[обзоре фреймворка](/ru/framework/overview/).

## Три формы одного API

У сервера один API возможностей, описанный один раз в `sdk/api.toml` и сгенерированный в трёх
формах. Форму вы выбираете, выбирая язык.

| Поверхность | Что вы пишете | Справочник |
|---|---|---|
| `node` | Ресурс на Lua. Пространства имён по существительным (`node.players`, `node.vehicles`, `node.storage`), объекты `Player` и `Vehicle` с методами, обработчики получают объекты, JSON декодируется за вас. | [Справочник Lua API](/ru/plugins/api/lua/) |
| `node.raw` | Те же вызовы один к одному с C ABI: на входе идентификаторы, на выходе таблицы. Всегда лежит внутри `node`; берите его, когда нужно ровно поведение C. | [Справочник raw Lua](/ru/plugins/api/raw/) |
| `NodeApi` | Нативный модуль на C или C++ против `node.h`. Все возможности Lua плюс то, что умеет только нативный код. | [Справочник C ABI](/ru/plugins/api/c/) |

JavaScript - второй способ записи первой формы: с установленным модулем `js-host` ресурс с `type = "js"`
получает те же имена и возможности на JavaScript. Так написан пример `session-report`.

## Ресурсы и нативные модули

**Ресурс** - это папка в `resources/` (рабочий каталог сервера). В ней могут быть `resource.toml`,
серверная половина (`server/main.lua`) и клиентская половина (`client/`). Серверная половина
выполняется на сервере; клиентская передаётся каждому игроку и выполняется внутри игры. Чат,
политики машин, правила очистки и команды администратора - это ресурсы.

**Нативный модуль** - это `.dll` или `.so` в `modules/` рядом с исполняемым файлом. Он экспортирует
три символа (`node_plugin_abi`, `node_plugin_init`, `node_plugin_shutdown`) и получает таблицу
`NodeApi`. Пишите его, когда ресурс на Lua не справится: чтобы зарегистрировать языковой хост для
нового типа ресурсов (`js-host`) или выполнять фильтр ретрансляции прямо в сетевых потоках
(`dimensions`). Модули загружаются раньше ресурсов, поэтому языковой хост готов до того, как
будет просканирован первый ресурс.

Плагины, написанные для других многопользовательских серверов, здесь как есть не работают; о
том, как перенести такой плагин, - на странице [Перенос плагинов](/ru/plugins/migrating/).

## Что где выполняется

- **Серверная половина** выполняется в рабочем потоке плагинов. Каждый обработчик каждого ресурса,
  каждый таймер и каждый колбэк выполняются там, по одному за раз, поэтому ресурсы никогда не
  конкурируют друг с другом - а блокирующий обработчик останавливает их всех. Модель описана на
  странице [Конкурентность](/ru/plugins/concurrency/).
- **Клиентская половина** выполняется в BeamNG на машине каждого игрока с полным доступом к игре.
  С серверной половиной она общается сетевыми событиями: `node.emitServer(name, data)` на клиенте,
  `node.on(name, fn)` на сервере; `player:send` и `node.broadcast` - в обратную сторону. Событие,
  отправленное клиентом, доходит только до серверных ресурсов; всё, что должно дойти до других
  игроков, проходит через ресурс, который его пересылает. Клиентская таблица `node` описана на
  странице [Клиентские скрипты](/ru/plugins/client-scripting/).
- **Нативные модули** выполняются в процессе сервера. Вызовы `NodeApi` потокобезопасны из любого
  потока; колбэки приходят в тот же рабочий поток, что и обработчики Lua, - исключения, работающие
  инлайн, это приёмник лога и фильтр ретрансляции. Подробности - на странице
  [Нативные модули](/ru/plugins/native-modules/).

## Жизненный цикл

1. **Запуск.** Сервер загружает `modules/`, затем сканирует `resources/`: для каждой папки читает
   `resource.toml`, упаковывает клиентские файлы и один раз выполняет серверную точку входа. Код
   верхнего уровня - место, где вы подписываетесь на события и готовите состояние. Консоль
   подтверждает каждый ресурс строкой
   `demo-numbers v1.0 loaded — lua · server 1 file · 1 client file`.
2. **Работа.** Запускается рабочий поток; события, таймеры и корутины выполняются в нём.
   Подключающийся игрок получает клиентские файлы каждого ресурса после синхронизации контента,
   затем срабатывает `playerJoined`.
3. **Перезагрузка.** `node.resources.reload(name)` сбрасывает обработчики, таймеры и корутины
   ресурса и заново выполняет его серверную половину без перезапуска сервера. `node.storage`
   сохраняется; клиентские файлы не меняются до перезапуска.
4. **Остановка.** Один раз срабатывает `serverShutdown`, ожидающие асинхронные записи файлов
   сбрасываются на диск, каждое хранилище сворачивается в один JSON-файл, а клиентский мод
   выгружает переданные скрипты, когда игрок выходит.

## Слова

Страницы держатся одного слова на вещь, и [глоссарий](/ru/reference/glossary/#авторам-плагинов)
определяет каждое. **Плагин** - общее слово: собственные строки сервера говорят `plugin worker`,
`plugin job queue` о всей подсистеме. **Ресурс** - папка в `resources/`; **нативный модуль** -
библиотека в `modules/`; **языковой хост** - нативный модуль, который учит сервер новому типу
ресурса (`js-host`). Слова «модуль» само по себе страницы избегают, потому что оно же называет
**модульный канал** (`node.modules`, нумерованные двоичные каналы к клиентам) и **фреймворк
модулей** клиентского мода (`NodeMP.modules`). Справочник событий называет виды событий
`builtin`, `notify`, `cancellable`, `client`, `bus` и `module`; руководства называют те же виды
событиями движка, уведомлениями о машинах, отменяемыми запросами, сетевыми событиями, шиной и
модульным каналом.
