Если у вас уже есть опыт настройки серверов или создания плагинов для BeamMP, эта страница поможет сориентироваться и понять, что меняется при переходе на NodeMP.

Хотя обе платформы реализуют мультиплеер для BeamNG.drive, их экосистемы и сетевой стек полностью независимы.

Ниже приведено сравнение двух систем, где можно увидеть, что очень похоже, а что отличается координально. Данные о BeamMP опираются на [docs.beammp.com](https://docs.beammp.com/).

## Схоже

Общие концепции у обеих платформ очень близки:

- В основе лежит схожая архитектура: сервер управляет подключениями и раздаёт моды игрокам, лаунчер, в свою очередь, запускает игру и держит соединение.
- Конфигурация задается через единый TOML-файл с возможностью переопределения переменными окружения. См. [Конфигурацию](/ru/hosting/configuration/).
- Моды и карты размещаются на сервере в виде zip-архивов (`content/` в NodeMP, `Resources/Client` в BeamMP) и автоматически скачиваются клиентами перед входом в мир.
- Для публикации в общем каталоге используется ключ с сайта проекта: секция `[Directory]` в `server.toml` для NodeMP или `AuthKey` в `ServerConfig.toml` для BeamMP. Ключи и учетные записи не взаимозаменяемы.
- Поддерживается вход как под учетной записью, так и без неё — в режиме гостя (`[Directory] TestDrive` в NodeMP, `AllowGuests` в BeamMP).

## Что различается
***пересмотреть, после закрытия всех issues***

| | NodeMP | BeamMP |
|---|---|---|
| Транспорт | TLS 1.3 поверх TCP; UDP для потока позиций с аутентифицирующим трейлером; каждый пакет — типизированный бинарный кадр `(Category, SubType)`. Сетевой протокол v23 проверяется при подключении (несовпадение версий отклоняется). | Обычные TCP и UDP; пакеты идентифицируются начальным символом; игровой трафик не шифруется. |
| Среда плагинов | Неблокирующий однопоточный цикл событий для всех ресурсов: блокировок нет, но «тяжёлый» синхронный вызов подвешивает весь воркер. Асинхронность — через корутины (`node.async`, `node.sleep`) или пул потоков (`node.job`). Блокирующего sleep и синхронного HTTP в API нет. | API `MP.*`; вызовы `MP.Sleep` и `Http.Get` блокируют вызывающий поток Lua. Периодические задачи запускаются через `MP.CreateEventTimer`. |
| Форма API плагинов | `node.on(name, fn)` передаёт готовые объекты `Player` и `Vehicle`; действие отклоняется через `return false, reason`; одна точка входа на ресурс, остальные модули подключаются через `require`. | `MP.RegisterEvent(name, "handler")` передаёт числовые ID; действие отклоняется через `return 1`; автоматически загружается каждый `.lua` верхнего уровня папки. |
| Перезагрузка | Явная: `node.resources.reload(name)` с хуком очистки `resourceUnload`. Автоматического наблюдения за файлами нет. | Автоматическая: редактирование любого `.lua` верхнего уровня вызывает горячую перезагрузку; `onFileChanged` отслеживает изменения в `Resources/Server`. |
| Клиентский Lua | Передаётся при входе из `resources/<name>/client/`, выполняется в игре в собственном пространстве имён ресурса и не сохраняется на диск. По умолчанию обфусцируется Prometheus. Не может перезаписывать файлы игры или клиентского мода ([Клиентские скрипты](/ru/plugins/client-scripting/#что-клиентский-файл-может-и-чего-не-может)). | Поставляется внутри zip-архивов модов в `Resources/Client` и монтируется игрой как обычные моды. |
| Другие языки | C ABI для нативных модулей (`.dll`/`.so`). Модули могут добавлять языковые хосты — например, `type = "js"` через `js-host` ([Нативные модули](/ru/plugins/native-modules/)). | Только Lua. |
| База данных | Встроенный асинхронный пул PostgreSQL через `node.pg` ([Доступ к базе данных](/ru/plugins/database/)). | Встроенной поддержки БД нет. |
| Проверка целостности игры | `[General] VerifyGame`: хелпер проверяет клиентские файлы (`size`, `scripts`, `full` или `strict` по эталонному манифесту) перед каждым входом ([Строгая проверка](/ru/hosting/strict-verification/)). | Аналога в `ServerConfig.toml` нет. |
| Чат | Модульный: чатом управляет ресурс `chat`; без него вызов `node.chat.say` ничего не выводит. | Встроен в ядро: обработчик `onChatMessage` и функция `MP.SendChatMessage`. |
| Консоль | Сервер не слушает стандартный ввод консоли; администрирование строится через чат-команды, шину событий или клиентские меню. | Интерактивная консоль со встроенными командами и хуком `onConsoleInput`. |
| Файлы и JSON из Lua | В границах ресурса: `node.fs.read`, `write`, `writeAsync`, `list`; `node.json.encode`/`decode`. Стандартные модули `io` и `os` остаются доступными ([Ресурсы → Файлы](/ru/plugins/resources/#файлы-nodefs)). | Глобальный доступ к диску через `FS.*` (`Exists`, `CreateDirectory`, `Remove` и др.); `Util.Json*` с форматированием, сжатием, сглаживанием и RFC 6902 diff/patch. |
| Диагностика из Lua | `node.server.metrics()` (игроки, машины, сетевые счетчики, очередь событий) плюс сторожевой таймер зависаний. Имя ОС, детальная память и замеры отдельных обработчиков не отдаются. | `MP.GetOSName`, `MP.GetStateMemoryUsage`, `MP.GetLuaMemoryUsage`, `Util.DebugExecutionTime`. |
| Защищённые моды | Все архивы из `content/` раздаются каждому подключающемуся игроку без исключений. | `protectmod`: позволяет помечать моды, которые клиент должен найти и установить самостоятельно. |

## Можно ли запустить мой плагин BeamMP на NodeMP?

Нет. `Node-Server` — это совершенно другая программа со своей схемой настроек, ключами директории и архитектурой плагинов. Она не поддерживает API `MP.*`.

При переносе сервера:
- **Карты и машины** переносятся без изменений: достаточно скопировать zip-архивы в папку `content/`.
- **Логику плагинов** нужно переписать на API `node`. В руководстве по [Переносу плагинов BeamMP](/ru/plugins/migrating/) подробно сопоставлены функции и события двух платформ.
- **Игрокам** потребуется [установить лаунчер NodeMP](/ru/players/install/). После [регистрации сервера](/ru/hosting/registering/) сообщество сможет находить его в общем каталоге.
