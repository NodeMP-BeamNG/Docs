---
title: Отличия от BeamMP
description: Для тех, кто знаком с BeamMP, — что в NodeMP устроено так же, что иначе и чего стоит перенести сервер.
---

Если вы играли на BeamMP, держали там сервер или писали плагины, многое в NodeMP покажется
знакомым. Но это два отдельных проекта: лаунчер NodeMP заходит только на серверы NodeMP, а сервер
NodeMP принимает только игроков NodeMP. Здесь собрано, что переносится как есть, а что нет.

## Что одинаково

- Игру запускает лаунчер на компьютере игрока, он же держит соединение; работу внутри игры
  делает клиентский мод.
- Сервер раздаёт свои моды (машины, карты) zip-файлами всем, кто заходит, ещё до входа в мир.
- Машину считает игра того, кто сидит за рулём.
- Сервер настраивается одним TOML-файлом, и любую настройку можно задать переменной окружения
  (`NODE_*` в NodeMP).
- Чтобы попасть в публичный список, нужен ключ с сайта проекта; играть можно с аккаунтом или
  гостем (в NodeMP это называется Test Drive).

## Что устроено иначе

| | NodeMP | BeamMP |
|---|---|---|
| Соединение | TLS 1.3 для всего, что должно дойти; позиции по UDP, каждый пакет подписан. При подключении лаунчер и сервер сверяют версию протокола. | Обычные TCP и UDP. |
| Проверка файлов игры | Сервер может попросить лаунчер проверить установку игрока, вплоть до строгой сверки с чистой копией ([Строгая проверка](/ru/hosting/strict-verification/)). | Такой настройки нет. |
| Чат | Часть сервера. Плагины могут отклонить или переписать строку (`chatMessageRequest`) и добавить команды (`node.commands.add`). | Часть сервера, с `onChatMessage`. |
| Консоль сервера | `help`, `status`, `players`, `kick`, `say`, `reload`, `stop` ([Администрирование](/ru/hosting/administration/)). Плагины пока не могут добавлять свои команды консоли. | Консоль со встроенными командами и `onConsoleInput`. |
| API плагинов | `node.on(name, fn)`; обработчики получают объекты `Player` и `Vehicle`; отказ — `return false, "причина"`. Один входной файл на ресурс, остальные — через `require`. | `MP.RegisterEvent(name, "handler")` с идентификаторами; отказ — `return 1`; загружается каждый `.lua` в корне папки. |
| Ожидание | Ничто не блокирует. Таймеры, корутины (`node.async`, `node.sleep`) и фоновые задачи; HTTP асинхронный. | `MP.Sleep` и `Http.*` блокируют плагин. |
| Перезагрузка плагина | По запросу: `reload <имя>` в консоли или `node.resources.reload(name)`, с хуком `resourceUnload`, чтобы сохранить состояние. | Автоматически при изменении файла. |
| Скрипты в игре игрока | Приходят при входе из папки `client/` ресурса; на диск игрока не пишутся; по умолчанию обфусцированы. | Лежат внутри zip-модов. |
| База данных | Модуль `db` в архиве сервера: PostgreSQL и SQLite, на Windows ещё MySQL/MariaDB ([База данных](/ru/plugins/database/)). | Встроенной нет. |
| Другие языки | Нативные модули на C или C++ по заголовку на C; модуль может добавить язык. | Только Lua. |
| Защищённые моды | Мод с пометкой `protected` в `content/mods.json` сервер не отдаёт; игроки сами кладут его в кэш лаунчера. | `protectmod`. |

И ещё одно игроки замечают сразу: лаунчер NodeMP качает моды сервера и проверяет файлы игры до
того, как запустить игру, а соединение, оборвавшееся посреди сессии, по умолчанию
восстанавливается в течение 30 секунд, а не завершает её.

## Можно ли перенести сервер с BeamMP?

Почти всё, но вручную:

- **Карты и машины** переносятся как есть: положите zip-файлы в папку `content/` сервера.
- **Настройки** переезжают в `server.toml`; все они перечислены на
  [странице настройки](/ru/hosting/configuration/). Ключ для списка серверов берётся в вашем
  аккаунте NodeMP ([Попасть в список](/ru/hosting/registering/)).
- **Плагины** нужно переписать на API `node`. [Перенос плагинов BeamMP](/ru/plugins/migrating/)
  сопоставляет каждый вызов `MP.*` и каждое событие с аналогом в NodeMP и разбирает перенос на
  примере.
- **Игрокам** нужно поставить лаунчер NodeMP ([Установка лаунчера](/ru/players/install/)).
