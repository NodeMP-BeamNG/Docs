NodeMP — это небольшое ядро сервера плюс платформа плагинов. Ядро — `Node-Server`, один процесс
на одном порту TCP и UDP, настраиваемый файлом `server.toml`, — делает то, что нужно каждому
серверу: принимает игроков, проверяет, кто они, владеет реестром машин (места, авторитет,
повреждения, теги, блокировки), раздаёт контент и передаёт клиентские скрипты. Всё остальное —
чат, правила, экономика, параллельные миры — это плагин: **ресурс** (Lua или JavaScript) или
**нативный модуль** (C или C++). Эта страница — карта; писать плагин начинайте с
[обзора плагинов](/ru/plugins/overview/). Части вокруг сервера (лаунчер, хелпер, клиентский мод,
директория) представлены на странице [Что такое NodeMP](/ru/introduction/what-is-nodemp/).

## Роль директории

- **Публикация.** Когда заданы `[Directory] Url`, `HostId` и `HostSecret`, сервер открывает
  сессию хоста и отправляет маяк с интервалом, который запрашивает директория (по умолчанию
  15 с); список в лаунчере строится из этих маяков. `Public = false` продолжает объявлять сервер,
  так что игроки, знающие адрес, видят его онлайн, но скрывает его из списка.
- **Идентификация.** Лаунчер получает одноразовый билет на подключение к серверу, к которому
  собирается подключиться, и отправляет его сразу после рукопожатия. Сервер погашает билет и берёт
  из ответа проверенное имя: имя аккаунта или гостевое имя, выданное директорией.
  `TestDrive = false` отказывает гостям и подключениям без билета. `RedeemFailOpen = true`
  пропускает игроков непроверенными, пока директория недоступна, — только на сервере, который
  также разрешает Test Drive; по умолчанию им отказывают.
- **Релизы.** Лаунчер спрашивает у директории, какая сборка клиентского мода актуальна, и
  устанавливает её перед каждым подключением.

Сервер может работать без всего этого. Оставьте `[Directory] Url` пустым — и сервер не
публикуется, никого не проверяет и берёт имена такими, какими их прислал лаунчер, но при этом
работает, и любой, кто знает адрес, может подключиться через форму **Direct Connect** в лаунчере
(`host:port` или `[addr]:port` для IPv6). Direct Connect работает и для серверов из списка, и для
серверов с `Public = false`.

## Транспорт

```
client mod   <-- loopback TCP 4444 (commands) + 4445 (game traffic) -->  helper
helper       <-- TLS 1.3 over TCP + UDP (position, head pose)       -->  Node-Server
Node-Server  <-- HTTPS                                              -->  directory
```

Каждый пакет — типизированный кадр `(Category, SubType)`. Лаунчер и сервер должны говорить на
одной версии сетевого протокола (`v17`), иначе они отказывают друг другу. При первом запуске
сервер генерирует самоподписанный TLS-сертификат и пишет в лог его отпечаток SHA-256; отпечаток
сервера из списка попадает в лаунчер через директорию, а при прямом подключении он закрепляется
при первом соединении. Из игрового трафика по UDP идут только `State::Pos` и `State::HeadPose`,
каждый с трейлером HMAC. Подробности: [Как работает синхронизация](/ru/framework/sync/) и
[сетевой протокол](/ru/plugins/protocol/).

## Три среды выполнения

1. **Серверный Lua или JavaScript.** `server/main.lua` каждого ресурса получает собственное
   состояние Lua с API `node`: `node.on("playerJoin", fn)`, `node.players`, `node.vehicles`,
   объекты `Player` и `Vehicle`, `node.storage`, `node.http`, таймеры и корутины. Все обработчики
   всех ресурсов выполняются в одном рабочем потоке, поэтому плагины никогда не конкурируют за
   данные. Ресурсам на JavaScript (`type = "js"`) нужен нативный модуль `js-host`; они получают
   тот же API в записи JavaScript. Справочник: [Справочник API](/ru/plugins/api/) (Lua API и
   события).
2. **Передаваемый клиентский Lua.** Файлы из папки `client/` ресурса отправляются каждому игроку
   после синхронизации контента пакетами `Content::ResourceChunk` и выполняются внутри игры с
   полным доступом к игре — песочницы нет, потому что серверному коду доверяют. Файлы игрового
   движка становятся расширениями BeamNG (возвращённая таблица с `onUpdate` вызывается каждый
   кадр); файлы из `lua/vehicle/` внедряются в виртуальные машины автомобилей. Они используют
   глобальную таблицу `node`: `node.on`, `node.off`, `node.emitServer`, `node.emitLocal`,
   `node.log`, `node.onModule`, `node.offModule`, `node.sendModule`, `node.requestVehicleTrigger`
   и `node.requestNodeGrab`. Клиентский мод выгружает скрипты игрового движка, когда вы покидаете
   сервер; скрипты для автомобилей чисто выгрузить нельзя, поэтому Lua для автомобилей лучше
   поставлять как контент. Перед отправкой клиентский Lua обфусцируется Prometheus, если только
   не задано `[Resources] Obfuscate = false` или ресурс не указал `obfuscation = "none"`.
3. **SDK мода (`NodeMP.*`).** Локально установленные моды BeamNG обращаются к клиентскому моду
   через глобальную таблицу `NodeMP` (`NodeMP.isInSession()`, `NodeMP.getAccount()`,
   `NodeMP.players`, `NodeMP.vehicles`, `NodeMP.chat`, `NodeMP.events`, `NodeMP.keys`), с
   подмножеством для автомобилей в виртуальной машине автомобиля. Справочник:
   [Клиентские скрипты](/ru/plugins/client-scripting/).

## Структура папки ресурса

```
resources/
└── demo-numbers/
    ├── resource.toml
    ├── server/
    │   └── main.lua        # server half: the node API
    └── client/
        └── main.lua        # streamed to every player
```

```toml
name = "demo-numbers"
version = "1.0"
type = "lua"                 # or "js" (needs the js-host module)

[server]
main = "server/main.lua"     # the default

[client]
files = ["main.lua"]         # default: every .lua under client/
obfuscation = "none"         # none | light | medium | strong; default light
```

Папка `resources/` сканируется один раз при запуске; папка, в которой нет ни `server/main.lua`,
ни клиентских скриптов, пропускается. `node.resources.reload(name)` перезагружает один ресурс без
перезапуска сервера. Пути в `resource.toml` не могут выходить за пределы папки ресурса.

## Нативные модули

Модуль — разделяемая библиотека в `modules/` рядом с исполняемым файлом сервера, экспортирующая
`node_plugin_abi`, `node_plugin_init(const NodeApi*)` и `node_plugin_shutdown`. `NodeApi`
(объявлен в `node.h`) даёт возможности Lua API плюс то, что доступно только нативному коду:
зарегистрировать языковой хост для нового типа ресурсов (`js-host`) или выполнять фильтр
ретрансляции прямо в сетевом потоке (`dimensions`) — `node.relay.filter` в Lua работает в
рабочем потоке с кешированием вердиктов. Модули загружаются раньше ресурсов, поэтому языковой хост готов до того, как будет просканирован первый
ресурс. Справочник: [Справочник API](/ru/plugins/api/) (C ABI).

## Контент

Zip-архивы в `content/` (`[Content] Folder`) — это моды BeamNG, которые сервер раздаёт
подключающимся игрокам; хелпер сравнивает хеши и скачивает недостающее в `mods/multiplayer/`.
При `[Content] Encrypt = true` архивы передаются зашифрованными ChaCha20 с ключом, создаваемым
при каждом запуске сервера, а хелпер удаляет расшифрованные копии по окончании сессии. См.
[Ресурсы и моды](/ru/hosting/resources/).

## Ретрансляция

События, отправленные клиентом, заканчиваются на сервере: `node.emitServer("name", data)`
доходит до серверных ресурсов и больше никуда. Всё, что должно дойти до других игроков, проходит
через ресурс. Ресурс `nodemp-relay` пересылает события клиентского мода `vehicle:fire`,
`vehicle:grab` и `vehicle:state` всем остальным игрокам и применяет политику каждого игрока для
его машин (`player:policy`: режим блокировки, разрешения на триггеры и захват узлов); чат —
отдельный ресурс `chat`. Фильтр ретрансляции (`node.relay.filter` в Lua, хук `canRelay`) может
запретить любой ретранслируемый пакет для конкретного получателя — так `dimensions` строит
параллельные миры. Двоичные данные идут по модульному каналу с идентификатором канала `u32`:
`node.modules.send` на сервере, `node.sendModule` и `node.onModule` в клиентских скриптах.
