Здесь собраны ответы на самые частые вопросы об игре, настройке серверов и разработке плагинов. Точные определения используемых терминов смотрите в [глоссарии](/ru/reference/glossary/).

## Игрокам

### Кнопка «Играть» или кнопка с удержанием?

С удержанием: **Зажмите для игры** — удерживайте её около полусекунды и отпустите. Это защищает от случайного входа. Если вам удобнее подключаться одним кликом, задержку можно отключить в **Настройки → Лаунчер → Удержание для игры**. → [Подключение к серверу](/ru/players/join/#войти)

### Нужен ли аккаунт? Что такое Test Drive?

Нет, аккаунт не обязателен. Test Drive позволяет играть без регистрации: при каждом входе вы получаете случайное имя `Guest-…` (выбрать его вручную нельзя). Некоторые серверы не пускают гостей (*Нужен аккаунт* в карточке сервера; фильтр *Без аккаунта* скрывает такие серверы). Аккаунт даёт постоянный подтверждённый никнейм и доступ ко всем серверам. Зарегистрироваться можно на [nodemp.com](https://nodemp.com/register), а вход выполняется через браузер в лаунчере. → [Аккаунт и вход](/ru/players/sign-in/)

### Какая версия BeamNG нужна?

0.39.4.0 — актуальный релиз игры. Клиентский мод 1.6.19 собран именно под эту версию, а эталоны строгих серверов рассчитываются для чистой установки актуального релиза. Версия не из Steam также поддерживается: достаточно указать путь к ней в **Настройки → Игра**. → [Установка лаунчера → Что нужно](/ru/players/install/#что-нужно)

### Windows предупреждает о неизвестном издателе. Установщик настоящий?

Да. Установочный файл пока не имеет платной цифровой подписи, поэтому фильтр Windows SmartScreen показывает предупреждение. Вы всегда можете сверить контрольную сумму SHA-256 файла (команда `Get-FileHash` в PowerShell) со значением на странице загрузки. → [Установка лаунчера → Скачать и установить](/ru/players/install/#скачать-и-установить)

### Лаунчер обновляется сам?

Да. Он проверяет наличие обновлений при старте и перед каждым подключением. Новая версия скачивается автоматически, после чего лаунчер предлагает **Перезапустить и обновить**. Во время активной игры обновления никогда не устанавливаются. Если сервер требует более свежую версию лаунчера, подключение приостановится с кнопкой **Обновить сейчас** — лаунчер обновится и сразу вернётся к подключению. Клиентский мод также автоматически проверяется перед каждым входом. → [Установка лаунчера → Обновления лаунчера](/ru/players/install/#обновления-лаунчера)

### Сервер проверяет мои файлы игры? А мои моды?

Каждый сервер проверяет целостность клиента на том уровне, который выбрал хост. Только **строгий** сервер дополнительно сканирует пользовательскую папку BeamNG. Обычные упакованные моды в папке `mods\` никогда не блокируют вход — проверки их пропускают, а лаунчер автоматически отключает их на время сессии (если только вы не включили опцию *Использовать мои моды в мультиплеере*, и сервер это разрешает). Строгий сервер отклоняет вход только из-за файлов, оставшихся вне папки `mods\`: распакованного контента в подпапках `vehicles\`, `levels\`, `lua\`, `ui\`, `art\`, `scripts\` пользовательской директории или посторонних файлов в корне игры. → [Подключение к серверу → Что сервер проверяет на вашем ПК](/ru/players/join/#что-сервер-проверяет-на-вашем-пк)

### Как увидеть всё, что не понравилось строгому серверу?

В уведомлении об отказе сервер показывает не более трёх примеров. Встроенная диагностика лаунчера позволяет вывести полный список несовпадений с указанием типа проблемы в каждой строке (`overlay`, `unlisted`, `hash` и т.д.). Готовую команду для проверки можно скопировать по кнопке **Копировать** прямо под уведомлением. → [Серверы со строгой проверкой → Полный список проблем](/ru/support/strict-servers/#полный-список-проблем)

### Что значит «Стоковый контент»?

Это относится к **модам сервера**, которые лаунчер скачивает перед началом заезда. Отметка «Стоковый контент» означает, что сервер не загружает сторонних архивов и использует только стандартные автомобили и карты BeamNG.drive. Список файлов отображается в блоке «Что придётся скачать» в карточке сервера. К вашей локальной установке игры эта отметка отношения не имеет. → [Подключение к серверу → Посмотреть сервер](/ru/players/join/#посмотреть-сервер)

### Как прямое подключение работает, когда список серверов недоступен?

Вы подключаетесь по `IP:порт` без билета авторизации от директории. Локальный сервер без ключа принимает никнеймы напрямую; публичный сервер из списка с включённым Test Drive впустит вас как гостя; а сервер с требованием *Нужен аккаунт* отклонит подключение до восстановления связи с директорией. → [Проблемы с лаунчером → Список серверов пуст](/ru/support/launcher/#список-серверов-пуст)

### Что такое помощник лаунчера?

Фоновый процесс лаунчера, который запускает BeamNG.drive и держит сетевое соединение во время заезда. Это та же самая программа, работающая в фоновом режиме без отдельного окна. Её лог пишется в `launcher.log`, а сообщение **Сетевой помощник лаунчера остановился** означает, что этот процесс неожиданно завершился. → [Устранение неполадок](/ru/support/troubleshooting/#лаунчер-и-его-помощник)

### Моего сообщения нет на этих страницах. Что делать?

Все возможные тексты ошибок лаунчера, фонового помощника и сервера собраны на странице [Коды ошибок](/ru/support/error-codes/). Если вашей ошибки нет и там — скопируйте лог `launcher.log`, сделайте скриншот или скопируйте текст из центра уведомлений и обратитесь за помощью на форум или в Discord. → [Логи и отчёты](/ru/support/logs/)

## Хостам

### Какую версию сервера описывают эти страницы?

Текущий релиз; точка отсчёта — таблица версий на странице [Что такое NodeMP](/ru/introduction/what-is-nodemp/#версии). Там, где поведение старых версий отличалось, указано примечание с номером версии.

### Что нужно, чтобы мой сервер попал в список?

Аккаунт NodeMP с подтверждённой почтой и привязанным Discord (только такой профиль может создать ключ сервера), машина с открытым портом 30814 по TCP и UDP, и ключ, указанный в секции `[Directory]` файла `server.toml`. Без ключа сервер работает в приватном режиме и доступен через Direct Connect. → [Быстрый старт](/ru/hosting/quick-start/#что-понадобится), [Регистрация сервера](/ru/hosting/registering/)

### Я вставил блок `[Directory]` с сайта, и сервер завершается. Почему?

В `server.toml` по умолчанию уже присутствует секция `[Directory]`. Если вставить блок повторно, в файле образуются дублирующиеся ключи, что запрещено форматом TOML. Удалите дубликат и укажите параметры `Url`, `HostId` и `HostSecret` в существующей секции `[Directory]`. Сервер выведет подсказку: `the table [Directory] appears twice. Put the keys into the existing [Directory] table …`. → [Регистрация → Передача ключа серверу](/ru/hosting/registering/#передача-ключа-серверу)

### На Windows лог говорит `TLS handshake failed: certificate verify failed` в сторону `api.nodemp.com`. Ключ неверный?

Нет, ключ в порядке — сервер не смог найти доверенные корневые сертификаты Windows. Убедитесь, что файл `cacert.pem` находится рядом с `Node-Server.exe`. Если сертификаты системы недоступны, задайте переменную окружения `SSL_CERT_FILE` с путем к PEM-файлу корневых сертификатов. Не фиксируйте параметр `[Directory] Fingerprint`. → [Регистрация → Windows](/ru/hosting/registering/#windows-сертификат-директории)

### Как узнать, что проверка директории достучалась до моего порта?

Лог сервера не сообщает об этом напрямую. Если проверка прошла успешно, сервер появится в общем каталоге лаунчера и на странице nodemp.com/servers, а входящее TCP-подключение на порт 30814 из внешней сети будет проходить без сбоев. → [Регистрация → Что сервер делает с ключом](/ru/hosting/registering/#что-сервер-делает-с-ключом)

### Сервер говорит `Cannot listen on port 30814 … the port is already in use` и завершается. Почему?

Порт 30814 занят другим процессом — чаще всего это предыдущий экземпляр `Node-Server`, который ещё не завершился. Завершите старый процесс или задайте другой порт в конфигурации. Сервер завершается с кодом 1. → [Запуск → Логи](/ru/hosting/administration/#логи)

### Как снять бан?

Остановите сервер. Команда `Node-Server --bans list` выведет список банов, а `Node-Server --bans remove <ip | account id>` снимет блокировку (для игрока, забаненного во время сессии, удаляются обе записи — IP и аккаунт). Также можно отредактировать файл `bans.json` при выключенном сервере или вызвать функцию `node.bans.remove` из серверного плагина на работающем сервере. → [Запуск → Баны](/ru/hosting/administration/#баны)

### Где примеры ресурсов (`chat`, `demo-numbers`, …)?

В архиве релиза в папке `examples/` рядом с `Node-Server`; файл `examples/README.txt` описывает каждый из них. Скопируйте нужный пример в директорию `resources/` и перезапустите сервер. → [Ресурсы и контент → Установка ресурса](/ru/hosting/resources/#установка-ресурса)

### Нужен ли ПК с Windows для `strict`?

Для генерации эталонного манифеста — да, так как утилита сканирует установленные файлы BeamNG.drive. Сгенерированный файл манифеста `.manifest` затем можно перенести на любой сервер под Linux или в Docker-контейнер. → [Строгая проверка](/ru/hosting/strict-verification/#генерация-манифеста)

### Где release notes?

В описании релизов на GitHub (начиная с 1.2.1 — в файле `RELEASE_NOTES.md` репозитория сервера): список изменений, изменения конфигурации и сетевого протокола. Если релиз сервера не меняет сетевой протокол, игрокам не требуется обновлять лаунчер. → [Обновление](/ru/hosting/updating/)

## Авторам плагинов

### Какое правило именования событий, и что происходит со старыми именами?

События-уведомления именуются как `<subject><Verb-ed>` (`playerJoined`, `vehicleSpawned`, `serverShutdown`). Запросы, которые можно отменить — `<subject><Action>Request` (`vehicleSpawnRequest`, `relayRequest`). Префикс `on` не используется. Сетевые события пишутся в нижнем регистре через двоеточие: `<domain>:<verb>` (`chat:send`). Старые имена (`playerJoin`, `onVehicleSpawnRequest` и т.д.) сохранены как устаревшие псевдонимы: они работают, выводят одно предупреждение `[deprecated]` и будут удалены в версии 2.0. → [События → Именование](/ru/plugins/events/#именование)

### Какие HTTP-методы существуют?

Функция `node.http.request(method, url, opts?, cb)` поддерживает любые стандартные HTTP-методы. Хелперы `node.http.get`, `post`, `put`, `patch`, `delete` и `head` вызывают тот же запрос с фиксированным методом, а `node.http.fetch(url, { method = … })` предоставляет асинхронную форму для корутин внутри `node.async`. Заголовки ответа всегда приводятся к нижнему регистру (`headers["content-type"]`). Проверка TLS-сертификатов отключена по умолчанию; чтобы включить проверку, укажите `[Http] CaFile` в настройках сервера. → [Параллелизм → HTTP](/ru/plugins/concurrency/#http)

### Есть ли сокеты — `node.net`?

Прямого сокетного API в ресурсах сейчас нет. Для взаимодействия с внешними сервисами используйте `node.http`, а для связи между компонентами сервера — сетевые события, шину событий `node.bus` и каналы модулей.

### Что переживает перезагрузку ресурса, и что такое `resourceUnload`?

Горячая перезагрузка сбрасывает все серверные обработчики, таймеры, корутины, подписки на шину, фильтры ретрансляции и состояние Lua, после чего заново выполняет `main.lua`. Хранилище `node.storage`, файлы на диске и другие ресурсы сохраняются; фоновые задачи пула потоков и активные HTTP-запросы не прерываются, а клиентские файлы не переупаковываются до перезапуска сервера. Событие `node.on("resourceUnload", fn(reason))` вызывается прямо перед выгрузкой ресурса (с причиной `"reload"` или `"shutdown"`), позволяя сохранить важные данные. → [Ресурсы → Перезагрузка](/ru/plugins/resources/#перезагрузка)

### Что проверяет строгий сервер, а что нет?

Строгий режим сравнивает всю папку игры, таблицы CRC-32 игровых архивов и пользовательскую директорию BeamNG с чистым эталоном при входе и во время заезда. Он не хеширует всё содержимое архивов целиком, не проверяет файлы лаунчера и игнорирует папку `mods\`. Не путайте это со **строгой сессией** (`session:config.strict`) — внутриигровыми ограничениями, которые ресурс может активировать для игрока. → [Строгая проверка](/ru/hosting/strict-verification/#что-strict-не-проверяет), [Клиентские скрипты → Строгие сессии](/ru/plugins/client-scripting/#строгие-сессии-sessionconfigstrict)

### Как тестировать плагин без игры?

Вся серверная логика работает без подключения клиента. Команды чата можно эмулировать через шину событий: опубликуйте событие `chat:command` с параметрами `{ pid, name, args, raw }` (где `name` в нижнем регистре) и перехватите ответ в `chat:say`. Сетевые события и клиентские скрипты требуют реального запуска игры. → [Первые шаги → Тестирование без игры](/ru/plugins/getting-started/#тестирование-без-игры)

### Почему `/HELLO` не доходит до моего обработчика, когда я публикую `chat:command` сам?

Ресурс `chat` и функция `node.commands.add` всегда приводят имя команды к нижнему регистру при регистрации. Публикуемое через шину событие `chat:command` также должно передавать поле `name` только в нижнем регистре. → [Рецепты → Команда чата](/ru/plugins/recipes/#команда-чата)

### `node.on` с одной и той же функцией дважды — один раз или два?

Один: повторный вызов `node.on` с той же функцией заменяет предыдущую регистрацию. Для отписки используйте `node.off(name, fn)`. Две разные функции зарегистрируют два независимых обработчика. → [Конвенции → Формы возвращаемых значений](/ru/plugins/conventions/#формы-возвращаемых-значений)

### Почему мой колбэк таймера на 600 мс не вызвал предупреждение о зависании?

В актуальной версии сервера предупреждение вызывается: время выполнения каждого обработчика событий, колбэка таймера и отрезка корутины замеряется отдельно, а лог указывает проблемный ресурс и контекст (`(resource race, timer)`). → [Параллелизм → Один рабочий поток](/ru/plugins/concurrency/#один-рабочий-поток)

### Сообщает ли сервер о синтаксической ошибке в моём клиентском файле?

Да. При запуске сервера каждый клиентский скрипт парсится перед упаковкой. При наличии синтаксической ошибки сервер выводит сообщение `Error` с именем ресурса, файла и ошибкой Lua независимо от настроек обфускации. Файл всё равно отправляется клиенту, а ошибка исполнения появится в логе игрока `beamng.log`. → [Ресурсы → Обфускация](/ru/plugins/resources/#обфускация)

### Где примеры, и где `chat`?

Примеры лежат в папке `examples/` архива релиза рядом с `Node-Server` (см. `examples/README.txt`). Сетевой протокол чата (`chat:send`, `chat:msg`) и события шины (`chat:command`, `chat:say`) стандартизированы, поэтому собственный модуль чата реализуется буквально в несколько строк. → [События → node.bus](/ru/plugins/events/#между-ресурсами-nodebus)

### Может ли ресурс перезаписать файл игры или клиентского мода своим клиентским файлом?

Нет. Клиентские скрипты ресурсов компилируются в памяти под собственным пространством имён ресурса и никогда не записываются на диск игрока. Они добавляют новые модули и хуки, но не могут подменить файлы базовой игры или официального мода `NodeMP.zip`. → [Клиентские скрипты → Что клиентский файл может и чего не может](/ru/plugins/client-scripting/#что-клиентский-файл-может-и-чего-не-может)

### Как проверить, что файл существует, создать папку, переименовать или скопировать файл через `node.fs`?

Модуль `node.fs` содержит только методы `read`, `write`, `writeAsync` и `list`. Проверка существования выполняется поиском в списке `node.fs.list(folder)`. Создание папок происходит автоматически при вызове `node.fs.write` для родительских каталогов указанного пути. Для копирования прочитайте и запишите файл (`node.fs.write(to, node.fs.read(from))`), а для переименования или удаления используйте стандартные вызовы Lua `os.rename` и `os.remove` с абсолютным путем к папке ресурса. Все пути указываются через прямой слеш `/`. → [Ресурсы → Чего в node.fs нет](/ru/plugins/resources/#чего-в-nodefs-нет)

### Есть ли событие `fileChanged`?

Нет, сервер не отслеживает изменения файлов на диске в реальном времени. Периодическую проверку можно настроить через `node.every`, сравнивая размеры файлов в `node.fs.list` или их контрольные суммы. → [События → События о файлах нет](/ru/plugins/events/#события-о-файлах-нет)

### Случайные числа, время выполнения, память, операционная система — где?

Используйте стандартные возможности Lua: `math.random()` (генератор уже инициализирован), `node.server.uptime()` для замера времени выполнения и `collectgarbage("count")` для оценки памяти состояния Lua данного ресурса. Общая статистика по всем стейтам и системные данные ОС в API намеренно не предоставляются. → [Соглашения → Окружение Lua](/ru/plugins/conventions/#окружение-lua)

### Умеет ли `node.json` красиво печатать или считать и применять diff двух документов?

Нет. Функция `node.json.encode` формирует компактный JSON без форматирования отступами. Операции diff, patch и flatten в API отсутствуют. → [Соглашения → Окружение Lua](/ru/plugins/conventions/#окружение-lua)

### Может ли сервер вызывать мой языковой хост из нескольких потоков?

Нет. Все вызовы хостируемого ресурса передаются строго по одному в рамках главного рабочего потока сервера. Если хост использует собственный асинхронный цикл событий (как `js-host`), он сам диспетчеризирует колбэки. Вызовы `NodeApi`, обработка ретрансляции и задачи `submit_job` выполняются вне главного потока. → [Нативные модули → Языковые хосты](/ru/plugins/native-modules/#языковые-хосты)
