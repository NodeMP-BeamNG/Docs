Всё, что сервер может сказать, он пишет в консоль и в `logs/server.log`. Начните с лога.

## Сервер не запускается

Если сервер не может запуститься, он объясняет почему, пишет `Closing in 10 seconds` и завершается с кодом 1. Служба systemd видит это как сбой, а не как обычную остановку.

| Сообщение | Что случилось | Что сделать |
|---|---|---|
| `Cannot listen on port … (…): the port is already in use (…). …` | Порт занят. Чаще всего это вторая копия сервера, которую забыли остановить. | Остановите другую копию или задайте другой порт. |
| `Cannot listen on port … (…): … failed: …. Closing.` | Порт не открылся по другой причине, в строке слова системы. | Прочитайте их. Проверьте, что `[server] address` — адрес этой машины. |
| `[server] address = "…" is not an IP address (…); the server cannot listen. …` | В `address` (или `NODE_IP`) не адрес. | Верните `"::"`. |
| `Error parsing config file value: …: the table […] appears twice. …` | Таблица в `server.toml` записана дважды, обычно это второй `[listing]`. | Перенесите ключи в первую таблицу, вторую удалите. |
| `Error parsing config file value: …: the key … is given twice. …` | Одна настройка записана дважды в одной таблице. | Удалите одну из строк. |
| `Error parsing config file value: …: … -- the line reads …` | Другая ошибка в файле, строка процитирована. | Исправьте строку или удалите `server.toml`, чтобы сервер написал новый. |
| `[network] timers must satisfy lag_grace_sec < seat_takeover_sec <= seat_release_sec <= disconnect_sec …` | Таймеры `[network]` идут не по порядку. | Исправьте их в `server.toml` или в переменных `NODE_NETWORK_*`. |
| `TLS: cannot write … (…); the certificate pair is generated on the first start, …` | Сервер не может записать сертификат туда, куда указывают настройки. | Укажите в `[network] tls_cert` и `tls_key` файлы в папке, куда можно писать. В Docker см. [ниже](#docker). |

Если сервер запустился, но какая-то его часть нет, в логе будет `started, but … failed — what they do may not work`, а строки выше скажут почему. Сервер при этом продолжает работать.

## До сервера не достучаться

Лаунчер пишет, что не может достучаться до сервера, или список помечает сервер как тот, к которому не удаётся подключиться.

1. Откройте порт для TCP и для UDP. TCP нужен для входа и всего надёжного, UDP для позиций машин. Проверьте брандмауэр на машине и проброс порта на роутере.
2. Проверяйте снаружи: подключение из своей сети ничего не говорит о роутере. Попросите друга или воспользуйтесь сервисом проверки портов.
3. Оставьте `[server] address` равным `"::"`. Тогда сервер слушает все адреса, и лог это подтверждает: `listening on [::]:30814 (tcp, tls 1.3, dual-stack: IPv4 + IPv6)`.
4. В Docker публикуйте порт, который слушает сервер: `-p 30814:30814/tcp` и `-p 30814:30814/udp` или тот, что задан в `NODE_PORT` ([Сервер в Docker](/ru/hosting/docker/#запустить)).

Игроки из той же сети, что и сервер, заходят по локальному адресу, например `192.168.1.20:30814`.

## Игроков не пускает на входе

Игрок пишет, что лаунчер показал `TLS handshake failed: unexpected eof while reading`. Часто это сразу несколько игроков из одного места или все с одного VPN. Сервер ограничивает, сколько подключений с одного адреса могут одновременно проходить вход, и закрывает лишние до рукопожатия. В логе сервера это видно под тегом `Net`.

- Лимит задаёт `[network] max_connections_per_ip`, по умолчанию 32. Поднимите его, если многие игроки приходят с одного адреса: клуб, NAT оператора, выход VPN.
- `[network] connection_limit_exempt` перечисляет диапазоны адресов без лимита на адрес. По умолчанию это локальные и частные сети: так покрывается VPN или прокси на той же машине, что и сервер.
- Фоновые опросы списка серверов из лаунчеров тоже считаются подключениями.

Каждое подключение, которое сорвалось до входа, сервер пишет в лог под тегом `Net` с адресом и причиной: тайм-аут, не TLS 1.3, вообще не TLS, клиент закрыл соединение.

## Docker

### Сервер останавливается сразу после запуска

В логе будет `TLS: cannot write /opt/node/node_key.pem (…)`. Внутри образа папка программы только для чтения, а сертификат по умолчанию пишется туда. Перенесите его в папку данных:

```bash
-e NODE_TLS_CERT=/data/tls/node_cert.pem
-e NODE_TLS_KEY=/data/tls/node_key.pem
```

Образ создаёт `/data/tls` при каждом запуске. Почему эти файлы нельзя терять: [Отпечаток сервера](/ru/hosting/registering/#отпечаток-сервера).

### `server.toml` не читается

Так и задумано: образ ставит `NODE_PROVIDER_DISABLE_CONFIG=true`, и все настройки идут из переменных `NODE_*`. Чтобы сервер читал и писал `/data/server.toml`, задайте `NODE_PROVIDER_DISABLE_CONFIG=false`.

### Permission denied при запуске

Сервер работает от пользователя 10001 и не может писать в папку данных или читать скопированные в неё файлы. Выполните `sudo chown -R 10001:10001 data` и перезапустите контейнер.

### Консоль не отвечает

У контейнера без терминала консоли нет ([Консоль](/ru/hosting/docker/#консоль)).

## Сервера нет в списке

Причину пишет лог: [Попасть в список серверов](/ru/hosting/registering/#сервера-нет-в-списке). Закрытый порт сервер из списка не убирает: список помечает его как тот, к которому не удаётся подключиться ([выше](#до-сервера-не-достучаться)).

## Игрок жалуется на лаги

Найдите в `logs/server.log` его строки `netstats`, по одной каждые 15 секунд. `rtt` показывает время туда и обратно в миллисекундах, `loss` долю потерянных UDP-пакетов. Если цифры высокие у одного игрока, а у остальных всё хорошо, дело в его соединении: пришлите ему страницу [Плохое соединение и VPN](/ru/players/connection/). Если плохо у всех, проблема в канале самого сервера.
