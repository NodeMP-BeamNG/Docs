`[General] VerifyGame = "strict"` — самая строгая проверка файлов игры. Более лёгкие уровни
сравнивают установку игрока со списком файлов самой игры — списком, который игрок может поправить
вместе с файлами. `strict` сравнивает её с **эталонным манифестом**: описанием чистой установки,
которое вы делаете один раз на каждую версию игры и кладёте на сервер. Лаунчер игрока один раз
скачивает его, кэширует и сверяет с ним всю установку и пользовательскую папку игры перед каждым
входом и снова во время сессии.

Это для гонок и турниров, где у всех должна быть одна и та же игра. Для фрирума обычно хватает
проверки `size` по умолчанию.

## Что проверяется

Проверка идёт в лаунчере игрока, а отчёт оценивает сервер. Игрок проходит, если сходится всё это:

- **Каждый файл из манифеста** — по длине. Код игры (`lua/`, `ui/`), всё в `Bin64/` и `BinLinux/` и
  файлы `.exe` в папке игры ещё и сверяются по SHA-256, так что правку без изменения длины тоже
  поймают. Остальные файлы россыпью сравниваются по размеру. Проблемы: `missing`, `size`, `hash`.
- **Каждый игровой архив** (`.zip`) — по оглавлению: имя, размер и CRC-32 каждой записи сравниваются
  с чистой установкой. Проблемы: `missing`, `extra`, `duplicate`, `size`, `crc` и `unreadable` для
  повреждённого zip.
- **Вся папка игры.** Файл, которого нет в манифесте, — `unlisted`, кроме логов, кэшей и нескольких
  файлов, которые сами пишут игра или Windows (`integrity.json`, `*.log`, `temp/`, `startup.ini`,
  `shadercache/`, `desktop.ini`, …). `.dll` в `Bin64/` не прощается никогда. Если лаунчер
  установлен внутрь папки игры, его собственные файлы не учитываются.
- **Пользовательская папка игры** (`…\BeamNG.drive\current`), где игра накладывает файлы россыпью
  поверх упакованного контента. Разрешено только то, что игроки держат там законно: настройки,
  скриншоты, повторы, сохранения, кэши, моды в `mods/`, сохранённые конфигурации машин
  (`vehicles/<модель>/<имя>.pc` с картинками) и папки редакторов. Всё прочее в `vehicles/`,
  `levels/`, `lua/`, `ui/`, `art/`, `scripts/` или `gameplay/` — это `overlay`.

На BeamNG 0.39.4.0, когда файлы уже в кэше системы, вся проверка занимает около секунды (14 193
файла, 173 архива, 7 203 файла с хешем). Первая проверка после перезагрузки читает всё с диска и
идёт десятки секунд.

## Чего она не проверяет

Проверка держит честных игроков на чистой игре; это не граница безопасности.

- **Внутри архивов** сравнивается только оглавление. CRC-32 можно подделать, если намеренно
  изменить архив и подогнать его обратно; хешировать все архивы — значит читать около 50 ГБ на
  каждый вход. Вторая линия — правила вашего плагина на сервере.
- **Сам лаунчер** работает на машине игрока, а её игрок контролирует.
- **Файлы россыпью вне кода и бинарников** сравниваются только по размеру.
- **Проверки во время сессии** (после изменения файлов и по таймеру) не хешируют бинарники:
  библиотека, которую игра уже загрузила, ничего не изменит до следующего запуска, а он снова
  проводит полную проверку. Проверка, которую плагин запросил через `player:verify("strict")`,
  хеширует всё.
- **Манифест чист ровно настолько, насколько чиста установка, из которой его сделали.**

## Как сделать манифест

Генератор встроен в сервер. Запустите его на компьютере с **чистой** установкой BeamNG.drive той
версии, что у ваших игроков (сначала проверьте файлы в Steam и уберите из папки игры утилиты и
моды), Windows-сборкой `Node-Server`:

```powershell
.\Node-Server.exe --gen-integrity "C:\Program Files (x86)\Steam\steamapps\common\BeamNG.drive"
```

Аргумент — основная папка игры, та, где лежит `integrity.json`. На сервере с Linux или в Docker
игры нет, так что сделайте файл на компьютере с Windows и скопируйте; где его сделали, значения не
имеет. Вывод:

```
reading the game install at C:\Program Files (x86)\Steam\steamapps\common\BeamNG.drive (every file is hashed; a few GB take about a minute) ...
integrity manifest written
  game        0.39.4.0 (build 20972)
  root files  14193 (whole install, 2656.7 MB hashed)
  archives    173 (59594 entries)
  size        6.4 MB json, 1.2 MB compressed
  hash        e326499d35bdef6f1d937a6648113b34225d37c5d0e07b4fc22cdee5db1273a6
  file        integrity\0.39.4.0.manifest
Put the file in the server's [General] IntegrityDir (default "integrity") and set VerifyGame = "strict".
```

`hash` — это id манифеста; по нему манифест называют везде, и под этим именем его кэшируют
лаунчеры. Два запуска по одной и той же установке дают одинаковый файл и одинаковый id.
`--out <файл>` пишет его в другое место, `--game-version <x.y.z.w>` задаёт версию вместо прочитанной
из `integrity.json`. Если что-то пошло не так, генератор ничего не пишет и сообщает
`integrity manifest NOT written: …`.

## Куда его положить

Скопируйте файл в `integrity/` в рабочем каталоге сервера (`/data/integrity/` в Docker) или в папку,
которую называет `[General] IntegrityDir`. Задайте `VerifyGame = "strict"` (`NODE_VERIFY_GAME=strict`)
и перезапустите; и то и другое читается при запуске. Здоровый запуск пишет:

```
integrity manifest for game 0.39.4.0 (build 20972): 173 archives, 59594 entries, 14193 root files, 1.2 MB (38 chunks), hash e326499d…
strict game verification ON: reference manifest for game 0.39.4.0 (e326499d…)
```

Держите в папке **ровно один** `.manifest`. Лаунчер не сообщает серверу версию игры, так что с двумя
файлами сервер не может выбрать и отказывает каждому с
`This server has integrity manifests for 2 game versions (0.39.4.0, 0.39.3.0) and cannot tell which one you run. …`;
без файла — с ``This server requires a strict check of your BeamNG install but has no integrity manifest to check it against. Ask the host to run `Node-Server --gen-integrity <gamedir>` and put the file in the server's integrity folder.``

Сервер на другом уровне всё равно загружает папку
(`1 integrity manifest loaded from "integrity" (available to Player:verify("strict"))`), так что
плагин может провести строгую проверку, когда захочет, никому не отказывая на входе.

## После обновления игры

Манифест описывает одну версию игры. Когда BeamNG обновляется, игроков с новой версией старый
манифест не пускает. Сделайте новый манифест из обновлённой чистой установки, замените старый файл
(в папке по-прежнему один файл) и перезапустите. Лаунчеры заметят новый id и скачают его при
следующем входе. Тогда не пустит уже тех, кто ещё не обновил игру, с примерами вроде
`/Bin64/BeamNG.drive.x64.exe (hash)`; это лечится обновлением игры в Steam.

## Что видят игроки

Строгий вход добавляет два шага: загрузка манифеста (один раз; около 1,2 МБ) и сверка с ним. Чистая
установка дальше заходит как на любой другой сервер. Несовпадение получает отказ
`Game files do not match this server's reference (3 problems). userfolder:vehicles/pickup/pickup.jbeam (overlay), …`,
который лаунчер объясняет простыми словами и дополняет командой, выводящей все проблемы. Сторона
игрока описана на странице [Строгие серверы](/ru/support/strict-servers/).

Во время сессии лаунчер проверяет снова, когда меняются файлы в папке игры или пользовательской
папке, и раз в 10 минут. Проверка, нашедшая изменение, завершает сессию с
`Game files changed while you were playing and no longer match this server's reference (1 problem). …`.

## Для авторов плагинов

- [`player:verify(level)`](/ru/plugins/api/lua/#playerverifylevel---boolean-string) просит лаунчер
  игрока проверить ещё раз прямо сейчас — на уровне `"size"`, `"scripts"`, `"full"` или `"strict"`.
  Возвращает `true`, если запрос ушёл, или `nil` и причину: `"unknown player"`, `"unsupported"`
  (например, `"strict"` без ровно одного загруженного манифеста) или `"pending"` (один запрос на
  игрока раз в 60 секунд; проверка на входе не считается).
- [`playerVerifyReported`](/ru/plugins/api/events/#playerverifyreported) срабатывает на каждый
  отчёт, уже после решения сервера, с `{ level, outcome, problems, detail, manifest }`. На сервере с
  `VerifyGame = "off"` событие — единственное последствие; так строится аудит, который никому не
  отказывает.
- [`player:setStrict(on)`](/ru/plugins/api/lua/#playersetstricton---boolean-string) заставляет
  сервер не пересылать отчёты о камере, в которых этот игрок следит за машиной, в которой не сидит.
  Клиенту он ничего не сообщает; клиентские правила строгой сессии включает `session:config`
  ([Клиентские скрипты](/ru/plugins/client-scripting/#строгие-сессии)).
