---
title: Попасть в список серверов
description: Создать ключ сервера в аккаунте NodeMP, вписать его в настройки, настроить, как сервер выглядит в списке, и разобраться, почему его там нет.
---

Сервер без ключа работает точно так же, и на него можно зайти по адресу через **Прямое
подключение**. Но в списке серверов его нет, а имена игроков он не проверяет.

С ключом сервер сообщает о себе NodeMP, появляется в лаунчере и на
[nodemp.com/servers](https://nodemp.com/servers), а аккаунт каждого игрока проверяется при входе.

## Создать ключ

Нужен аккаунт NodeMP с подтверждённой почтой и привязанным Discord. Discord привязывается в
разделе **Подключения** аккаунта.

1. Войдите на [nodemp.com](https://nodemp.com) и откройте
   [**Мои серверы**](https://nodemp.com/account/servers).
2. Введите название, по которому вы узнаете сервер, и создайте ключ.
3. Сайт покажет **Host ID** и **Host secret**. Секрет показывается один раз — скопируйте его сразу.

Один ключ — для одного сервера. В **Моих серверах** видно все ключи и когда каждый сервер последний
раз выходил на связь.

## Вписать ключ в настройки

В `server.toml` уже есть таблица `[Directory]` с пустыми значениями. Заполните в ней три ключа:

```toml
[Directory]
Url = "https://api.nodemp.com"
HostId = "…"
HostSecret = "…"
```

:::caution[Не добавляйте вторую таблицу]
TOML не разрешает одну таблицу дважды. Если вставить под существующей таблицей ещё одну
`[Directory]`, сервер не запустится. Заполняйте ту, что уже есть в файле.
:::

То же самое переменными окружения, для Docker или systemd:

```
NODE_DIRECTORY_URL=https://api.nodemp.com
NODE_DIRECTORY_HOST_ID=…
NODE_DIRECTORY_HOST_SECRET=…
```

Перезапустите сервер. Нужны все три значения: если одного нет, сервер запустится без списка и
напишет об этом в логе. Храните секрет как пароль.

## Что происходит дальше

При запуске сервер пишет в лог `announcing this server to https://api.nodemp.com`, а когда ключ
принят — `listed in the server browser`. Потом он регулярно, обычно раз в 15 секунд, сообщает своё
имя, карту, число игроков и мест, теги и список модов. Если NodeMP недоступен, сервер продолжает работать и повторяет
попытки сам.

Ещё NodeMP проверяет снаружи, что до сервера можно достучаться по его порту. Недоступный сервер в
списке не показывается, даже если в логе есть `listed in the server browser`. Поэтому порт должен
быть открыт и проброшен, а проверять его нужно не из своей сети.

Пока сервер в списке, каждый вход проходит проверку: лаунчер игрока приносит одноразовый билет,
сервер сверяет его с NodeMP и получает имя аккаунта. Игрок в режиме Test Drive получает гостевое
имя. Сервер без ключа ничего не проверяет и берёт имя, которое прислал лаунчер.

## Как сервер выглядит в списке

Остальные ключи `[Directory]` задают карточку сервера и то, кого он пускает:

```toml
[Directory]
Description = "Фрирум на West Coast, без таранов"
Mode = "freeroam"
Tags = "freeroam, no-crash, ru"
TestDrive = true
```

- `Description` — одно-два предложения под именем.
- `Mode` — одно слово, отдельная колонка в списке: `freeroam`, `racing`, `roleplay`…
- `Tags` — до восьми тегов через запятую. По ним игроки фильтруют список.
- `TestDrive = false` не пускает игроков без аккаунта. В лаунчере такой сервер помечен «Нужен
  аккаунт».
- `Public = false` убирает сервер из общего списка. Те, кто знает адрес, по-прежнему видят его
  онлайн.
- `RedeemFailOpen` решает, что делать, если NodeMP недоступен в момент входа: `false` (по
  умолчанию) — не пускать, `true` — пускать как непроверенного гостя.

`Fingerprint`, `CaFile` и `AllowInsecure` нужны только для собственного каталога серверов. Для
`api.nodemp.com` оставьте их пустыми и выключенными.

### Картинка

В карточке сервера показывается картинка карты. Откуда она берётся:

1. Из `Preview`, если он задан: ваш JPEG или PNG до 2 МБ. Относительный путь считается от рабочей
   папки.
2. Иначе для своей карты из `content/` — её собственная картинка из архива.
3. Для стоковой карты NodeMP показывает картинку из игры, сервер ничего не отправляет.

## Отпечаток сервера

Лаунчеры узнают сервер по отпечатку его TLS-сертификата. Он пишется в лог при каждом запуске:
`TLS 1.3 enabled — certificate fingerprint (SHA-256): …`. Отпечаток меняется, только если потерять
или заменить `node_cert.pem` и `node_key.pem`, поэтому их стоит хранить в резервной копии. Игроки,
которые заходили по адресу, запоминают отпечаток и не подключатся к серверу с другим.

## Сменить или удалить ключ

В **Моих серверах** кнопка **Сменить секрет** выдаёт новый секрет (он тоже показывается один раз), а
старый перестаёт работать. Впишите новый `HostSecret` и перезапустите сервер. Делайте так, если
секрет мог утечь. **Удалить** удаляет ключ: сервер продолжит работать, но из списка пропадёт.

## Сервера нет в списке

| В логе | Почему | Что сделать |
|---|---|---|
| `The directory refused this server's credentials: …` | Неверный Host ID или секрет, секрет сменили или ключ удалили. | Сверьте с **Моими серверами**. Если сомневаетесь, смените секрет и впишите новый. |
| `This server is NOT announced to a directory: …` | Одного из трёх значений нет или в имени опечатка. | Заполните `Url`, `HostId` и `HostSecret`. |
| `Could not reach the directory at https://api.nodemp.com: …` | Нет исходящего HTTPS, не работает DNS или NodeMP недоступен. | Проверьте `curl https://api.nodemp.com/healthz` на машине сервера. Сервер повторяет попытки сам. |
| `listed in the server browser`, но в лаунчере сервера нет | NodeMP не достаёт до порта снаружи, или стоит `Public = false`. | Откройте и пробросьте порт. Список обновится примерно через 15 секунд. |
| Игроков не пускает с `The server could not verify your account with the directory (…)` | NodeMP был недоступен, когда они заходили. | Подождите. На сервере с Test Drive можно включить `RedeemFailOpen`. |
