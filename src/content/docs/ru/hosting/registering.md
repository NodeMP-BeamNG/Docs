---

Ключ сервера — то, что помещает ваш сервер в список лаунчера. Без него сервер работает точно так
же, и любой, у кого есть адрес, подключится через Direct Connect, но сервера нет в списке и ничьё
имя не проверяется. С ключом сервер объявляет о себе **директории** по адресу
`https://api.nodemp.com`, директория показывает его игрокам, и каждый билет на подключение
сверяется с аккаунтом игрока.

## Создание ключа сервера

Нужен аккаунт NodeMP с **подтверждённым адресом электронной почты** и **привязанным аккаунтом
Discord**. Регистрация на [nodemp.com/register](https://nodemp.com/register) спрашивает имя
пользователя, почту и пароль и отправляет ссылку для подтверждения; вход до перехода по ссылке
отвечает `please verify your e-mail first`. Discord при регистрации не спрашивают — его
привязывают на странице `/hosts`, и только аккаунт с привязанным Discord может создать ключ (ни для
чего другого привязка не используется). Хост без Discord не может вывести сервер в список; сервер
при этом работает и доступен через Direct Connect.

1. Войдите на [nodemp.com](https://nodemp.com) и откройте
   [nodemp.com/hosts](https://nodemp.com/hosts) (**Server keys**).
2. Если страница показывает **Link Discord to create server keys**, нажмите **Link Discord
   account** и подтвердите; форма создания ключа появится, когда привязка сделана.
3. В блоке **Create a server key** введите **Label** (до 64 символов, `EU Freeroam #1`) и нажмите
   **Create key**.
4. Диалог **Server key created** показывает **Host ID** и **Host secret**. Секрет показывается
   один раз; скопируйте его сейчас. Две вкладки предлагают его готовым для вставки:
   **server.toml** и **Environment** (следующий раздел).

Каждый ключ регистрирует один сервер. Директория допускает небольшое число ключей на аккаунт
(три по умолчанию). Ваши ключи перечислены в блоке **Your servers** со статусом (**Online**,
**Offline**, **Banned**), регионом, адресом и временем *last seen*.

## Передача ключа серверу

В `server.toml` уже есть таблица `[Directory]`: сервер записал её при первом запуске со всеми
ключами по умолчанию (для этих трёх — пустые строки). Заполните значения трёх ключей **в этой
существующей таблице**:

```toml
Url        = "https://api.nodemp.com"
HostId     = "…"
HostSecret = "…"
```

Не вставляйте второй заголовок `[Directory]` под первым. TOML не допускает таблицу, определённую
дважды, и сервер тогда завершается при запуске с
`Error parsing config file value: server.toml, line …: the table [Directory] appears twice. Put the keys into the existing [Directory] table -- the server wrote one with every key in it on the first start -- and remove the second [Directory] line together with the keys under it. The file has not been changed; fix it and start the server again.`
и `Closing in 10 seconds` (до 1.2.1 строка вместо этого цитировала парсер:
`toml::insert_value: table ("Directory") already exists`). Именно поэтому вкладка **server.toml**
на сайте показывает три строки ключей, и то же самое говорит заголовочный комментарий
сгенерированного файла. Комментарий над `Url` называет директорию, `https://api.nodemp.com` (в
файле, записанном версией 1.2.0 или старше, там стоит неверный пример адреса, пока следующий
запуск его не перепишет).

То же в виде переменных — для Docker-образа или unit systemd; они перекрывают те же ключи в
`server.toml`:

```
NODE_DIRECTORY_URL=https://api.nodemp.com
NODE_DIRECTORY_HOST_ID=…
NODE_DIRECTORY_HOST_SECRET=…
```

Перезапустите сервер. Нужны все три значения; если одно пусто, сервер стартует без листинга и
предупреждает. Относитесь к секрету как к паролю: окружение — лучшее место для него на машине,
где `server.toml` копируют или вставляют в темы поддержки.

## Что сервер делает с ключом

При запуске сервер открывает **сессию** с директорией (`POST /v1/hosts/session`, с ключом) и
пишет в лог `announcing this server to https://api.nodemp.com`. Затем он отправляет **маяк**
каждые 15 секунд — интервал задаёт директория, он ограничен диапазоном 5–300 секунд — с именем
сервера, описанием, режимом, тегами, портом, картой, числом игроков и вместимостью, до 100 имён
игроков, флагами `Public` и `TestDrive`, именами и общим размером архивов в `content/` и версией
сервера. Первый принятый маяк пишет в лог `listed in the server browser`. Когда маяки
прекращаются, запись в списке истекает через 45 секунд; когда директория недоступна, сервер
повторяет попытки через 5, 15, 30, 60, а затем каждые 120 секунд.

Директория также **проверяет** сервер: подключается к адресу, с которого пришёл маяк, на порт,
указанный в маяке, и завершает рукопожатие TLS. Проверка выполняется с первым маяком,
повторяется с каждым маяком, пока не проходит, и раз в две минуты после успеха. Сервер, чью
проверку пройти не удалось, не попадает в публичный список, даже если маяк принят, а отпечаток
сертификата, который видит проверка, — тот, который сообщают лаунчерам. Поэтому адрес вашего
сервера в списке — публичный адрес машины, отправляющей маяки, плюс `[General] Port`; за
роутером пробросьте этот порт на машину. Результат проверки в лог сервера не попадает:
`listed in the server browser` означает, что маяк принят, а не что проверка прошла. Прошла ли она, видно в
двух местах — сервер появляется в списке лаунчера и на [nodemp.com/servers](https://nodemp.com/servers)
примерно через 15 секунд после открытия порта, а TCP-соединение с `ваш публичный адрес:30814`
извне вашей сети проходит (`Test-NetConnection 203.0.113.10 -Port 30814` с ПК на другом
подключении или любой онлайн-проверщик портов). **Online** в блоке **Your servers** на `/hosts`
говорит лишь о том, что маяк дошёл, а соединение из вашей же локальной сети ничего не говорит о
роутере.

Пока сессия открыта, каждое подключение несёт билет от лаунчера, который сервер погашает в
директории: имя пользователя аккаунта заменяет имя, запрошенное лаунчером, а для игрока Test
Drive создаётся гостевое имя. Серверы без ключа пропускают этот шаг и принимают имена как есть.

## Настройки листинга

Всё остальное в `[Directory]` формирует запись и правила входа:

```toml
[Directory]
Description = "Freeroam on West Coast, no crashing into others"
Mode        = "freeroam"
Tags        = "freeroam, no-crash, eu"
Public      = true
TestDrive   = true
```

- `Description` — одно-два предложения под именем (обрезается до 500 символов).
- `Mode` — одно слово, показывается колонкой: `freeroam`, `racing`, `roleplay`, …
- `Tags` — до восьми тегов через запятую, каждый до 24 символов; игроки фильтруют по ним.
- `Public` — `false` держит сервер вне списка, но по-прежнему объявляет его, так что знающие
  адрес видят его в сети. Частный сервер для своей группы.
- `TestDrive` — `false` отклоняет игроков без аккаунта. Лаунчер показывает такой сервер как
  *Account required*, а гость при попытке получает
  `This server requires a NodeMP account: sign in to the launcher and join again`.
- `RedeemFailOpen` — `true` впускает игроков как непроверенных гостей, пока директория
  недоступна, вместо отказа с сообщением
  `The server could not verify your account with the directory (…). Try again in a moment`.
  Действует только вместе с `TestDrive = true`; обоснование — в
  [обзоре фреймворка](/ru/framework/overview/).
- `Fingerprint`, `CaFile` и `AllowInsecure` — для директории, которую вы держите сами
  (закреплённый сертификат, набор частного CA, адрес на простом `http://`). Для `api.nodemp.com`
  оставьте всем трём значения по умолчанию: её сертификат проверяется по доверенным корням
  машины — на Windows по хранилищу сертификатов Windows плюс `cacert.pem` из архива, см.
  [ниже](#windows-сертификат-директории). `CaFile` задаёт PEM-набор, по которому проверять
  *вместо* этих корней; относительный путь разрешается от рабочего каталога.

Измените любую из них и перезапустите; следующий маяк понесёт новые значения.

## Windows: сертификат директории

Сертификат директории — обычный публичный. На Windows сервер проверяет его по **хранилищу
сертификатов Windows** (хранилище `ROOT`) и, как запасной вариант для машины со скудным
собственным хранилищем — свежий Server Core, урезанный образ, — по **`cacert.pem`**, набору
публичных корней от Mozilla, который архив для Windows поставляет рядом с `Node-Server.exe`
вместе с его `cacert.LICENSE` (MPL 2.0). Перенося исполняемый файл, держите файл рядом с ним;
настраивать ничего не нужно. Переменные OpenSSL `SSL_CERT_FILE` / `SSL_CERT_DIR` тоже
учитываются. Машина, у которой нет ни пригодного хранилища, ни файла, получает одну понятную
строку при запуске —
`This machine has no trusted root certificates to verify the directory against (the Windows certificate store is empty and there is no cacert.pem next to Node-Server.exe): put Mozilla's cacert.pem (https://curl.se/ca/cacert.pem) next to the executable, or name a PEM bundle in [Directory] CaFile` —
и тот же совет внутри текста о неудавшемся рукопожатии. Linux и Docker-образ используют корни
дистрибутива.

До 1.2.1 — на 1.1.0 и 1.2.0 — сборка для Windows не смотрела ни туда, ни туда и проваливала
каждую попытку с
`Could not reach the directory at https://api.nodemp.com: TLS handshake failed: certificate verify failed (SSL routines)`,
хотя ключ и сеть были в порядке. Хост, всё ещё сидящий на одной из тех версий, обновляется
([Обновление](/ru/hosting/updating/)); до тех пор `SSL_CERT_FILE`, указывающая на PEM-набор
публичных корней (`Invoke-WebRequest https://curl.se/ca/cacert.pem -OutFile C:\NodeMP\cacert.pem`,
затем `$env:SSL_CERT_FILE = "C:\NodeMP\cacert.pem"` перед `.\Node-Server.exe`), выводит старую
сборку в список. Не обходите проблему через `[Directory] Fingerprint`: закрепление конечного
сертификата директории ломается, когда сертификат меняется.

## TLS-отпечаток вашего сервера

Идентичность сервера для лаунчеров — отпечаток SHA-256 его сертификата, который пишется в лог
при каждом запуске: `TLS 1.3 enabled — certificate fingerprint (SHA-256): …`. Серверы из списка
передают его игрокам через директорию (его записывает проверка); игроки Direct Connect закрепляют
его при первом визите. Он меняется, только если `node_cert.pem` и `node_key.pem` потеряны или
заменены, поэтому берегите их — см. [Обновление](/ru/hosting/updating/). Это не настройка
`[Directory]`; ключ `Fingerprint` там относится к сертификату директории, а не к вашему.

## Смена или удаление ключа

В блоке **Your servers** на [nodemp.com/hosts](https://nodemp.com/hosts):

- **Rotate secret** выдаёт новый секрет и показывает его один раз в диалоге **New host secret**.
  Старый секрет перестаёт работать; обновите `HostSecret` (или `NODE_DIRECTORY_HOST_SECRET`) и
  перезапустите. Делайте это всякий раз, когда секрет мог утечь.
- **Delete**, затем **Confirm**, удаляет ключ. Сервер, который всё ещё им пользуется, пишет в лог
  `The directory refused this server's credentials: check [Directory] HostId and HostSecret, and that the host still exists in your account`,
  продолжает работать и исчезает из списка.

## Устранение неполадок

| Что вы видите | Причина | Что делать |
|---|---|---|
| `announcing this server to …`, но `listed in the server browser` так и не появляется, и `The directory refused this server's credentials: …` | Неверный Host ID или секрет, сменённый секрет или удалённый ключ. | Сравните с ключом на nodemp.com; если не уверены — смените секрет и вставьте новый. |
| `Could not reach the directory at https://api.nodemp.com: TLS handshake failed: certificate verify failed (SSL routines)` | У сервера нет доверенных корневых сертификатов, чтобы проверить директорию. На текущем сервере это машина с Windows с пустым хранилищем и без `cacert.pem` рядом с исполняемым файлом (лог запуска так и говорит); на 1.2.0 и 1.1.0 это случалось на каждой машине с Windows. Ключ и сеть в порядке. | Обновите сервер; верните `cacert.pem` рядом с `Node-Server.exe`; или, на старой сборке, задайте `SSL_CERT_FILE` — см. [заметку о Windows](#windows-сертификат-директории). |
| `[Directory] CaFile '…' could not be loaded (…): the directory's certificate cannot be verified and this server will not be listed until it can` | `CaFile` называет набор, которого нет, который не разбирается или в котором нет ни одного сертификата. | Исправьте путь или файл либо оставьте `CaFile` пустым для `api.nodemp.com`. |
| `Could not reach the directory at https://api.nodemp.com: …` (любой другой текст после двоеточия) | Нет исходящего HTTPS, сбой DNS или директория недоступна. | Проверьте `curl https://api.nodemp.com/healthz` с машины сервера (он отвечает `{"status":"ok"}`). Сервер повторяет попытки сам через 5, 15, 30, 60, а затем каждые 120 секунд. |
| `This server is NOT announced to a directory: [Directory] needs Url, HostId and HostSecret, and one of them is empty` | Одно из трёх значений отсутствует или написано с ошибкой. | Заполните все три. Имена переменных: `NODE_DIRECTORY_URL`, `NODE_DIRECTORY_HOST_ID`, `NODE_DIRECTORY_HOST_SECRET`. |
| `Refusing to announce this server: the [Directory] Url is plain http…` | `Url` начинается с `http://`. | Используйте `https://api.nodemp.com`. |
| `listed in the server browser`, но сервера нет в списке лаунчера | Проверка не может достучаться до `ваш публичный адрес:Port` по TCP, или `Public = false`. | Откройте и пробросьте `30814/tcp` (и `/udp` для игры). Проверка повторяется с каждым маяком, так что список обновится примерно через 15 секунд после открытия порта. |
| Игроки получают отказ `This server requires a NodeMP account…` | `TestDrive = false`. | Так и задумано; поставьте `true`, чтобы впускать гостей. |
| Игроки получают отказ `The server could not verify your account with the directory (…)` | Директория была недоступна с сервера в момент подключения. | Подождите; или поставьте `RedeemFailOpen = true` на сервере с Test Drive. |
| `Could not reach the directory to stay listed: …` или `The directory answered 503 to a beacon: …` во время игры | Маяк не прошёл. | Сервер делает паузу и повторяет; игроки, которые уже внутри, остаются. |
