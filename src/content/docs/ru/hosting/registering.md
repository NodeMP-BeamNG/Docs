**Ключ сервера** — то, что ставит ваш сервер в список лаунчера. Без него сервер работает ровно так
же, и любой, у кого есть адрес, зайдёт через прямое подключение, но в списке его нет и ники никто не
проверяет. С ключом сервер представляется NodeMP, появляется в лаунчере и на
[nodemp.com/servers](https://nodemp.com/servers), а аккаунт каждого игрока проверяется при входе.

## Создать ключ сервера

Нужен аккаунт NodeMP с подтверждённой почтой и привязанным Discord (привязывается в разделе
**Подключения** аккаунта; больше ни для чего не используется).

1. Войдите на [nodemp.com](https://nodemp.com) и откройте **Мои серверы**
   ([nodemp.com/account/servers](https://nodemp.com/account/servers)).
2. Введите понятную вам подпись (`EU Freeroam #1`) и создайте ключ.
3. Сайт покажет **Host ID** и **Host secret**. Секрет показывается только один раз — скопируйте
   его сразу. Сайт предлагает и готовые к вставке варианты: строками для `server.toml` или
   переменными окружения.

Один ключ — один сервер. В **Моих серверах** видны все ваши ключи, их статус и когда сервер в
последний раз выходил на связь.

## Вписать ключ в сервер

В `server.toml` уже есть таблица `[Directory]`: сервер записал её при первом запуске с пустыми
значениями. Заполните эти три ключа **в этой таблице**:

```toml
[Directory]
Url = "https://api.nodemp.com"
HostId = "…"
HostSecret = "…"
```

Не вставляйте вторую таблицу `[Directory]` под первой. TOML этого не позволяет, и сервер тогда
останавливается при запуске с
`the table [Directory] appears twice. Put the keys into the existing [Directory] table -- the server wrote one with every key in it on the first start -- and remove the second [Directory] line together with the keys under it. …`
и затем `Closing in 10 seconds`.

То же самое переменными окружения — для Docker или юнита systemd (они сильнее файла):

```
NODE_DIRECTORY_URL=https://api.nodemp.com
NODE_DIRECTORY_HOST_ID=…
NODE_DIRECTORY_HOST_SECRET=…
```

Перезапустите сервер. Нужны все три значения; если одного нет, сервер запустится вне списка и
скажет об этом. Берегите секрет как пароль: на машине, где `server.toml` копируют туда-сюда, ему
лучше жить в окружении.

## Что происходит дальше

При запуске сервер пишет `announcing this server to https://api.nodemp.com`, а когда NodeMP примет
ключ — `listed in the server browser`. Дальше он отчитывается каждые 15 секунд: имя, карта, игроки,
места, теги, моды, которые он раздаёт, и их размер. Если NodeMP недоступен, сервер пробует снова
через 5, 15, 30 и 60 секунд, потом каждые 2 минуты, и всё это время работает.

Ещё NodeMP проверяет снаружи, что может достучаться до вашего сервера по его порту. Сервер, до
которого он не достучался, в списке не показывается, даже если в логе было
`listed in the server browser`. Поэтому за роутером пробросьте порт и проверьте снаружи своей сети:
сервер должен появиться в списке лаунчера примерно через 15 секунд после того, как порт открыт.
Проверка из своей же сети ничего не говорит о роутере.

Пока сервер в списке, каждый вход приносит одноразовый билет из лаунчера игрока, и сервер проверяет
его через NodeMP: вошедший игрок получает ник своего аккаунта, игрок в Test Drive — гостевое имя.
Сервер без ключа этого не делает и берёт ники такими, какими их присылает лаунчер.

## Как сервер выглядит в списке

Остальное в `[Directory]` определяет запись в списке и то, кого пускать:

```toml
[Directory]
Description = "Freeroam on West Coast, no crashing into others"
Mode = "freeroam"
Tags = "freeroam, no-crash, eu"
Preview = "listing.jpg"
Public = true
TestDrive = true
```

- `Description` — одно-два предложения под названием.
- `Mode` — одно слово, показывается столбцом: `freeroam`, `racing`, `roleplay`, …
- `Tags` — до восьми, через запятую; игроки могут по ним фильтровать.
- `Preview` — картинка в списке (см. ниже).
- `Public` — `false` убирает сервер из публичного списка. Те, кто знает адрес, всё равно видят его
  онлайн; удобно для своей компании.
- `TestDrive` — `false` не пускает игроков без аккаунта. Лаунчер показывает такой сервер как *Нужен
  аккаунт*, а гость, который всё же попробует, получит
  `This server requires a NodeMP account: sign in to the launcher and join again`.
- `RedeemFailOpen` — что делать, пока NodeMP недоступен и билет не проверить. `false` (по умолчанию)
  отказывает во входе; `true` пускает игрока непроверенным гостем под тем ником, который он
  попросил.
- `Fingerprint`, `CaFile` и `AllowInsecure` нужны только для своей директории. Для
  `api.nodemp.com` оставьте их пустыми и выключенными.

Поменяли что-то — перезапустите; следующий отчёт уйдёт уже с новыми значениями.

### Картинка

Карточка сервера в лаунчере показывает картинку карты. Откуда она берётся:

1. Из `Preview`, если вы его задали: свой JPEG или PNG, не больше 2 МБ. NodeMP обрежет её до 16:9 и
   уменьшит максимум до 960 на 540. Относительный путь считается от рабочего каталога.
2. Иначе, для своей карты в `content/`, — собственная картинка карты из её zip.
3. Для стоковой карты NodeMP показывает игровую картинку; сервер ничего не отправляет.

Лог называет картинку и откуда она взялась (`map preview for the server list: …`) и сообщает, когда
она отправлена (`map preview sent to the directory (…)`). Если файл слишком большой или это не JPEG
и не PNG, будет предупреждение с объяснением, а картинку, которую NodeMP отклонил, сервер не
отправляет снова, пока вы её не поменяете.

## Отпечаток вашего сервера

Лаунчеры узнают ваш сервер по отпечатку его TLS-сертификата, который пишется в лог при каждом
запуске: `TLS 1.3 enabled — certificate fingerprint (SHA-256): …`. Серверы из списка передают его
игрокам через NodeMP; игроки, зашедшие по адресу, запоминают его при первом визите. Он меняется,
только если `node_cert.pem` и `node_key.pem` потерялись или заменены, так что храните их копию
([Что сохранять](/ru/hosting/running/#что-сохранять-в-резервную-копию)). Настройка `Fingerprint` в
`[Directory]` — про сертификат NodeMP, а не ваш.

## Сменить или удалить ключ

В **Моих серверах** кнопка смены секрета выдаёт новый секрет (показывается один раз), а старый
перестаёт работать: обновите `HostSecret` и перезапустите. Делайте это всякий раз, когда секрет мог
утечь. Удаление убирает ключ; сервер, который им ещё пользуется, пишет
`The directory refused this server's credentials: check [Directory] HostId and HostSecret, and that the host still exists in your account`,
продолжает работать, но из списка пропадает.

## Если не получается

| Что вы видите | Почему | Что делать |
|---|---|---|
| `announcing this server to …`, затем `The directory refused this server's credentials: …` | Неверный Host ID или секрет, секрет сменили или ключ удалён. | Сверьте с ключом в **Моих серверах**; если не уверены, смените секрет и вставьте новый. |
| `This server is NOT announced to a directory: [Directory] needs Url, HostId and HostSecret, and one of them is empty` | Одного из трёх значений нет или оно с опечаткой. | Заполните все три. Переменные — `NODE_DIRECTORY_URL`, `NODE_DIRECTORY_HOST_ID` и `NODE_DIRECTORY_HOST_SECRET`. |
| `Refusing to announce this server: the [Directory] Url is plain http…` | `Url` начинается с `http://`. | Укажите `https://api.nodemp.com`. |
| `Could not reach the directory at https://api.nodemp.com: …` | Нет исходящего HTTPS, проблема с DNS или NodeMP недоступен. | Попробуйте `curl https://api.nodemp.com/healthz` на машине сервера. Сервер сам продолжает попытки. |
| `This machine has no trusted root certificates to verify the directory against …` | Машина с Windows с пустым хранилищем сертификатов и без `cacert.pem` рядом с `Node-Server.exe`. | Верните `cacert.pem` из архива релиза рядом с исполняемым файлом. |
| `[Directory] CaFile '…' could not be loaded (…): …` | `CaFile` указывает на файл, которого нет или который не является набором сертификатов. | Для `api.nodemp.com` оставьте `CaFile` пустым. |
| `listed in the server browser`, но в списке лаунчера сервера нет | NodeMP не достучался до вашего порта снаружи, или `Public = false`. | Откройте и пробросьте порт (TCP для проверки, UDP — ещё и для игры). Список обновится примерно за 15 секунд. |
| `Could not reach the directory to stay listed: …` или `The directory answered 503 to a beacon: …` | Отчёт не дошёл. | Ничего делать не нужно: сервер повторит, а игроки на сервере остаются. |
| Игрокам отказывают с `The server could not verify your account with the directory (…)` | В момент входа NodeMP был недоступен. | Подождите — или задайте `RedeemFailOpen = true` на сервере, который пускает в Test Drive. |
