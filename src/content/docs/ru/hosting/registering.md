title: Попасть в список серверов
description: Как создать ключ сервера в аккаунте NodeMP, вписать его в настройки, настроить вид сервера в списке и разобраться, почему его там нет.
---

Сервер без ключа работает так же, и на него можно зайти по адресу через **Прямое подключение**. Но в списке серверов его нет, а имена игроков он не проверяет.

С ключом сервер сообщает о себе NodeMP, появляется в лаунчере и на [nodemp.com/servers](https://nodemp.com/servers), а аккаунт каждого игрока проверяется при входе.

## Создать ключ

Нужен аккаунт NodeMP с привязанным Discord. Discord привязывается в разделе **Подключения** аккаунта или кнопкой **Привязать Discord** на странице **Мои серверы**.

1. Войдите на [nodemp.com](https://nodemp.com) и откройте [**Мои серверы**](https://nodemp.com/account/servers).
2. Впишите подпись, чтобы отличать сервер от других ваших (её видите только вы), и нажмите **Создать ключ**.
3. В окне *Ключ создан* сайт покажет **Host ID** и **Host secret**. Секрет показывается один раз, поэтому скопируйте его сразу.

Каждому серверу нужен свой ключ. На странице **Мои серверы** видно все ваши ключи и когда каждый сервер последний раз был в сети. Сколько ключей можно создать, зависит от ролей аккаунта. Сколько уже занято, видно рядом с формой создания ключа.

Если сайт не создаёт ключ, он пишет почему: не привязан Discord, у аккаунта уже все положенные ключи (удалите ненужный или смените секрет у существующего) или запрос отклонён для защиты сервиса. В последнем случае сайт показывает номер решения, его называют в поддержке.

## Вписать ключ в настройки

В `server.toml` уже есть таблица `[listing]` с пустыми `url`, `host_id` и `host_secret`. Заполните их:

```toml
[listing]
url = "https://api.nodemp.com"
host_id = "…"
host_secret = "…"
```

:::caution[Одна таблица `[listing]`]
Сайт показывает эти три строки готовыми к копированию. Впишите их в таблицу `[listing]`, которая уже есть в файле, и не добавляйте вторую: TOML не разрешает одну таблицу дважды, и сервер не запустится.
:::

То же самое можно задать переменными окружения, для Docker или systemd:

```text
NODE_DIRECTORY_URL=https://api.nodemp.com
NODE_DIRECTORY_HOST_ID=…
NODE_DIRECTORY_HOST_SECRET=…
```

Перезапустите сервер. Нужны все три значения. Если все они пусты, сервер не сообщает о себе и молчит об этом, а если пусто только часть, пишет об этом в лог. Храните секрет как пароль.

## Что происходит дальше

При запуске сервер пишет в лог `announcing this server to https://api.nodemp.com`, а когда ключ принят и список показывает сервер, пишет `listed in the server browser`. Потом он регулярно, обычно раз в 15 секунд, сообщает своё имя, карту, число игроков и мест, теги, список модов и отпечаток своего сертификата. Если NodeMP недоступен, сервер продолжает работать и повторяет попытки сам.

NodeMP к серверу не подключается, поэтому порт снаружи никто не проверяет, пока не придут игроки. Если игроки получают билеты на вход на сервер, а ни один до него не доходит, NodeMP помечает сервер *Не удаётся подключиться* на странице **Мои серверы**, лаунчер помечает его в списке, а в логе сервера появляется `Listed in the server browser, but players cannot connect: …` с номером порта, который нужно пробросить. Пометка снимается, как только игрок до сервера дойдёт. Поэтому откройте и пробросьте порт для TCP и UDP и проверьте его не из своей сети.

Пока сервер в списке, каждый вход проходит проверку: лаунчер игрока приносит одноразовый билет, сервер сверяет его с NodeMP и получает имя аккаунта. Игрок в режиме Test Drive получает гостевое имя. Сервер без ключа ничего не проверяет и берёт имя, которое прислал лаунчер.

## Как сервер выглядит в списке

Остальные ключи `[listing]` задают карточку сервера и то, кого он пускает ([Справочник настроек](/ru/hosting/configuration/#listing)):

```toml
[listing]
description = "Фрирум на West Coast, без таранов"
mode = "freeroam"
tags = "freeroam, no-crash, ru"
guests = true
```

- В `tags` до восьми тегов, каждый до 24 символов. По ним игроки фильтруют список.
- При `guests = false` сервер не пускает игроков без аккаунта, а в его карточке в строке **Доступ** написано *Нужен аккаунт*.
- При `public = false` сервера нет в общем списке, но на него по-прежнему можно зайти по адресу.

### Ссылки

В подробностях о сервере, под картой, лаунчер и [nodemp.com/servers](https://nodemp.com/servers) показывают кнопки на собственные страницы сервера, и на каждой написан её домен. Ссылки задают ключи `[listing]`:

```toml
[listing]
discord = "https://discord.gg/abc123"
rules = "https://example.com/rules"
site = "https://example.com"
donate = "https://example.com/donate"
voice = "mumble://voice.example.com:64738"
```

- Ссылка начинается с `https://`. Для `voice` можно ещё `mumble://` или `ts3server://`: такой адрес не открывается, а копируется, потому что открыть его может только программа голосового чата.
- `discord` должен быть приглашением: `https://discord.gg/…` или `https://discord.com/invite/…`.
- Ссылка не длиннее 256 символов, без пробелов и без `user:password@`.
- Ссылку, которая нарушает эти правила, сервер при запуске не передаёт в список и предупреждает, назвав ключ: `[listing] discord = "…" is not a link the server list shows: …; left out`.

### Картинка

В карточке сервера показывается картинка карты. Откуда она берётся:

1. Из `preview`, если он задан: свой JPEG или PNG до 2 МБ. Относительный путь считается от рабочей папки. Если файл не читается, слишком большой или не картинка, сервер предупреждает в логе `No map preview is sent to the directory: …`.
2. Иначе для своей карты из `content/` её собственная картинка из архива.
3. Для стоковой карты NodeMP показывает картинку из игры, сервер ничего не отправляет.

## Отпечаток сервера

Лаунчеры узнают сервер по отпечатку его TLS-сертификата. Он пишется в лог при каждом запуске: `TLS 1.3 enabled — certificate fingerprint (SHA-256): …`. Сервер передаёт его NodeMP в каждом сообщении о себе, и лаунчер примет только этот сертификат, в том числе при входе по адресу. Отпечаток меняется, только если потерять или заменить `node_cert.pem` и `node_key.pem`, поэтому храните их в резервной копии. Если отпечаток сменится, к серверу не из списка не подключатся лаунчеры, которые запомнили прежний ([Подключиться по адресу](/ru/players/join/#подключиться-по-адресу)).

## Сменить или удалить ключ

На странице **Мои серверы** кнопка **Сменить секрет** выдаёт новый секрет (он тоже показывается один раз), а старый перестаёт работать. Впишите новый `host_secret` и перезапустите сервер. Делайте так, если секрет мог утечь. Кнопка **Удалить** удаляет ключ: сервер продолжит работать, но из списка пропадёт.

## Сервера нет в списке

| В логе | Почему | Что сделать |
|---|---|---|
| `The directory refused this server's credentials: …` | Неверный Host ID или секрет, секрет сменили или ключ удалили. | Сверьте ключ со страницей **Мои серверы**. Если сомневаетесь, смените секрет и впишите новый. |
| `The directory refused this server: This server is banned from the directory.` | Модераторы NodeMP заблокировали этот сервер. | Напишите в Discord. |
| `This server is NOT announced to a directory: …` | Нет `url`, `host_id` или `host_secret`. | Заполните все три в `[listing]`. |
| `Refusing to announce this server: the [listing] url is plain http, …` | В `url` стоит `http://`, и секрет ушёл бы открытым текстом. | Впишите адрес с `https://`. |
| `Could not reach the directory at https://api.nodemp.com: …` | Нет исходящего HTTPS, не работает DNS или NodeMP недоступен. | Выполните на машине сервера `curl https://api.nodemp.com/healthz`. Сервер повторяет попытки сам. |
| `The directory answered 429 …` или `The directory answered 503 …` | Слишком много попыток за короткое время (например, сервер перезапускается по кругу) или NodeMP занят. Причину после двоеточия пишет сам NodeMP. | Ничего: сервер подождёт, сколько просит NodeMP, и попробует снова. |
| `not shown in the server browser: [listing] public is false; …` | Стоит `public = false`. | Уберите его или поставьте `public = true` и перезапустите сервер. |
| `Not shown in the server browser: the directory's staff have hidden it` | Модераторы NodeMP скрыли сервер из списка. | Напишите в Discord. |
| `Not shown in the server browser: it is banned from the directory` | Модераторы NodeMP заблокировали этот сервер. | Напишите в Discord. |
| `Not shown in the server browser: another server key already announces this address and port, …` | Один адрес и порт анонсируют два ключа, а в списке только один. | Удалите лишний ключ на странице **Мои серверы**. |
| `Listed in the server browser, but players cannot connect: …` | Игроки получали билеты на вход, но ни один не дошёл до сервера. | Пробросьте порт из этой строки для TCP и UDP и откройте его в брандмауэре. |
| Игрокам отказывают с `The server could not verify your account with the directory (…)` | NodeMP был недоступен или перегружен, когда они заходили. | Подождите. На сервере с Test Drive можно включить `admit_when_down`. |
