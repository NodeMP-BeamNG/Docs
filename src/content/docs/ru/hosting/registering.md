---
title: Попасть в список серверов
description: Создать ключ сервера в аккаунте NodeMP, вписать его в настройки, настроить, как сервер выглядит в списке, и разобраться, почему его там нет.
---

Сервер без ключа работает точно так же, и на него можно зайти по адресу через **Прямое
подключение**. Но в списке серверов его нет, а имена игроков он не проверяет.

С ключом сервер сообщает о себе NodeMP, появляется в лаунчере и на
[nodemp.com/servers](https://nodemp.com/servers), а аккаунт каждого игрока проверяется при входе.

## Создать ключ

:::caution[Ключи, созданные до перезапуска NodeMP]
NodeMP переехал на новый сервис и начал аккаунты и список серверов заново. Аккаунты и ключи
серверов, созданные раньше, удалены, и со старым ключом сервер не примут. Зарегистрируйтесь заново,
привяжите Discord и создайте новый ключ. Обновите и сервер: версия, выпущенная до переезда, в список
не попадёт ([Обновление](/ru/hosting/updating/)).
:::

Нужен аккаунт NodeMP с подтверждённой почтой и привязанным Discord. Discord привязывается в
разделе **Подключения** аккаунта.

1. Войдите на [nodemp.com](https://nodemp.com) и откройте
   [**Мои серверы**](https://nodemp.com/account/servers).
2. Введите название, по которому вы узнаете сервер, и создайте ключ.
3. Сайт покажет **Host ID** и **Host secret**. Секрет показывается один раз — скопируйте его сразу.

Один ключ — для одного сервера. В **Моих серверах** видно все ключи и когда каждый сервер последний
раз выходил на связь. Сколько ключей можно аккаунту, зависит от его ролей; страница показывает,
сколько осталось.

Если сайт не создаёт ключ, он пишет почему: не привязан Discord, не подтверждена почта, у аккаунта
уже все ключи, какие ему положены (удалите ненужный или смените секрет существующего вместо нового
ключа), или запрос отклонён для защиты сервиса. В последнем случае сайт показывает номер решения:
попросите помощи в Discord и назовите его.

## Вписать ключ в настройки

В `server.toml` уже есть таблица `[listing]` с пустыми `url`, `host_id` и `host_secret`.
Заполните их:

```toml
[listing]
url = "https://api.nodemp.com"
host_id = "…"
host_secret = "…"
```

:::caution[Одна таблица `[listing]`]
Сайт показывает эти три строки готовыми к копированию. Впишите их в таблицу `[listing]`, которая уже
есть в файле, и не добавляйте вторую: TOML не разрешает одну таблицу дважды, и сервер не запустится.
:::

То же самое переменными окружения, для Docker или systemd. Эти имена не менялись:

```
NODE_DIRECTORY_URL=https://api.nodemp.com
NODE_DIRECTORY_HOST_ID=…
NODE_DIRECTORY_HOST_SECRET=…
```

Перезапустите сервер. Нужны все три значения. Если `url` пустой, сервер просто не сообщает о себе;
если `url` задан, а ключа нет, сервер запустится без списка и напишет об этом в логе. Храните
секрет как пароль.

## Что происходит дальше

При запуске сервер пишет в лог `announcing this server to https://api.nodemp.com`, а когда ключ
принят и список показывает сервер — `listed in the server browser`. Потом он регулярно, обычно раз в
15 секунд, сообщает своё имя, карту, число игроков и мест, теги, список модов и отпечаток своего
сертификата. Если NodeMP недоступен, сервер продолжает работать и повторяет попытки сам.

NodeMP к серверу не подключается, поэтому порт снаружи никто не проверяет, пока не придут игроки.
Если игроки получают билеты на вход на ваш сервер, а ни один до него не доходит, NodeMP помечает
сервер «Не удаётся подключиться» в **Моих серверах**, лаунчер помечает его в списке, а в логе сервера
появляется `Listed in the server browser, but players cannot connect: …` с номером порта, который
нужно пробросить. Пометка снимается, как только игрок до сервера дойдёт. Поэтому откройте и
пробросьте порт для TCP и UDP и проверьте его не из своей сети.

Пока сервер в списке, каждый вход проходит проверку: лаунчер игрока приносит одноразовый билет,
сервер сверяет его с NodeMP и получает имя аккаунта. Игрок в режиме Test Drive получает гостевое
имя. Сервер без ключа ничего не проверяет и берёт имя, которое прислал лаунчер.

## Как сервер выглядит в списке

Остальные ключи `[listing]` задают карточку сервера и то, кого он пускает:

```toml
[listing]
description = "Фрирум на West Coast, без таранов"
mode = "freeroam"
tags = "freeroam, no-crash, ru"
guests = true
```

- `description` — одно-два предложения под именем.
- `mode` — одно слово, отдельная колонка в списке: `freeroam`, `racing`, `roleplay`…
- `tags` — до восьми тегов через запятую. По ним игроки фильтруют список.
- `guests = false` не пускает игроков без аккаунта. В лаунчере такой сервер помечен «Нужен
  аккаунт».
- `public = false` убирает сервер из общего списка. Те, кто знает адрес, по-прежнему видят его
  онлайн.
- `admit_when_down` решает, что делать, если NodeMP недоступен в момент входа: `false` (по
  умолчанию) — не пускать, `true` — пускать как непроверенного гостя.

`fingerprint`, `ca_file` и `allow_http` нужны только для собственного каталога серверов. Для
`api.nodemp.com` их не пишут.

### Ссылки

В подробностях о сервере, под картой, лаунчер и [nodemp.com/servers](https://nodemp.com/servers)
показывают кнопки на собственные страницы сервера, и на каждой написан её домен. Ссылок пять, все в
`[listing]`:

```toml
[listing]
discord = "https://discord.gg/abc123"
rules = "https://example.com/rules"
site = "https://example.com"
donate = "https://example.com/donate"
voice = "mumble://voice.example.com:64738"
```

- Ссылка начинается с `https://`. Для `voice` можно ещё `mumble://` или `ts3server://`: такой адрес
  не открывается, а копируется, потому что открыть его может только программа голосового чата.
- `discord` должен быть приглашением: `https://discord.gg/…` или `https://discord.com/invite/…`.
- Не длиннее 256 символов, без пробелов и без `user:password@`.
- Ссылку, которая нарушает эти правила, сервер при запуске выбрасывает и предупреждает, назвав ключ:
  `[listing] discord = "…" is not a link the server list shows: …; left out`. Всё остальное в
  списке работает как обычно.

В окружении это `NODE_DIRECTORY_LINK_DISCORD`, `NODE_DIRECTORY_LINK_RULES`,
`NODE_DIRECTORY_LINK_SITE`, `NODE_DIRECTORY_LINK_DONATE` и `NODE_DIRECTORY_LINK_VOICE`.

### Картинка

В карточке сервера показывается картинка карты. Откуда она берётся:

1. Из `preview`, если он задан: ваш JPEG или PNG до 2 МБ. Относительный путь считается от рабочей
   папки.
2. Иначе для своей карты из `content/` — её собственная картинка из архива.
3. Для стоковой карты NodeMP показывает картинку из игры, сервер ничего не отправляет.

## Отпечаток сервера

Лаунчеры узнают сервер по отпечатку его TLS-сертификата. Он пишется в лог при каждом запуске:
`TLS 1.3 enabled — certificate fingerprint (SHA-256): …`. Сервер передаёт его NodeMP в каждом
сообщении о себе, и лаунчер, который заходит из списка, примет только этот сертификат. Отпечаток
меняется, только если потерять или заменить `node_cert.pem` и `node_key.pem`, поэтому их стоит
хранить в резервной копии. Игроки, которые заходили по адресу, запоминают отпечаток и не подключатся
к серверу с другим.

## Сменить или удалить ключ

В **Моих серверах** кнопка **Сменить секрет** выдаёт новый секрет (он тоже показывается один раз), а
старый перестаёт работать. Впишите новый `host_secret` и перезапустите сервер. Делайте так, если
секрет мог утечь. **Удалить** удаляет ключ: сервер продолжит работать, но из списка пропадёт.

## Сервера нет в списке

| В логе | Почему | Что сделать |
|---|---|---|
| `The directory refused this server's credentials: …` | Неверный Host ID или секрет, секрет сменили, ключ удалили или он создан до перезапуска NodeMP. | Сверьте с **Моими серверами**. Если сомневаетесь, смените секрет и впишите новый. Вместо старого ключа нужен новый. |
| `The directory refused this server: This server is banned from the directory.` | Модераторы NodeMP заблокировали этот сервер. | Напишите в Discord. |
| `This server is NOT announced to a directory: …` | Нет `host_id` или `host_secret`. | Заполните `url`, `host_id` и `host_secret` в `[listing]`. |
| `Could not reach the directory at https://api.nodemp.com: …` | Нет исходящего HTTPS, не работает DNS или NodeMP недоступен. | Проверьте `curl https://api.nodemp.com/healthz` на машине сервера. Сервер повторяет попытки сам. |
| `The directory answered 429 …: Too many requests. Try again later.` или `The directory answered 503 …` | Слишком много попыток за короткое время (например, сервер перезапускается по кругу) или NodeMP занят. Текст после двоеточия — причина от самого NodeMP. | Ничего: сервер подождёт, сколько просит NodeMP, и попробует снова. |
| `not shown in the server browser: [listing] public is false; …` | Стоит `public = false`. | Уберите его или поставьте `public = true` и перезапустите сервер. |
| `Not shown in the server browser: the directory's staff have hidden it` | Модераторы NodeMP скрыли сервер из списка. | Напишите в Discord. |
| `Not shown in the server browser: another server key already announces this address and port, …` | Один адрес и порт анонсируют два ключа, а в списке только один. | Один ключ — один сервер: удалите лишний ключ в **Моих серверах**. |
| `Listed in the server browser, but players cannot connect: …` | Игроки получали билеты на вход, но ни один не дошёл до сервера. | Пробросьте порт из этой строки для TCP и UDP и откройте его в файрволе. |
| Игроков не пускает с `The server could not verify your account with the directory (…)` | NodeMP был недоступен или перегружен, когда они заходили. | Подождите. На сервере с Test Drive можно включить `admit_when_down`. |
