Сервер добавляет что-то поверх игры тремя способами. Эта страница — об установке и относящихся к
ней настройках; о написании — раздел [Разработка плагинов](/ru/plugins/resources/).

| | Ресурс | Контент | Нативный модуль |
|---|---|---|---|
| Что | Папка с серверным скриптом (Lua или, с `js-host`, JavaScript) и, при желании, клиентским Lua, который передаётся игрокам. | Zip-архив мода BeamNG: карта, машина, набор звуков. | Скомпилированный `.so` или `.dll`, собранный под SDK сервера. |
| Где | `resources/<name>/` в рабочем каталоге | `content/` в рабочем каталоге (`[Content] Folder`) | `modules/` рядом с исполняемым файлом |
| Игроки получают | Клиентские скрипты при каждом подключении, после синхронизации контента. Устанавливать ничего не нужно. | Архив, который лаунчер скачивает и подключает до запуска игры. | Ничего; он работает на сервере. |
| Загружается | При запуске, после модулей | Индексируется при запуске | При запуске, первым |

## Установка ресурса

Ресурс — это папка; установить его — скопировать папку в `resources/` и перезапустить сервер.
Откуда берётся папка:

- **Вы пишете её сами.** Самый маленький ресурс, `hello`, набирается на странице
  [Первые шаги](/ru/plugins/getting-started/) — манифест и два коротких Lua-файла, — а каждый
  рецепт на странице [Рецепты](/ru/plugins/recipes/) — законченный ресурс в несколько строк.
- **Примеры.** Страницы называют несколько примеров ресурсов — `chat` (чат и команды `/`, на
  которые опираются `player:tell` и `node.commands.add` в любом другом ресурсе), `demo-numbers`,
  `vehicle-cleanup`, `gatekeeper-example`, `nodegrab-allow`, `nodemp-relay`, `devapi-example`,
  `session-report`. Начиная с сервера 1.2.1 они входят в архив релиза в папке `examples/` рядом
  с `Node-Server`: скопируйте `examples/chat` в `resources/chat` и перезапустите. В архиве 1.2.0
  их нет, и отдельно они не публикуются.
- **Чужой ресурс.** Ресурс, написанный для NodeMP, — папка, которую вы копируете; ничего не
  устанавливается в систему, и ресурс никогда не выходит за пределы своей папки иначе как через API.

Лог подтверждает каждый:

```
demo-numbers v1.0 loaded — lua · server 1 file · 1 client file
1 resource · 0 modules loaded
```

Папка, в которой нет ни серверного скрипта, ни клиентских скриптов, молча пропускается. Под
Docker папка — `data/resources/<name>/`; сделайте её читаемой для пользователя с id 10001
(`sudo chown -R 10001:10001 data`) и перезапустите контейнер.

Без установленного `chat` помощники чата любого другого ресурса (`player:tell`, `node.chat.say`,
`node.commands.add`) не делают вообще ничего — ни строки в чате, ни строки в консоли; ресурс,
который хочет быть заметным, пока `chat` отсутствует, использует `node.log`.

## resource.toml

В каждой папке ресурса может лежать `resource.toml`. Всё в нём необязательно; папка без него — это
Lua-ресурс с именем папки и точкой входа `server/main.lua`.

```toml
name = "demo-numbers"
version = "1.0"
type = "lua"

[server]
main = "server/main.lua"

[client]
files = ["main.lua"]
obfuscation = "light"
```

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `name` | имя папки | Имя ресурса в логах, в API и в пакетах, которые несут его клиентские файлы. |
| `version` | пусто | Показывается после имени в строке загрузки (`demo-numbers v1.0`). |
| `type` | `"lua"` | Какая среда выполняет серверную часть; приводится к нижнему регистру. `"js"` требует модуля `js-host`. Тип, который не даёт ни один модуль, пропускается с сообщением `resource type 'js' has no language host loaded, skipping (a native module in modules/ must register one)`. |
| `[server] main` | `"server/main.lua"` | Серверная точка входа относительно папки ресурса. Должна оставаться внутри папки; путь, выходящий за неё, отклоняется. Ресурс может вовсе не иметь серверной части. |
| `[client] files` | все `.lua` в `client/`, рекурсивно | Файлы, передаваемые игрокам, относительно `client/`. Если ключ опущен, сначала идут файлы из `client/lua/ge/extensions/`, остальные — в алфавитном порядке. Перечисленные пути тоже должны оставаться внутри папки. |
| `[client] obfuscation` | `"light"` | `none`, `light`, `medium` или `strong`. `off` и `false` означают `none`; `high` и `full` означают `strong`; всё остальное — `light`. Игнорируется при `[Resources] Obfuscate = false`. |

Таблицу `[config]` сервер не читает; ресурс сам читает её как `node.config`, так что её ключи —
те, что задокументировал автор ресурса (см. `vehicle-cleanup` в примерах).

### Клиентские файлы

Клиентский Lua отправляется сразу после синхронизации контента, до того как о подключении узнают
другие ресурсы, пакетами `Content::ResourceChunk` до 900 КБ каждый. Файл из `client/lua/vehicle/`
доставляется как скрипт стороны автомобиля, всё остальное — как скрипт игрового движка. Один файл
больше предела в 900 КБ пропускается с предупреждением. Обфускация происходит до доставки и
невидима для клиентского мода.

## Обфускация

При `[Resources] Obfuscate = true` (по умолчанию) клиентский Lua перед передачей прогоняется
через прилагаемую копию обфускатора Prometheus. Prometheus — программа на Lua, поэтому серверу
нужен исполняемый файл Lua 5.1 или LuaJIT, чтобы её запустить:

- Windows: `tools\lua515\lua5.1.exe` из архива релиза, находится автоматически.
- Linux: в архиве релиза интерпретатора нет. Установите пакет `lua5.1` из дистрибутива и задайте
  `NODE_LUA=/usr/bin/lua5.1`. В Docker-образ встроено и то и другое.

При запуске сервер проверяет уровни на тестовом модуле. Успех —
`client obfuscation ready · runner lua5.1 · Prometheus (cache .obfcache)`. Без интерпретатора вы
получите `no Lua 5.1/LuaJIT runner found under tools/, client scripts will be shipped unobfuscated (drop lua5.1.exe in tools/lua515/ or set NODE_LUA)`,
а без `tools/` — `Prometheus not found under any tools/ dir, client scripts will be shipped unobfuscated`.
В обоих случаях сервер работает и отдаёт исходный текст. Файл, с которым Prometheus не
справляется, тоже отдаётся открытым, со строкой `Warn`, называющей его, так что подключение
никогда не срывается из-за обфускации. `Node-Server --obf-selftest` выполняет ту же проверку из
командной строки и печатает `[obf-selftest] available=1`, когда всё работает (в тексте `--help`
версии 1.2.0 флага нет; сервер 1.2.1 его перечисляет).

Клиентский файл, который не является корректным Lua, — одно из того, с чем Prometheus не
справляется. Сервер 1.2.0 сообщает об этом только таким косвенным способом —
`Prometheus failed on 'main.lua' (…), shipping it unobfuscated` — а при выключенной обфускации не
сообщает вовсе: первым признаком тогда становится ошибка компиляции в `beamng.log` игрока.
Начиная с сервера 1.2.1 каждый клиентский файл проверяется на синтаксис при упаковке независимо от
настройки обфускации, и файл, который не разбирается, получает строку `Error` с именем ресурса,
файла и сообщением парсера; файл всё равно отправляется, поскольку это проверка синтаксиса, а не
обещание, что игра его выполнит.

Три уровня из `[client] obfuscation`: `light` переименовывает локальные переменные и скрывает
строковые константы (безопасно для кода, выполняющегося каждый кадр); `medium` добавляет
косвенность для локальных переменных и переписывает числа (тяжелее во время выполнения);
`strong` дополнительно оборачивает весь файл (для меню и разовой инициализации, не для
покадрового кода). Результат детерминирован и кэшируется в `.obfcache/` рядом с `tools/`, поэтому
перезапуски и повторные подключения не запускают Prometheus заново для неизменённых файлов;
папку можно удалить в любой момент.

## Контент: клиентские моды

Положите архивы модов в `content/`. При запуске сервер хеширует каждый архив SHA-256, кэширует
хеш в `content/mods.json` по размеру и времени изменения и пишет в лог
`serving 2 mods (148.3 MB) from content/`. Всё, что не является `.zip`, сопровождается сообщением
`'…' is not a ZIP file and will be ignored`. Папка индексируется только при запуске: после
добавления, замены или удаления архива перезапустите сервер. Для обновления достаточно заменить
архив; изменившийся размер или время вызывают повторное хеширование.

Подключающиеся игроки скачивают архивы через лаунчер до запуска BeamNG, и лаунчер подключает их
только на эту сессию. Имена и общий размер входят в маяк, поэтому список серверов в лаунчере
показывает, сколько скачает подключение, а игроки могут фильтровать серверы по размеру контента.
Держите папку небольшой.

`[Content] Encrypt = true` шифрует архивы при передаче ChaCha20 с ключом, создаваемым при каждом
запуске; лаунчер тогда хранит в кэше только зашифрованные копии и удаляет расшифрованные архивы
из папки модов игры, когда игрок выходит. Пока игрок в сессии, открытый архив существует у него
на диске, так что это мешает собирать моды из кэша, но не останавливает решительного пользователя.

## Проверка установки игры

`[General] VerifyGame` решает, какую часть установки BeamNG подключающегося игрока сравнивать со
списком файлов самой игры до подключения. Лаунчер всегда выполняет как минимум проверку `size`,
поэтому настройка выбирает, сколько ещё требовать: `scripts` ловит отредактированный скрипт игры,
`full` хеширует всю установку и для подключения слишком медленна, `strict` сравнивает всю
установку, оглавление каждого архива и пользовательскую папку игрока с эталонным манифестом чистой
игры, который вы генерируете командой `Node-Server --gen-integrity`
([Строгая проверка](/ru/hosting/strict-verification/)). Несовпадение отклоняет игрока с указанием
причины. Проверка охватывает файлы самой игры, а не архивы из `content/`. Значения и время
выполнения — на странице [Конфигурация](/ru/hosting/configuration/).

## Нативные модули

Модули загружаются из `modules/` рядом с исполняемым файлом, до ресурсов, и могут научить сервер
новому языку ресурсов: `js-host` регистрирует `type = "js"`. Каждый модуль сверяется с ABI
плагинов сервера и отклоняется с требованием пересборки, если мажорная версия отличается. Модуль
собирается из исходников под SDK; Docker-образ содержит пустую `modules/` внутри образа, а не на
томе `/data`, поэтому модулю под Docker нужен образ, собранный поверх этого.
