Поверх игры сервер может добавлять три вида вещей. Эта страница — об их установке; как писать
плагины, рассказывает раздел [Разработка плагинов](/ru/plugins/overview/).

| | Моды (контент) | Ресурсы | Нативные модули |
|---|---|---|---|
| Что это | Zip-моды BeamNG: карта, машина, звуковой пак. | Плагины: папка с Lua, которая работает на сервере, иногда со скриптами для игроков. | Скомпилированные библиотеки (`.dll`, `.so`) для работы, которая должна быть быстрой. |
| Где лежат | `content/` в рабочем каталоге | `resources/<имя>/` в рабочем каталоге | `modules/` рядом с исполняемым файлом |
| Что получают игроки | Zip — лаунчер скачивает его до запуска игры. | Скрипты — приходят при входе. Ставить ничего не нужно. | Ничего; модуль работает на сервере. |
| Когда подхватываются | При запуске | При запуске; один можно перезагрузить на ходу | При запуске, раньше ресурсов |

## Моды: карты и машины

Положите zip-моды в `content/` и перезапустите сервер. При запуске он проверяет каждый zip и пишет
`serving 2 mods (148.3 MB) from content/`; файл, который не zip, отмечается как
`'…' is not a ZIP file and will be ignored`. Папка читается только при запуске, так что после того
как добавили, заменили или удалили zip, перезапустите сервер.

Игроки скачивают zip через лаунчер до запуска игры и хранят их в кэше лаунчера, так что в следующий
раз ничего не качается. Карточка сервера в лаунчере перечисляет файлы и их общий размер, и игроки
могут фильтровать серверы по нему. Не раздувайте папку.

**Своя карта**: положите её zip в `content/` и задайте `[General] Map` как
`/levels/<папка>/info.json`, где `<папка>` — папка карты под `levels/` внутри zip. Если у карты
есть своя картинка, сервер покажет её в списке ([Попасть в список](/ru/hosting/registering/#картинка)).

**Мод, который игроки берут сами**: откройте `content/mods.json` (его пишет сервер) и поставьте
`"protected": true` в записи нужного zip. Тогда сервер никогда не отдаёт этот файл, а игроку, у
которого его нет, говорят, куда положить его в кэше лаунчера. Пометка переживает замену zip.

## Ресурсы

Ресурс — это папка. Чтобы поставить его, скопируйте папку в `resources/` и перезапустите сервер.
Лог подтверждает каждый:

```
demo-numbers v1.0 loaded — lua · server 1 file · 1 client file
1 resource · 1 module loaded
```

Чат и системные сообщения сервера в чате работают без всяких ресурсов. Команды чата дают
ресурсы, например `chat-commands` ниже.

### Примеры

В архиве релиза есть несколько готовых ресурсов в папке `examples/` рядом с `Node-Server` и файл
`examples/README.txt`, который говорит, что делает каждый. Чтобы воспользоваться примером,
скопируйте всю папку в `resources/`; копия ваша, её можно менять, и обновления её не трогают.

| Пример | Что делает |
|---|---|
| `chat-commands` | Добавляет в чат `/help`, `/me` и `/pm`; с него удобно начать свои команды. |
| `demo-numbers` | Самый маленький ресурс с серверной и клиентской частью. |
| `freeroam-example` | Приветствует игроков, отвечает на событие от клиента, запускает таймеры. |
| `vehicle-cleanup` | Удаляет машины, которыми больше никто не пользуется, по правилам из своего `resource.toml`. |
| `gatekeeper-example` | Показывает, как отказать во входе, спавне или правке с причиной, которую увидит игрок. |
| `seat-demo` | Сажает игроков в машины с сервера, высаживает, меняет местами. |
| `nodegrab-allow` | Разрешает экспериментальный нод-граббер, который без такого плагина запрещён. |
| `devapi-example` | Обзор API плагинов, по одной возможности за раз. |
| `session-report` | Кто играл, сколько и на чём. Написан на JavaScript, для которого нужен нативный модуль, которого нет в архиве; без него сервер этот пример пропускает. |

На странице [Примеры плагинов](/ru/plugins/examples/) они разобраны для авторов плагинов.

### resource.toml

Ресурс может нести `resource.toml`; всё в нём необязательно:

```toml
name = "demo-numbers"
version = "1.0"

[client]
obfuscation = "light"

[config]
greeting = "Welcome!"
```

`name` и `version` видны в логе; `[config]` — собственные настройки ресурса, их описывает автор.
Полный список ключей — на странице [Ресурсы](/ru/plugins/resources/#resourcetoml).

### Перезагрузить один ресурс

`reload <имя>` в консоли сервера заново запускает серверную часть ресурса без перезапуска сервера.
Клиентские скрипты упаковываются один раз, при запуске: их изменения дойдут до игроков после
перезапуска.

## Клиентские скрипты и обфускация

Скрипты, которые ресурс отправляет игрокам, сначала запутываются (`[Resources] Obfuscate = true`, по
умолчанию), чтобы их было сложнее скопировать. Инструмент — Prometheus, программа на Lua в `tools/`
(с одноимённой системой мониторинга она никак не связана). Для работы ему нужна Lua 5.1:

- Windows: есть в архиве, находится сама.
- Linux: поставьте пакет `lua5.1` своего дистрибутива и задайте `NODE_LUA=/usr/bin/lua5.1`. В образе
  Docker всё уже есть.

Когда всё работает, лог пишет `client obfuscation ready · runner … · Prometheus (cache .obfcache)`.
Без Lua будет
`no Lua 5.1/LuaJIT runner found under tools/, client scripts will be shipped unobfuscated (drop lua5.1.exe in tools/lua515/ or set NODE_LUA)`,
а без `tools/` — `Prometheus not found under any tools/ dir, client scripts will be shipped unobfuscated`.
В обоих случаях сервер работает и отправляет скрипты как обычный текст. `Node-Server --obf-selftest`
проверяет настройку и выводит `[obf-selftest] available=1`, если всё в порядке.

Насколько сильно запутывать, ресурс выбирает в `[client] obfuscation`: `none`, `light` (по умолчанию,
годится для кода, который выполняется каждый кадр), `medium` или `strong` (для меню и разовой
настройки, не для покадрового кода). Результаты кэшируются в `.obfcache/`, эту папку можно удалять в
любой момент.

Ещё при упаковке сервер проверяет каждый клиентский скрипт на синтаксические ошибки и сообщает о них:
`race · client file 'main.lua' has a syntax error: main.lua:1: unexpected symbol near '=' (the file ships anyway; the game's Lua will very likely refuse it too)`.

## Нативные модули

Модули кладут в `modules/` рядом с исполняемым файлом, и они загружаются раньше ресурсов. Один уже
есть в архиве: модуль базы данных (`db.dll` или `db.so`), через который плагины работают с
PostgreSQL или SQLite ([База данных](/ru/plugins/database/)). Пока он не настроен, он пишет одно
предупреждение при запуске и в остальном просто ждёт.

При загрузке каждый модуль проверяется на совместимость с интерфейсом плагинов сервера, и модуль,
собранный под несовместимую версию, отклоняется с просьбой пересобрать его. В Docker папка
`modules/` находится внутри образа, а не на томе с данными, так что добавить модуль — значит
собрать свой образ поверх.
