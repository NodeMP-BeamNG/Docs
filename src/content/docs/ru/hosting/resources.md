Плагин — папка в `resources/` с Lua-кодом, который работает на сервере, и, если нужно, со скриптами, которые сервер отправляет игрокам. Команды чата, правила, режимы игры и инструменты для админов — всё это плагины. Как их писать: [Разработка плагинов](/ru/plugins/overview/).

## Поставить плагин

1. Скопируйте папку плагина целиком в `resources/` рядом с `server.toml`. Если папки `resources/` ещё нет, создайте её. В Docker это `data/resources/`.
2. Перезапустите сервер.

Каждый загруженный плагин сервер отмечает в логе:

```text
demo-numbers v1.0 loaded — lua · server 1 file · 1 client file
1 resource · 1 module loaded
```

Чат работает и без плагинов. А вот команды в чате, например `/pm`, появляются только с плагином, который их добавляет.

В архиве сервера рядом с программой лежит папка `examples/` с готовыми плагинами. Чтобы попробовать пример, скопируйте его папку в `resources/`. Копия ваша: её можно менять, обновление сервера её не тронет. Какие примеры есть: [Примеры плагинов](/ru/plugins/examples/).

## Настройки плагина

Плагин может нести файл `resource.toml`. Хосту в нём интересна таблица `[config]` с настройками самого плагина. Какие ключи там бывают, пишет автор плагина. Например, у `vehicle-cleanup`:

```toml
[config]
deleteIdleAfterSeconds = 600
maxWorldVehicles = 20
```

После правки перезапустите сервер или перезагрузите плагин.

## Перезагрузить плагин

Команда `reload <имя>` в консоли сервера заново запускает серверную часть плагина без перезапуска всего сервера. Клиентские скрипты сервер упаковывает один раз, при запуске, поэтому их изменения дойдут до игроков только после перезапуска.

## Обфускация клиентских скриптов

Скрипты, которые плагин отправляет игрокам, сервер сначала запутывает (`[resources] obfuscate`, включено по умолчанию), чтобы их было труднее скопировать. Делает это Prometheus, программа на Lua из папки `tools/`. С системой мониторинга того же имени она не связана. Для работы ей нужна Lua 5.1:

- на Windows она есть в архиве;
- на Linux поставьте пакет `lua5.1` и задайте `NODE_LUA=/usr/bin/lua5.1`;
- в Docker-образе она уже есть.

Если всё в порядке, в логе будет `client obfuscation ready · runner … · Prometheus (cache .obfcache)`. Если нет, сервер всё равно работает и отправляет скрипты как есть, а в логе объясняет, чего не хватает. Проверить настройку можно командой `Node-Server --obf-selftest`: при успехе она печатает `[obf-selftest] available=1`.

Насколько сильно запутывать, решает плагин ключом `[client] obfuscation` в `resource.toml`: `none`, `light` (по умолчанию), `medium` или `strong`. Результаты кэшируются в `.obfcache/`, эту папку можно удалить в любой момент.

Ещё при упаковке сервер проверяет синтаксис клиентских скриптов. Скрипт с ошибкой он всё равно отправит, но предупредит в логе: `… client file 'main.lua' has a syntax error: …`.

## Нативные модули

Нативный модуль — скомпилированная библиотека (`.dll` или `.so`) в папке `modules/` рядом с программой. Модули загружаются раньше плагинов. В архиве уже есть модуль базы данных для плагинов ([База данных](/ru/plugins/database/)).

При загрузке сервер проверяет, под какую версию интерфейса собран модуль. Несовместимый модуль он не загрузит и попросит пересобрать. В Docker папка `modules/` находится внутри образа: чтобы добавить модуль, соберите свой образ на основе этого.
