## Консоль

Сервер, запущенный в терминале, принимает команды прямо в своём окне. На Windows это окно `Node-Server.exe`, на Linux терминал, из которого его запустили.

| Команда | Что делает |
|---|---|
| `help` | Список команд. |
| `status` | Версия, время работы, игроки, машины, плагины, память. |
| `players` | Все игроки: номер, имя, пинг, машины и адрес (последняя часть скрыта). |
| `kick <id\|имя> [причина]` | Отключить игрока. Он увидит причину. Имя с пробелами берите в кавычки. |
| `say <текст>` | Системное сообщение в чат всем игрокам. |
| `reload <плагин>` | Перезапустить плагин. |
| `stop` | Остановить сервер. То же делают `exit` и `quit`. |

Плагины могут добавлять свои команды, `help` показывает их в разделе `from resources:` вместе с названием плагина. На слово, которое никто не взял, консоль отвечает `unknown command, try help`.

Без причины кикнутый игрок увидит `Kicked by the server`. У игроков доступа к консоли нет: `/kick 1`, набранный в чате, остаётся строкой чата, пока его не возьмёт себе какой-нибудь плагин.

У службы systemd консоли нет ([Служба systemd](/ru/hosting/linux/#служба-systemd)). В Docker консоль появляется, если дать контейнеру терминал ([Консоль](/ru/hosting/docker/#консоль)).

### Чат в консоли

Консоль показывает чат по мере того, как игроки пишут, с номером игрока:

```text
17:51:12.345  Chat   › (0) Alice: привет
17:51:16.000  Chat   › System -> all: Рестарт через 5 минут  [console]
```

Если строка не ушла, рядом написано почему, а строка, которую плагин взял как команду, помечена `[handled by a resource]`. Аргументы команд с паролями (`/login`, `/register` и других из `[chat] masked_commands`) заменяются на `***`. `[chat] log = false` убирает чат из консоли и лога.

## Кики и баны

Кикнуть можно из консоли, командой выше. Команды бана в консоли нет: банят плагины, например командой `/ban` для модераторов ([пример](/ru/plugins/chat/)).

### Баны

Баны хранятся в `bans.json` в рабочей папке, одним JSON-объектом. Ключ записи называет, что заблокировано: адрес, аккаунт NodeMP в виде `nodemp:<id>` или установку лаунчера в виде `install:<id>` (64 шестнадцатеричные цифры). В значении записаны причина, время и имя игрока:

```json
{
  "203.0.113.7": { "reason": "Спам", "at": 1789558100, "name": "Bob" },
  "nodemp:108": { "reason": "Спам", "at": 1789558100, "name": "Bob" },
  "install:6b46e2582a74234a47a4fa2c7046023be8ea6043e62ff00f1d6c166d39f57fd4": { "reason": "Спам", "at": 1789558100, "name": "Bob" }
}
```

У временного бана есть ещё поле `"until"`: время окончания в секундах Unix. Когда оно наступит, сервер сам уберёт бан.

Если забанить игрока, который на сервере, блокируются его адрес и, если он вошёл в аккаунт, сам аккаунт. Так бан действует и из другой сети. На сервере из списка блокируется и установка его лаунчера, номер которой сервер получает от NodeMP при входе: с этого лаунчера не войти ни с каким аккаунтом, ни в Test Drive. Номер установки у каждого сервера свой (другие серверы знают тот же лаунчер под другими) и меняется, когда NodeMP меняет ключ, а после этого бан по старому номеру не срабатывает. Забаненный игрок при входе видит причину или, если её нет, `You are banned from this server`.

NodeMP может заблокировать аккаунт сразу на всех серверах. Такой игрок не получит билет на вход ни на один сервер из списка, а того, кто уже играет, сервер отключит при следующем сообщении о себе NodeMP с `This account is banned from NodeMP`.

Чтобы снять бан, остановите сервер и выполните:

```text
Node-Server --bans list
Node-Server --bans remove 203.0.113.7
Node-Server --bans remove nodemp:108
Node-Server --bans remove install:6b46e2582a74234a47a4fa2c7046023be8ea6043e62ff00f1d6c166d39f57fd4
```

`list` показывает все баны, `remove` снимает один: по адресу, по `nodemp:<id>` или номеру аккаунта либо по `install:<id>`. Файл можно поправить и руками, но тоже при остановленном сервере. Работающий сервер держит список в памяти и перезапишет файл при следующем бане.

## Перезапуск с предупреждением

`stop` отключает всех сразу. Чтобы предупредить игроков, перезапуск планирует плагин: вызов `node.server.shutdown("Ночной перезапуск", 5 * 60 * 1000)` остановит сервер через пять минут. Игроки увидят эту причину, плагины сохранят данные, сервер завершится с кодом 0. Служба systemd с `Restart=always` или контейнер с `restart: unless-stopped` поднимут его снова, и получится перезапуск. Пример с обратным отсчётом в чате есть на странице [Таймеры и корутины](/ru/plugins/concurrency/).

## Лог

Всё, что сервер пишет в консоль, попадает и в `logs/server.log`, а в файле есть и больше. Консоль показывает то, на что нужно реагировать: входы и выходы, спавны, отказы, чат, предупреждения и ошибки. Статистика и служебные строки, например `netstats`, идут только в файл, пока `[logs] details = true` не выводит их и в консоль. Новый файл начинается при каждом запуске и когда старый перерастает 50 МБ. Пять старых хранятся как `server.1.log`, `server.2.log` и так далее (`[logs] max_size_mb` и `keep`).

Главные строки лога:

| Строка | Что значит |
|---|---|
| `server is ready` | Сервер полностью запустился. |
| `started, but … failed — what they do may not work` | Какая-то часть не запустилась. Почему, написано в строках выше. |
| `listed in the server browser` | Сервер в списке ([Попасть в список серверов](/ru/hosting/registering/)). |
| `<имя> kicked — <причина>` | Сервер отказал игроку или завершил его сессию теми же словами, что увидел игрок. |
| `netstats id=… rtt=… loss=…` | В файле, раз в 15 секунд по каждому игроку: пинг, трафик, потери ([Игрок жалуется на лаги](/ru/hosting/troubleshooting/#игрок-жалуется-на-лаги)). |

## Игрока не пускает

Игрок обычно присылает текст из лаунчера. Что он значит, сказано на странице [Сообщения об ошибках](/ru/reference/error-codes/), а в логе тот же текст стоит в строке с тегом `Kick`. Если не пускает сразу нескольких игроков из одного места, читайте [Игроков не пускает на входе](/ru/hosting/troubleshooting/#игроков-не-пускает-на-входе).
