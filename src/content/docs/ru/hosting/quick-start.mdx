`Node-Server` — это игровой сервер. Игроки подключаются к нему из лаунчера — из списка серверов
или по адресу. Эта страница — первая для хоста: она проводит одну машину от нуля до работающего
сервера в списке. Следующие страницы подробно разбирают [каждую настройку](/ru/hosting/configuration/),
[запуск как службы](/ru/hosting/running/) и [ключ сервера](/ru/hosting/registering/); слова,
которые здесь используются, определены в [глоссарии](/ru/reference/glossary/#хостам).

Три из них встречаются раньше своих страниц. **Директория** — сервис NodeMP по адресу
`https://api.nodemp.com`, который ведёт список серверов, видимый игрокам в лаунчере. **Ключ
сервера** (Host ID и Host secret из вашего аккаунта NodeMP) — то, что позволяет вашему серверу
объявить о себе директории и попасть в список. **Direct Connect** — форма лаунчера для
подключения к серверу по `адрес:порт` без списка.

## Что понадобится

- Машина, доступная из интернета по порту **30814**, TCP и UDP. За домашним роутером
  пробросьте оба на машину. Это единственное входящее требование; с директорией сервер
  общается по исходящему HTTPS.
- Linux x64 или Windows x64. Сборка для Linux сделана на Ubuntu 24.04 и требует glibc не
  старше; на более старом дистрибутиве используйте Docker-образ.
- Чтобы сервер попал в список лаунчера: аккаунт NodeMP на [nodemp.com](https://nodemp.com) с
  **подтверждённым адресом электронной почты** (без него не войти) и **привязанным аккаунтом
  Discord** (ключ сервера может создать только аккаунт с такой привязкой — ни для чего другого
  она не используется). Без ключа сервера сервер тоже работает, и любой, кому вы дадите адрес,
  подключится к нему через Direct Connect; он просто не в списке, и имена игроков не проверяются.
- Только для `VerifyGame = "strict"`: ПК с Windows и чистой установкой BeamNG.drive, чтобы
  сгенерировать эталонный манифест ([Строгая проверка](/ru/hosting/strict-verification/)). Всем
  остальным уровням ничего, кроме сервера, не нужно.

## Установка и запуск

<Tabs>
<TabItem label="Бинарник">

Архивы релиза приложены к тегу `server-v1.2.1` на
[github.com/NodeMP-BeamNG/releases](https://github.com/NodeMP-BeamNG/releases):
`Node-Server-1.2.1-linux-x64.tar.gz` и `Node-Server-1.2.1-windows-x64.zip`, к каждому — файл
`.sha256`. Оба содержат исполняемый файл и папку `tools/`. В `tools/` лежит **Prometheus** —
Lua-программа, которая обфусцирует *клиентские скрипты* (Lua-файлы, которые плагин передаёт в
игры игроков) перед тем, как они покинут сервер; с системой мониторинга с тем же названием она не
связана, настройки не требует и поставляется полным деревом исходников (`tools\prometheus\` с
`web/`, `tests/` и `Dockerfile` внутри — так и должно быть). В архиве для Windows есть и
интерпретатор Lua 5.1, нужный Prometheus (`tools\lua515\lua5.1.exe`); в архиве для Linux его
нет — установите пакет `lua5.1` из дистрибутива и укажите путь в `NODE_LUA`. Без интерпретатора
сервер всё равно запустится, но отдаст клиентские скрипты открытым текстом. Оба архива содержат
ещё и примеры ресурсов в папке `examples/` (с `README.txt`, который говорит, что делает каждый, их
`LICENSE` и файлом `EXAMPLES_COMMIT` рядом с исполняемым файлом, называющим коммит, из которого
они взяты), а zip для Windows добавляет `cacert.pem` — набор публичных корневых сертификатов от
Mozilla, с его `cacert.LICENSE` — рядом с `Node-Server.exe` (см. [Попасть в список](#попасть-в-список)).

**Linux**

```bash
sudo mkdir -p /opt/nodemp && sudo chown "$USER" /opt/nodemp
cd /opt/nodemp
curl -LO https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.2.1/Node-Server-1.2.1-linux-x64.tar.gz
curl -LO https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.2.1/Node-Server-1.2.1-linux-x64.tar.gz.sha256
sha256sum -c Node-Server-1.2.1-linux-x64.tar.gz.sha256
tar -xzf Node-Server-1.2.1-linux-x64.tar.gz
sudo apt install -y lua5.1
export NODE_LUA=/usr/bin/lua5.1
./Node-Server
```

**Windows** (PowerShell)

```powershell
New-Item -ItemType Directory -Force C:\NodeMP | Out-Null
Set-Location C:\NodeMP
Invoke-WebRequest https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.2.1/Node-Server-1.2.1-windows-x64.zip -OutFile Node-Server-1.2.1-windows-x64.zip
Invoke-WebRequest https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.2.1/Node-Server-1.2.1-windows-x64.zip.sha256 -OutFile Node-Server-1.2.1-windows-x64.zip.sha256
(Get-FileHash Node-Server-1.2.1-windows-x64.zip).Hash.ToLower() -eq (Get-Content Node-Server-1.2.1-windows-x64.zip.sha256).Split(' ')[0]
Expand-Archive Node-Server-1.2.1-windows-x64.zip -DestinationPath .
.\Node-Server.exe
```

Строка сравнения печатает `True`, если архив скачан без повреждений.

Первый запуск записывает `server.toml` со всеми ключами по умолчанию, создаёт TLS-сертификат
`node_cert.pem` и его ключ `node_key.pem` рядом с исполняемым файлом, создаёт `content/` (с
пустым кэшем хешей `content/mods.json`), `logs/` и `.obfcache/` и начинает работать. Среди
строк лога — первым идёт баннер с версией, именем, портом, картой и числом игроков — важны эти
шесть:

```
No config file found! Generating one...
generated a new self-signed TLS certificate (node_cert.pem)
TLS 1.3 enabled — certificate fingerprint (SHA-256): …
client obfuscation ready · runner lua5.1 · Prometheus (cache .obfcache)
0 resources · 0 modules loaded
server is ready
```

(На Windows строка интерпретатора читается `runner lua5.1.exe`.) Ещё две строки — норма, а не
предупреждения: `state relay interest management OFF (StateRelayRadius <= 0: every position relayed to everyone)`
описывает значение по умолчанию `[Network] StateRelayRadius`, а `listening on [::]:30814 (tcp, tls 1.3)`
вместе с парной `(udp)` говорит, что сервер принимает IPv6 и IPv4 на этом порту.

Остановите сервер по Ctrl+C и откройте порт. Команды для Windows нужно выполнять в PowerShell,
запущенном **от имени администратора**, — всё остальное на этой странице работает в обычном:

```bash
sudo ufw allow 30814/tcp
sudo ufw allow 30814/udp
```

```powershell
New-NetFirewallRule -DisplayName "Node-Server TCP" -Direction Inbound -Protocol TCP -LocalPort 30814 -Action Allow
New-NetFirewallRule -DisplayName "Node-Server UDP" -Direction Inbound -Protocol UDP -LocalPort 30814 -Action Allow
```

Затем отредактируйте `server.toml`. Ключи, которые меняет большинство серверов:

```toml
[General]
Name = "My server"
Map = "/levels/west_coast_usa/info.json"
MaxPlayers = 16
MaxCars = 2
```

Настройки читаются при запуске, поэтому запустите сервер снова. Каждый ключ описан на странице
[Конфигурация](/ru/hosting/configuration/).

<TabItem label="Docker">

Образ `ghcr.io/nodemp-beamng/server:v1.2.1` запускает тот же бинарник на Ubuntu 24.04 с
установленным Lua 5.1 (`latest` следует за новейшей сборкой ветки main и может опережать
последний релиз — закрепляйте тег версии). В нём нет `server.toml`: образ задаёт
`NODE_PROVIDER_DISABLE_CONFIG=true`, поэтому каждая настройка — переменная окружения:
`NODE_NAME` для `[General] Name` и так далее, список — в разделе
[Конфигурация](/ru/hosting/configuration/). Процесс работает от пользователя с id 10001, его
рабочий каталог — `/data`; там лежат `resources/`, `content/`, `storage/`, `tls/`, `.obfcache/`,
`logs/` и `bans.json`. Образ пока нельзя скачать анонимно: до того как пакет станет публичным,
`docker pull` доступен только аккаунтам, которым организация NodeMP-BeamNG дала доступ. Пока
используйте бинарник.

```bash
mkdir -p data && sudo chown 10001:10001 data
docker run -d --name nodemp-server --restart unless-stopped \
  -p 30814:30814/tcp -p 30814:30814/udp \
  -v "$PWD/data:/data" \
  -e NODE_NAME="My server" \
  -e NODE_MAP=/levels/west_coast_usa/info.json \
  -e NODE_MAX_PLAYERS=16 \
  -e NODE_MAX_CARS=2 \
  -e NODE_TLS_CERT=/data/tls/node_cert.pem \
  -e NODE_TLS_KEY=/data/tls/node_key.pem \
  ghcr.io/nodemp-beamng/server:v1.2.1
docker logs -f nodemp-server
```

Две строки важнее, чем кажутся. Папка данных должна принадлежать пользователю 10001 до первого
запуска: контейнер создаёт в ней каталоги состояния и отказывается работать, если не может. А
`NODE_TLS_CERT` и `NODE_TLS_KEY` должны указывать внутрь `/data`: относительный путь
разрешается рядом с исполняемым файлом, который внутри образа доступен только для чтения, и
сервер тогда останавливается с `TLS: failed to write /opt/node/node_key.pem`.

Откройте 30814 TCP и UDP в брандмауэре хоста и пробросьте их на роутере — так же, как для
бинарника. Чтобы изменить настройку, удалите контейнер (`docker rm -f nodemp-server`) и
запустите его снова с новыми переменными; всё в `data/` сохранится. На странице
[Запуск сервера](/ru/hosting/running/) та же конфигурация оформлена как файл Compose.

## Попасть в список

Сервер появляется в списке лаунчера, когда объявляет о себе директории по адресу
`https://api.nodemp.com` с **ключом сервера**. Создайте ключ на
[nodemp.com/hosts](https://nodemp.com/hosts) — для этого нужен аккаунт с подтверждённой почтой и
привязанным аккаунтом Discord; страница [Регистрация сервера](/ru/hosting/registering/) проводит
по шагам — и передайте его серверу:

- бинарник: в `server.toml` уже есть таблица `[Directory]` (её записал первый запуск, все ключи
  пустые). Задайте значения её трёх ключей `Url`, `HostId` и `HostSecret` так, как показывает
  сайт. **Не** вставляйте второй заголовок `[Directory]` под существующим: TOML не допускает
  таблицу, определённую дважды, и при следующем запуске сервер завершается с
  `Error parsing config file value: server.toml, line …: the table [Directory] appears twice. Put the keys into the existing [Directory] table …`;
- Docker: добавьте `-e NODE_DIRECTORY_URL=https://api.nodemp.com`, `-e NODE_DIRECTORY_HOST_ID=…`
  и `-e NODE_DIRECTORY_HOST_SECRET=…` в строку `docker run`.

Перезапустите. Лог сначала сообщит `announcing this server to https://api.nodemp.com`, а когда
директория примет ключ — `listed in the server browser` (так сервер называет список серверов).
Если вторая строка так и не появилась, ключ неверен или директория недоступна;
[таблица устранения неполадок](/ru/hosting/registering/#устранение-неполадок) на странице
регистрации перечисляет сообщения. На Windows сервер проверяет сертификат директории по
хранилищу сертификатов Windows и по `cacert.pem` из архива, так что настраивать ничего не нужно;
хост, всё ещё сидящий на 1.2.0 или 1.1.0, вместо этого видит
`Could not reach the directory at https://api.nodemp.com: TLS handshake failed: certificate verify failed (SSL routines)`,
и таблица говорит, что делать до обновления.

## Проверка из лаунчера

Запустите лаунчер, откройте **Servers** и найдите сервер по имени или воспользуйтесь
**Direct Connect** с адресом `203.0.113.10:30814` (ваш публичный адрес). Direct Connect работает
и для сервера без ключа. Первое подключение длится дольше: лаунчер проверяет файлы игры игрока
(`VerifyGame`) и скачивает контент, который вы положили в `content/`. Проверка `size` по умолчанию
сравнивает размеры файлов со списком самой игры; `scripts` и `full` хешируют больше; `strict`
сравнивает всю установку и пользовательскую папку игрока с эталонным манифестом чистой игры,
который вы сначала генерируете на ПК с Windows и установленной игрой — шаги на странице
[Строгая проверка](/ru/hosting/strict-verification/).

## Добавить ресурс

Пока плагин не решит иначе, сервер не делает ничего, кроме совместной езды, — чата включительно.
Папка `examples/` архива содержит примеры ресурсов, которые называют страницы (`chat`,
`demo-numbers`, `vehicle-cleanup`, …; `examples/README.txt` говорит, что делает каждый): установка
одного из них — копирование его папки в `resources/` и перезапуск; первым — `examples/chat` →
`resources/chat`, потому что чат и команды `/` живут там
([Ресурсы и контент](/ru/hosting/resources/#установка-ресурса)). Самый маленький ресурс, который
вы напишете сами, — `hello` со страницы [Первые шаги](/ru/plugins/getting-started/).
