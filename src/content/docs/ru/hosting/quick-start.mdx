`Node-Server` — программа, к которой подключаются игроки. Чтобы запустить её и попасть в список
лаунчера, нужно пять шагов:

1. [Скачать и запустить](#1-скачать-и-запустить).
2. [Открыть порт](#2-открыть-порт) — TCP и UDP.
3. [Задать имя, карту и число мест](#3-имя-карта-и-места).
4. [Попасть в список](#4-попасть-в-список) с ключом сервера.
5. [Зайти](#5-зайти) из лаунчера.

## Что понадобится

- Машина, до которой игроки могут достучаться по одному порту, TCP и UDP (`30814`, если не
  выберете другой). Дома это значит пробросить порт на роутере.
- Windows x64 или Linux x64 не старше Ubuntu 24.04 (серверу нужны glibc 2.38 и библиотека C++ из
  GCC 13). На более старом Linux используйте образ Docker.
- Чтобы попасть в список — аккаунт NodeMP на [nodemp.com](https://nodemp.com). Серверу вне списка
  аккаунт вообще не нужен; на него заходят по адресу.

## 1. Скачать и запустить

Сервер публикуется в [релизах на GitHub](https://github.com/NodeMP-BeamNG/releases) под тегом
`server-v1.7.0`: `Node-Server-1.7.0-windows-x64.zip`, `Node-Server-1.7.0-linux-x64.tar.gz` и образ
Docker `nodemp-server-v1.7.0-image.tar`, у каждого есть файл `.sha256` для проверки загрузки.

<Tabs>
<TabItem label="Windows">

В PowerShell:

```powershell
New-Item -ItemType Directory -Force C:\NodeMP | Out-Null
Set-Location C:\NodeMP
$base = "https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.7.0"
Invoke-WebRequest "$base/Node-Server-1.7.0-windows-x64.zip" -OutFile Node-Server-1.7.0-windows-x64.zip
Invoke-WebRequest "$base/Node-Server-1.7.0-windows-x64.zip.sha256" -OutFile Node-Server-1.7.0-windows-x64.zip.sha256
(Get-FileHash Node-Server-1.7.0-windows-x64.zip).Hash.ToLower() -eq (Get-Content Node-Server-1.7.0-windows-x64.zip.sha256).Split(' ')[0]
Expand-Archive Node-Server-1.7.0-windows-x64.zip -DestinationPath .
.\Node-Server.exe
```

Строка сравнения выводит `True`, если архив скачался целым. Не закрывайте окно, пока сервер
работает: оно же служит [консолью сервера](/ru/hosting/administration/#консоль).

</TabItem>
<TabItem label="Linux">

```bash
sudo mkdir -p /opt/nodemp && sudo chown "$USER" /opt/nodemp
cd /opt/nodemp
base=https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.7.0
curl -LO "$base/Node-Server-1.7.0-linux-x64.tar.gz"
curl -LO "$base/Node-Server-1.7.0-linux-x64.tar.gz.sha256"
sha256sum -c Node-Server-1.7.0-linux-x64.tar.gz.sha256
tar -xzf Node-Server-1.7.0-linux-x64.tar.gz
sudo apt install -y lua5.1
NODE_LUA=/usr/bin/lua5.1 ./Node-Server
```

`lua5.1` нужен серверу, чтобы запутывать скрипты, которые плагины отправляют игрокам; без него
сервер всё равно работает и отправляет эти скрипты как обычный текст.

</TabItem>
<TabItem label="Docker">

Образ лежит в релизе файлом. Загрузите его один раз:

```bash
docker load -i nodemp-server-v1.7.0-image.tar
```

Docker ответит `Loaded image: nodemp-server:1.7.0-0c9c284` — этот тег и запускайте. В образе
сервер берёт настройки только из переменных окружения (`NODE_NAME` для `[General] Name` и так
далее) и всё, что пишет, хранит в `/data`, от имени пользователя с id 10001:

```bash
mkdir -p data && sudo chown 10001:10001 data
docker run -d --name nodemp-server --restart unless-stopped \
  -p 30814:30814/tcp -p 30814:30814/udp \
  -v "$PWD/data:/data" \
  -e NODE_NAME="My server" \
  -e NODE_MAP=/levels/west_coast_usa/info.json \
  -e NODE_MAX_PLAYERS=16 \
  -e NODE_MAX_CARS=2 \
  -e NODE_TLS_CERT=/data/tls/node_cert.pem \
  -e NODE_TLS_KEY=/data/tls/node_key.pem \
  nodemp-server:1.7.0-0c9c284
docker logs -f nodemp-server
```

Две строки здесь важнее, чем кажутся:

- папка `data/` должна принадлежать пользователю 10001 ещё до первого запуска, иначе сервер не
  сможет писать свои файлы;
- `NODE_TLS_CERT` и `NODE_TLS_KEY` должны указывать внутрь `/data`. По умолчанию сертификат
  ложится рядом с исполняемым файлом, а там в образе только чтение, и сервер останавливается при
  запуске с `TLS: cannot write /opt/node/node_key.pem (…)`.

Чтобы поменять настройку, удалите контейнер (`docker rm -f nodemp-server`) и запустите заново с
новыми переменными; всё в `data/` останется. В разделе
[Чтобы сервер работал постоянно](/ru/hosting/running/#docker-compose) то же самое — файлом Compose.

</TabItem>
</Tabs>

При первом запуске сервер записывает `server.toml` со всеми настройками по умолчанию, делает себе
TLS-сертификат, создаёт `content/` и `logs/` и стартует. После заставки с версией, именем, портом и
картой смотрите на эти строки:

```
no config file server.toml yet; writing one with every default
generated a new self-signed TLS certificate (node_cert.pem)
TLS 1.3 enabled — certificate fingerprint (SHA-256): …
listening on [::]:30814 (tcp, tls 1.3, dual-stack: IPv4 + IPv6)
client obfuscation ready · runner lua5.1.exe · Prometheus (cache .obfcache)
0 resources · 1 module loaded
server is ready
```

Предупреждение о том, что база данных не настроена, — это нормально: модуль базы идёт вместе с
сервером и ждёт, пока он понадобится какому-нибудь плагину. Остановить сервер — Ctrl+C или команда
`stop` в его окне.

## 2. Открыть порт

Разрешите порт 30814, TCP и UDP, в файрволе и пробросьте оба на роутере, если машина за ним. В
Windows выполните это в PowerShell, открытом **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "Node-Server TCP" -Direction Inbound -Protocol TCP -LocalPort 30814 -Action Allow
New-NetFirewallRule -DisplayName "Node-Server UDP" -Direction Inbound -Protocol UDP -LocalPort 30814 -Action Allow
```

В Linux с `ufw`:

```bash
sudo ufw allow 30814/tcp
sudo ufw allow 30814/udp
```

## 3. Имя, карта и места

Откройте `server.toml` (в Docker — переменные `-e` выше). Большинство серверов меняют только это:

```toml
[General]
Name = "My server"
Map = "/levels/west_coast_usa/info.json"
MaxPlayers = 16
MaxCars = 2
```

Сервер читает файл при запуске, так что после изменения перезапустите его. Этот файл сервер пишет
один раз и ваши правки никогда не перезаписывает. Всё остальное — на странице
[server.toml](/ru/hosting/configuration/).

## 4. Попасть в список

Сервер появляется в списке лаунчера, когда представляется NodeMP с **ключом сервера**. Создайте его
в своём аккаунте на [nodemp.com/account/servers](https://nodemp.com/account/servers) (по шагам — на
странице [Попасть в список](/ru/hosting/registering/)), затем:

- **Windows и Linux:** в `server.toml` уже есть таблица `[Directory]` с пустыми значениями. Впишите
  туда `Url`, `HostId` и `HostSecret`.
- **Docker:** добавьте `-e NODE_DIRECTORY_URL=https://api.nodemp.com`,
  `-e NODE_DIRECTORY_HOST_ID=…` и `-e NODE_DIRECTORY_HOST_SECRET=…`.

:::caution[Не вставляйте вторую таблицу [Directory]]
TOML не разрешает одну и ту же таблицу дважды, и сервер тогда откажется запускаться с
`the table [Directory] appears twice. Put the keys into the existing [Directory] table …`.
Заполните ту таблицу, что уже есть.
:::

Перезапустите. В логе появится `announcing this server to https://api.nodemp.com`, а когда NodeMP
примет ключ — `listed in the server browser`. Если вторая строка так и не появилась, сообщения
разобраны в разделе [Попасть в список → Если не получается](/ru/hosting/registering/#если-не-получается).

## 5. Зайти

Запустите лаунчер, откройте **Серверы** и найдите свой сервер по имени — или нажмите **Прямое
подключение** и введите публичный адрес и порт, например `203.0.113.10:30814`. Прямое подключение
работает и для сервера без ключа.
