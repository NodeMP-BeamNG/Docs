Это протокол между помощником лаунчера и сервером NodeMP, сетевой протокол v23. Ресурсы его не
видят: они отправляют и получают события. С ним сталкиваются в фильтре ретрансляции нативного
модуля, которому пакеты описываются категорией и подтипом, и при чтении дампа трафика или
отладочного лога сервера. Здесь названы пакеты и их порядок; раскладка по полям — в
`include/net/Protocol.h` сервера, точная копия которого есть у помощника.

## Транспорт

У сессии два канала между помощником и сервером: одно TCP-соединение внутри **TLS 1.3** для всего
надёжного и, после привязки, один поток **UDP** для позиций машин.

- **По UDP** идут только `State::Pos`, `State::HeadPose`, `State::PosBatch` и пакеты рукопожатия
  `Ping`, `Pong`, `UdpHello` и `UdpHelloAck`. Датаграммы клиента подписываются ключом сессии,
  который один раз приходит по TLS (`UdpToken`) и никогда не передаётся по UDP. Пока UDP не
  привязан, позиции идут по TCP.
- **Локальные каналы.** Игра говорит с помощником по двум локальным TCP-портам: `4444` — канал
  команд, `4445` — ретрансляция. Первый кадр на каждом — `Command::Auth` с токеном помощника;
  с неверным токеном соединение закрывается.
- **Сжатие.** Сжатое тело помечено битом `FlagCompressed` и несёт точный размер после распаковки,
  поэтому получатель сверяет его с пределом пакета до распаковки. Клиентский мод сжатых тел не видит:
  их распаковывает помощник.
- **Лимиты.** Кадр — до 4 КБ до `Welcome` и до 1 МБ после; UDP-датаграмма — до 10 КБ.
  Конфигурация машины — до 768 КБ, чтобы её повтор при входе помещался в кадр. Эталонный манифест
  передаётся частями по `IntegrityChunkBytes` = 32 КиБ.

## Кадр

Каждый пакет назван двумя байтами: **категорией** и **подтипом** внутри неё. TCP-кадр — это
`[u32 length][category][subtype][flags][body]`, UDP-датаграмма — то же без длины. Существует восемь
категорий:

| Категория | Байт | Что в ней |
|---|---|---|
| `Handshake` | `0x01` | Установка соединения, проверка связи, привязка UDP. |
| `Session` | `0x02` | Приход и уход игроков, сообщения для всей сессии. |
| `Content` | `0x03` | Список модов, загрузка файлов, клиентские скрипты ресурсов. |
| `Vehicle` | `0x04` | Машины: спавн, места, авторитет. |
| `State` | `0x05` | Частое состояние машин. |
| `Event` | `0x06` | Именованные события: API плагинов и клиентских скриптов. |
| `Command` | `0x07` | Канал команд между игрой и помощником. |
| `Module` | `0x08` | Двоичные данные между нативными модулями и клиентами. |

Подтип `0` недопустим во всех категориях, так что обнулённый буфер никогда не означает пакет. Числа
— little-endian, строки — UTF-8 без нулевого байта, и без префикса длины может быть только одно поле
переменной длины — последнее, оно занимает остаток кадра.

В таблицах **L** — помощник, **S** — сервер, **G** — клиентский мод в игре; **T** — TCP-канал
сервера, **U** — его UDP-канал, **R** — порт ретрансляции, **CC** — порт команд.

## Пакеты по категориям

### Handshake (18)

| Подтип | Направление | Назначение |
|---|---|---|
| `Hello` | L→S, T | Версия протокола, биты возможностей помощника и имя, которое попросил игрок. При несовпадении версий — отказ с обеими версиями. |
| `Welcome` | S→L, T | Id игрока, токен для восстановления сессии, окно восстановления и биты возможностей сервера. |
| `Ping` | L→S, T и U | Проверка связи и времени отклика; необязательная метка возвращается в `Pong`. |
| `Pong` | S→L, T и U | Ответ на `Ping`. |
| `UdpToken` | S→L, T | 64-байтный ключ сессии для подписи UDP. |
| `UdpHello` | L→S, U | Привязывает UDP-адрес клиента нонсом и HMAC. Верный пакет привязывает с любого адреса — это нужно при раздельном туннелировании VPN. |
| `MapInfo` | S→L, T | Карта, которую должна загрузить игра. |
| `JoinWorld` | L→S, T | Карта загружена, присылай мир. |
| `VerifyRequest` | S→L, T | Насколько строго проверять установку игры (`[integrity] verify`), а для strict — id эталонного манифеста. Во время сессии его отправляет `player:verify`. |
| `VerifyReport` | L→S, T | Что лаунчер проверил и что нашёл: уровень, итог, число проблем и строка подробностей. |
| `Identity` | L→S, T | Билет на вход, всегда сразу после `Hello`; пустой — билета нет. |
| `IntegrityManifestRequest` | L→S, T | В кэше лаунчера нет эталонного манифеста с этим id, и он его просит. |
| `IntegrityManifestChunk` | S→L, T | Очередная часть сжатого манифеста. |
| `IntegrityManifestDone` | S→L, T | Все части отправлены; хеш, который лаунчер сверяет, прежде чем сохранить файл. |
| `Resume` | L→S, T | Идёт после `Hello` вместо `Identity`, чтобы вернуть оборванную сессию в пределах окна. |
| `UdpHelloAck` | S→L, U | Подтверждает принятый `UdpHello` на привязанный адрес. |
| `Queued` | S→L, T | Сервер заполнен, и вход ждёт в его очереди: место, сколько ждут и пояснение хоста, пока очередь на паузе. Вместо `Welcome`, затем снова при каждой перемене. |
| `QueueAdmit` | S→L, T | Для этого входа освободилось место; за ним идёт `Welcome`. |

## Порядок входа

1. Помощник открывает TLS и отправляет `Hello`, затем `Identity` с билетом на вход (или `Resume`,
   чтобы вернуть оборванную сессию).
2. Сервер проверяет баны, свободные места и билет, выдаёт игроку id и спрашивает плагины:
   `playerConnectRequest`, затем `playerAuthenticated`. Отказ — это `Kick` с причиной.
3. `Welcome` и `VerifyRequest`. Если строгому серверу нужен эталонный манифест, помощник скачивает
   его, проверяет игру и отправляет `VerifyReport`. Проваленная проверка — `Kick` до любых загрузок.
4. Моды: `ModsRequest`, `ModsInfo`, затем `FileRequest` и `FileBegin` или `FileDeny` для каждого
   недостающего файла, пока не придёт `SyncDone`.

Заполненный сервер может не отказать игроку с аккаунтом, а поставить его в
[очередь на вход](/ru/hosting/join-queue/): он отвечает `Queued` там, где был бы `Welcome`, и шаги
3 и 4 проходят, пока игрок ждёт, — до `ModsReady` вместо `SyncDone`. Пока помощник ждёт, он
пингует сервер каждые 30 секунд. Когда освобождается место, приходят `QueueAdmit` и `Welcome`,
помощник кладёт моды в игру, отправляет `SyncDone`, и вход продолжается с шага 5.
5. `UdpToken` и `MapInfo`, сразу за ними — клиентские скрипты ресурсов (`ResourceChunk` …
   `ResourceDone`). Сервер вызывает `playerJoining`, игра загружает карту.
6. Помощник привязывает UDP через `UdpHello` и отправляет `JoinWorld`.
7. Сервер отвечает `SelfInfo` вошедшему и `PlayerJoined` остальным, повторяет все машины с их
   состоянием и вызывает `playerJoined`.

## Версии

Версия протокола растёт с каждым изменением на проводе и передаётся в `Hello` и `Command::Version`.
Версии должны совпадать точно: лаунчер с другой версией получает отказ, в котором названы обе.
Добавления, которые старые участники могут спокойно пропустить, вроде битов возможностей в конце
`Welcome` и битов помощника в `Hello`, обходятся без новой версии. Помощник говорит в `Hello`, что
умеет ждать в очереди; тот, что не говорит, получает "Server full!", как раньше.
