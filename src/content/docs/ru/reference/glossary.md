title: Глоссарий
description: Термины NodeMP простым языком, с английским термином и страницей-объяснением — лаунчер, хелпер, клиентский мод, контент, директория, strict.
---

По одной строке на термин, английский термин в скобках (там, где он пишется иначе) и страница,
которая его объясняет. Каждая страница использует эти слова ровно в этом смысле; там, где сама
программа печатает другое слово (строка лога говорит `server browser`, всплывающее сообщение
называет хелпер «launcher»), запись об этом говорит, а страницы цитируют программу как есть. О том,
как части работают вместе, сначала прочитайте [Что такое NodeMP](/ru/introduction/what-is-nodemp/);
вопросы, которые читатели задают чаще всего, собраны в [FAQ](/ru/reference/faq/).

## Игрокам

| Термин | Определение | Где объясняется |
|---|---|---|
| **Лаунчер** (launcher) | `nodemp-launcher.exe`, приложение для Windows, которое вы устанавливаете: оно выполняет вход (или пускает играть как Test Drive), показывает список серверов, поддерживает клиентский мод актуальным и начинает подключение кнопкой **Hold to play**. Версия 1.1.12. Сам себя он не обновляет: текущую версию показывает [страница загрузки](https://nodemp.com/download). | [Установка лаунчера](/ru/players/install/) |
| **Хелпер** (helper) | Часть лаунчера, которая выполняет само подключение: запускает BeamNG.drive, соединяется с сервером и переносит ваш трафик, пока вы играете. Это тот же `nodemp-launcher.exe`, запущенный второй раз с `--helper` и без окна. Всплывающие сообщения лаунчера называют его «launcher» (`The launcher stopped · …`, `Could not start the launcher · …`): имеется в виду этот процесс, а не окно перед вами; его лог — `launcher.log`. Технически он держит TLS 1.3-сессию с сервером, скачивает контент и общается с клиентским модом по локальным TCP-портам `4444` (команды) и `4445` (игровой трафик). Отдельно собранный `Node-Launcher.exe` существует только в сборках разработчика. | [Устранение неполадок](/ru/players/troubleshooting/) |
| **Клиентский мод** (client mod) | `NodeMP.zip`, мод BeamNG, который делает всю мультиплеерную работу внутри игры (id BeamNG `multiplayernodemp`, в `mods/multiplayer/` пользовательской папки). Лаунчер устанавливает и обновляет его; руками вы его не копируете. Версия 1.6.1, собрана для BeamNG.drive 0.39.4.0. «Мультиплеерный мод» и «мод BeamNG» на сайте — этот же файл. | [Установка лаунчера](/ru/players/install/) |
| **Ваши моды** (your mods) | Моды BeamNG, которые вы установили сами, в `mods\` пользовательской папки. Это не клиентский мод и не контент сервера. Во время сессии они выключены, если вы не включили *Use my local mods in multiplayer* и сервер это не разрешил; строгая сессия держит их выключенными. Ни один уровень проверки не заглядывает в `mods\`. | [Подключение к серверу](/ru/players/join/#что-сервер-проверяет-на-вашем-пк) |
| **Контент** (content) | Zip-архивы модов, которые сервер держит в папке `content/` и отправляет подключающимся игрокам; хелпер скачивает их в `mods/multiplayer/` до входа игры в мир. Лаунчер называет их общий размер *Required mods* (фильтр) и *Content* (панель), а экран загрузки называет каждый файл `Resource` (`Downloading Resource 2/5`) — всё это одни и те же файлы. `Stock content` и `Stock only` означают, что сервер ничего лишнего не отправляет; о вашей установке они ничего не говорят. | [Подключение к серверу](/ru/players/join/#список-серверов) |
| **Директория** (directory) | Не папка: сервис NodeMP по адресу `https://api.nodemp.com`. Он хранит аккаунты и выполняет вход, выдаёт билеты на подключение, строит список серверов из маяков серверов, выдаёт хостам ключи серверов и публикует релизы лаунчера и клиентского мода. | [Обзор фреймворка](/ru/framework/overview/) |
| **Список серверов** (server list) | Список онлайн-серверов из директории в лаунчере (**Servers**) и, только для чтения, на [nodemp.com/servers](https://nodemp.com/servers), построенный из маяков, которые серверы шлют директории. Строка лога сервера `listed in the server browser` означает этот список. | [Подключение к серверу](/ru/players/join/#список-серверов) |
| **Аккаунт** (account) | Аккаунт NodeMP, созданный на [nodemp.com](https://nodemp.com) или в лаунчере. Даёт постоянное имя, которое серверы проверяют через директорию. Для игры необязателен; хосту он нужен (с подтверждённой почтой и привязанным аккаунтом Discord), чтобы создать ключ сервера. | [Установка лаунчера](/ru/players/install/#аккаунты) |
| **Test Drive** | Игра без аккаунта: директория выдаёт новое имя `Guest…` на каждое подключение, и выбрать его нельзя. Разрешено ли это, решает одна настройка сервера, и видна она под несколькими подписями: *Test Drive allowed* / *Account required* в панели сервера, фильтр *No account needed*, `Guest · a new name each session, and servers may refuse it` в Settings → Account и `[Directory] TestDrive` в `server.toml` хоста. В отличие от входа, Test Drive не запоминается: окно входа открывается при каждом запуске лаунчера, и вы снова нажимаете **Continue as Test Drive**. | [Установка лаунчера](/ru/players/install/#аккаунты) |
| **Гость** (guest) | Игрок в режиме Test Drive, каким его видят серверы и директория: имя `Guest…`, `player.guest` в плагине. Страницы говорят «Test Drive» о режиме и «гость» о человеке. | [Установка лаунчера](/ru/players/install/#аккаунты) |
| **Билет на подключение** (join ticket) | Одноразовый токен, который лаунчер запрашивает у директории для одного сервера и отправляет сразу после рукопожатия. Сервер погашает его в директории и берёт из ответа проверенное имя. Сервер без ключа сервера билеты не проверяет и берёт имена такими, какими их присылает лаунчер. | [Обзор фреймворка](/ru/framework/overview/) |
| **Hold to play** | Кнопка подключения: нажмите и держите около секунды. Отдельной кнопки *Play* нет. | [Подключение к серверу](/ru/players/join/#подключение) |
| **Direct Connect** | Форма лаунчера, подключающая к серверу по `host:port` (или `[addr]:port` для IPv6) вместо выбора из списка — для приватного сервера или сервера без ключа. Первое подключение запоминает сертификат сервера (его отпечаток), и следующие подключения отказывают серверу, чей сертификат изменился. | [Подключение к серверу](/ru/players/join/#direct-connect) |
| **Уровень проверки** (verification level) | Сколько вашей установки BeamNG сервер проверяет перед тем, как впустить: `[General] VerifyGame` равен `off`, `size` (по умолчанию), `scripts`, `full` или `strict`. Каждый уровень сравнивает файлы игры со списком; только `strict` смотрит ещё и в вашу пользовательскую папку. | [Подключение к серверу](/ru/players/join/#что-сервер-проверяет-на-вашем-пк) |
| **Строгий сервер** (strict server) | Сервер с `VerifyGame = "strict"`: он сравнивает всю папку игры, оглавление каждого игрового архива и вашу пользовательскую папку BeamNG с эталонным манифестом чистой установки перед каждым подключением и снова во время сессии. «Strict» во всплывающем сообщении означает это. Значение настройки пишется как `strict`, прилагательное — «строгий». | [Строгие серверы](/ru/players/troubleshooting/#строгие-серверы) |
| **Эталонный манифест** (reference manifest) | Файл, описывающий чистую установку BeamNG одной версии игры: размер каждого файла и, для кода и бинарников, его SHA-256, плюс оглавление каждого архива. Хост создаёт его командой `Node-Server --gen-integrity`; строгий сервер отправляет его вашему лаунчеру, который кэширует его и сравнивает с ним вашу установку. Сообщения называют его «this server's reference», шаг подключения — `Downloading the server's integrity manifest`. В вашу игру ничего не записывается. | [Строгая проверка](/ru/hosting/strict-verification/) |
| **Строгая сессия** (strict session) | Не то же самое, что строгий сервер: набор внутриигровых правил, которые серверный ресурс включает для игрока через `session:config.strict` — нет свободной камеры, нельзя пересесть в чужие машины, локальные моды выключены и так далее. Строгий сервер обычно ведёт и строгие сессии, но это два отдельных механизма. | [Клиентские скрипты](/ru/plugins/client-scripting/#строгие-сессии-sessionconfigstrict) |
| **Отпечаток (TLS)** (fingerprint) | SHA-256 самоподписанного TLS-сертификата сервера, пишется в лог при каждом запуске сервера. Серверы из списка передают его лаунчерам через директорию; Direct Connect закрепляет его при первом соединении в `known_servers.json`. `[Directory] Fingerprint` в `server.toml` закрепляет сертификат *директории*, а не сервера. | [Регистрация сервера](/ru/hosting/registering/) |

## Хостам

| Термин | Определение | Где объясняется |
|---|---|---|
| **Хост** (host) | Человек, который держит `Node-Server`. Сообщения и отказы говорят «ask the host»; эти страницы говорят «хост», никогда «хостер». | [Быстрый старт](/ru/hosting/quick-start/) |
| **Ключ сервера** (server key) | **Host ID** и **Host secret**, созданные на [nodemp.com/hosts](https://nodemp.com/hosts) и заданные как `[Directory] HostId` и `HostSecret` в уже существующей таблице `[Directory]` файла `server.toml`. Вместе с `Url` они позволяют серверу открыть сессию хоста в директории, слать маяки и погашать билеты на подключение. Чтобы создать ключ, нужен аккаунт с подтверждённой почтой и привязанным аккаунтом Discord. | [Регистрация сервера](/ru/hosting/registering/) |
| **Маяк** (beacon) | Отчёт, который зарегистрированный сервер отправляет директории по умолчанию каждые 15 с: имя, карта, игроки, вместимость, имена и размер контента, флаги `Public` и `TestDrive`, версия. Список серверов строится из маяков; когда они прекращаются, запись пропадает. | [Регистрация сервера](/ru/hosting/registering/) |
| **Рабочий каталог** (working directory) | Папка, из которой запущен сервер: там лежат `server.toml`, `resources/`, `content/`, `storage/`, `bans.json` и `logs/`. Папка самого исполняемого файла содержит `tools/`, `modules/` и файлы TLS. | [Запуск сервера](/ru/hosting/running/) |
| **Список банов** (ban book) | `bans.json` в рабочем каталоге: один JSON-объект, ключи которого — заблокированный IP-адрес или `nodemp:<id аккаунта>`. Читается один раз при первой проверке бана после запуска, записывается при каждом новом бане; бан снимают при остановленном сервере — `Node-Server --bans list` / `--bans remove` или правкой файла. | [Запуск сервера](/ru/hosting/running/#баны) |

## Авторам плагинов

| Термин | Определение | Где объясняется |
|---|---|---|
| **Плагин** (plugin) | Общее слово для всего, чем хост дополняет поведение сервера: ресурс или нативный модуль. Собственные строки лога сервера используют его для всей подсистемы (`plugin worker job stalled …`, `plugin job queue full`); ключ метрик — `plugin`. | [Обзор разработки плагинов](/ru/plugins/overview/) |
| **Ресурс** (resource) | Папка в `resources/` рабочего каталога сервера: необязательный `resource.toml`, серверная часть (`server/main.lua` или JavaScript с модулем `js-host`) на API `node` и необязательная клиентская часть в `client/`, передаваемая каждому игроку при подключении. Чат, права, игровые режимы и админ-команды — это ресурсы. | [Ресурсы](/ru/plugins/resources/) |
| **Нативный модуль** (native module) | Разделяемая библиотека (`.dll` или `.so`) в `modules/` рядом с исполняемым файлом сервера. Экспортирует `node_plugin_abi`, `node_plugin_init` и `node_plugin_shutdown` и обращается к серверу через таблицу `NodeApi`, объявленную в `node.h`. | [Нативные модули](/ru/plugins/native-modules/) |
| **Языковой хост** (language host) | Нативный модуль, который регистрирует `type` ресурса и выполняет ресурсы этого типа. `js-host` регистрирует `type = "js"`; без него такие ресурсы пропускаются. | [Нативные модули](/ru/plugins/native-modules/) |
| **Модуль (четыре смысла)** (module) | Слово встречается в четырёх местах и означает четыре вещи: **нативный модуль** (выше); **канал модулей** — нумерованный двоичный канал между клиентом и сервером (`node.modules.on`, `node.sendModule`, кадры `Module`); **фреймворк модулей** клиентского мода (`NodeMP.modules`) — необязательные возможности внутри клиентского мода; и модули-**языковые хосты** вроде `js-host`. Страницы говорят, какой из них имеется в виду. | [События](/ru/plugins/events/#модульный-канал) |
| **Сетевое событие** (wire event) | Именованный кадр `Event` между клиентским скриптом и сервером: `node.emitServer(name, data)` вверх, `player:send` и `node.broadcast` вниз. Имена — `<domain>:<verb>` в нижнем регистре (`chat:send`); имена в camelCase — серверные хуки, которые никогда не идут по сети. Справочник API называет этот вид `client`. | [События](/ru/plugins/events/) |
| **Виды событий** (event kinds) | Руководства говорят *событие движка*, *уведомление о машине*, *отменяемый запрос*, *сетевое событие*, *сообщение шины*, *канал модулей*; [справочник API](/ru/plugins/api/events/) и `api.toml` говорят `builtin`, `notify`, `cancellable`, `client`, `bus`, `module` и `special` для фильтра ретрансляции `relayRequest`. Строки ошибок используют свои слова: `error in event '…'` для обработчика события движка или сетевого события, `error in resource event '…'` для обработчика шины, `error in timer callback`, `error in async task`. | [События](/ru/plugins/events/) |
| **Шина** (bus) | Канал между ресурсами одного сервера: `node.bus.emit(name, data)` и `node.bus.on(name, fn)`. Через неё говорят помощники чата: `player:tell` и `node.chat.say` публикуют `chat:say`, `node.commands.add` слушает `chat:command`, а ресурс `chat` отвечает на оба. | [События](/ru/plugins/events/#между-ресурсами-nodebus) |
| **Ретрансляция** (relay) | Пересылка трафика одного игрока остальным. Состояние машин ядро ретранслирует само; клиентские события заканчиваются на сервере и доходят до других игроков только через ресурс, который их пересылает (собственные огонь, захват, триггеры и политика машин клиентского мода — типизированные пакеты, которые ядро ретранслирует само). Фильтр ретрансляции (`node.relay.filter` или хук `relayRequest` в Lua, `register_relay_filter` в C) может запретить любой ретранслируемый пакет для конкретного получателя. | [Обзор фреймворка](/ru/framework/overview/) |
| **Категория / подтип** (category / subtype) | Два байта, определяющие каждый пакет сетевого протокола v23: одна из восьми категорий (`Handshake`, `Session`, `Content`, `Vehicle`, `State`, `Event`, `Command`, `Module`) и подтип внутри неё. Каждая таблица на странице протокола построена по этой паре. | [Сетевой протокол](/ru/plugins/protocol/) |
| **Уровень обфускации** (obfuscation level) | Насколько клиентский Lua ресурса преобразуется перед доставкой: `none`, `light` (по умолчанию), `medium` или `strong`, задаётся для каждого ресурса ключом `[client] obfuscation`. `[Resources] Obfuscate = false` выключает её для всего сервера. Prometheus, обфускатор, — это Lua-программа в `tools/`; с системой мониторинга с тем же названием она не связана. | [Ресурсы и контент](/ru/hosting/resources/) |
| **Примеры** (examples) | Примеры ресурсов, которые называют руководства: `chat`, `demo-numbers`, `vehicle-cleanup`, `gatekeeper-example`, `nodegrab-allow`, `devapi-example`, `session-report`. Они входят в архив релиза в папке `examples/` с файлом `examples/README.txt`, который говорит, что делает каждый; `examples/chat` — тот, на который опираются помощники чата любого другого ресурса. | [Ресурсы и контент](/ru/hosting/resources/#установка-ресурса) |
| **Авторитет / водитель / спавнер** (authority / driver / spawner) | Три роли у каждой машины. **Спавнер** создал её и может удалить. **Водитель** сидит в ней и отправляет органы управления. **Авторитет синхронизации** — клиент, чья симуляция считается верной и кто передаёт состояние машины (режим управления `S` для пустой или чужой машины); водителя и авторитет назначает сервер и помечает обоих эпохой места. | [Как работает синхронизация](/ru/framework/sync/) |
