title: Глоссарий
description: Термины NodeMP в одной таблице с английским термином и страницей, которая их объясняет - директория, ключ сервера, билет, ресурс, контент, хелпер.
---

По одной строке на термин, английский термин в скобках и страница, которая его объясняет. О том,
как части работают вместе, сначала прочитайте [Что такое NodeMP](/ru/introduction/what-is-nodemp/).

| Термин | Определение | Где объясняется |
|---|---|---|
| **Директория** (directory) | Сервис по адресу `https://api.nodemp.com`: аккаунты и вход, билеты на подключение, список серверов, ключи серверов для хостов, релизы лаунчера и клиентского мода. | [Обзор фреймворка](/ru/framework/overview/) |
| **Ключ сервера** (server key) | **Host ID** и **Host secret**, созданные на `https://nodemp.com` и заданные как `[Directory] HostId` и `HostSecret`. Вместе с `Url` они позволяют серверу открыть сессию хоста в директории, слать маяки и погашать билеты на подключение. | [Регистрация сервера](/ru/hosting/registering/) |
| **Билет на подключение** (join ticket) | Одноразовый токен, который лаунчер запрашивает у директории (`/v1/play/ticket`) для одного сервера и отправляет в кадре `Identity` сразу после `Hello`. Сервер погашает его в директории и берёт из ответа проверенное имя. | [Обзор фреймворка](/ru/framework/overview/) |
| **Test Drive** (Test Drive) | Сессия без аккаунта: директория выдаёт новое имя `Guest…` на каждое подключение. Сервер с `[Directory] TestDrive = false` отказывает игрокам Test Drive и подключениям без билета. | [Установка лаунчера](/ru/players/install/) |
| **Ресурс** (resource) | Папка в `resources/` рабочего каталога сервера: необязательный `resource.toml`, серверная часть (`server/main.lua` или JavaScript с модулем `js-host`) на API `node` и необязательный клиентский Lua в `client/`, передаваемый каждому игроку при подключении. | [Ресурсы](/ru/plugins/resources/) |
| **Контент** (content) | Zip-архивы модов BeamNG в `content/` (`[Content] Folder`). Сервер объявляет их при подключении; хелпер скачивает недостающее в `mods/multiplayer/` до того, как игра входит в мир. | [Ресурсы и контент](/ru/hosting/resources/) |
| **Клиентский мод** (client mod) | `NodeMP.zip` (id BeamNG `multiplayernodemp`) в `mods/multiplayer/` пользовательской папки BeamNG. Лаунчер устанавливает его из релиза директории и проверяет хеш перед каждым подключением. Версия 1.4.0. | [Установка лаунчера](/ru/players/install/) |
| **Лаунчер** (launcher) | `nodemp-launcher.exe`, настольное приложение для Windows: вход или Test Drive, список серверов, проверка клиентского мода и запуск хелпера для подключения. Версия 1.1.0. | [Установка лаунчера](/ru/players/install/) |
| **Хелпер** (helper) | Процесс на C++, переносящий трафик; встроен в лаунчер и запускается как `nodemp-launcher.exe --helper`. Он находит и запускает BeamNG.drive, держит TLS 1.3-сессию с сервером, скачивает контент и общается с клиентским модом по локальным TCP-портам `4444` (команды) и `4445` (игровой трафик). Отдельный `Node-Launcher.exe` существует только в сборках разработчика. | [Что такое NodeMP](/ru/introduction/what-is-nodemp/) |
| **Ретрансляция** (relay) | Пересылка трафика одного игрока остальным. Состояние машин ядро ретранслирует само; клиентские события заканчиваются на сервере и доходят до других игроков только через ресурс, например `nodemp-relay`. Фильтр ретрансляции (`node.relay.filter` или хук `relayRequest` в Lua, `register_relay_filter` в C) может запретить любой ретранслируемый пакет для конкретного получателя. | [Обзор фреймворка](/ru/framework/overview/) |
| **Сетевое событие** (wire event) | Именованный кадр `Event` между клиентским скриптом и сервером: `node.emitServer(name, data)` вверх, `player:send` и `node.broadcast` вниз. Имена - `<domain>:<verb>` в нижнем регистре (`chat:send`); имена в camelCase - серверные хуки, которые никогда не идут по сети. | [События](/ru/plugins/events/) |
| **Категория / подтип** (category / subtype) | Два байта, определяющие каждый пакет сетевого протокола v18: одна из восьми категорий (`Handshake`, `Session`, `Content`, `Vehicle`, `State`, `Event`, `Command`, `Module`) и подтип внутри неё. Каждая таблица на странице протокола построена по этой паре. | [Сетевой протокол](/ru/plugins/protocol/) |
| **Уровень обфускации** (obfuscation level) | Насколько клиентский Lua ресурса преобразуется перед доставкой: `none`, `light` (по умолчанию), `medium` или `strong`, задаётся для каждого ресурса ключом `[client] obfuscation`. `[Resources] Obfuscate = false` выключает её для всего сервера. | [Ресурсы и контент](/ru/hosting/resources/) |
| **Нативный модуль** (native module) | Разделяемая библиотека (`.dll` или `.so`) в `modules/` рядом с исполняемым файлом сервера. Экспортирует `node_plugin_abi`, `node_plugin_init` и `node_plugin_shutdown` и обращается к серверу через таблицу `NodeApi`, объявленную в `node.h`. | [Нативные модули](/ru/plugins/native-modules/) |
| **Языковой хост** (language host) | Нативный модуль, который регистрирует `type` ресурса и выполняет ресурсы этого типа. `js-host` регистрирует `type = "js"`; без него такие ресурсы пропускаются. | [Нативные модули](/ru/plugins/native-modules/) |
| **Маяк** (beacon) | Отчёт, который зарегистрированный сервер отправляет директории по умолчанию каждые 15 с: имя, карта, игроки, вместимость, имена и размер контента, флаги `Public` и `TestDrive`, версия. Список серверов строится из маяков; когда они прекращаются, запись пропадает. | [Регистрация сервера](/ru/hosting/registering/) |
| **Отпечаток (TLS)** (fingerprint) | SHA-256 самоподписанного TLS-сертификата сервера, пишется в лог при каждом запуске. Серверы из списка передают его лаунчерам через директорию; Direct Connect закрепляет его при первом соединении в `known_servers.json`. `[Directory] Fingerprint` закрепляет сертификат директории, а не сервера. | [Регистрация сервера](/ru/hosting/registering/) |
| **Direct Connect** (Direct Connect) | Форма лаунчера, подключающая к серверу по `host:port` (или `[addr]:port` для IPv6) без выбора из списка. Работает и для серверов вне списка, и для серверов с `Public = false`. | [Подключение к серверу](/ru/players/join/) |
| **Авторитет / водитель / спавнер** (authority / driver / spawner) | Три роли у каждой машины. **Спавнер** создал её и может удалить. **Водитель** сидит в ней и отправляет органы управления. **Авторитет синхронизации** - клиент, чья симуляция считается верной и кто передаёт состояние машины (режим управления `S` для пустой или чужой машины); водителя и авторитет назначает сервер и помечает обоих эпохой места. | [Как работает синхронизация](/ru/framework/sync/) |

*Плагин* - не отдельный тип: это общее слово для ресурсов и нативных модулей.
