`Node-Server` is the game server. Players join it from the launcher, from the server list or by
address. This page is the first page for a host: it takes one machine from nothing to a running,
listed server. The pages after it cover [every setting](/hosting/configuration/),
[running it as a service](/hosting/running/) and [the server key](/hosting/registering/) in
depth; the words used here are defined in the [glossary](/reference/glossary/#for-hosts).

Three of them come up before their own pages do. The **directory** is the NodeMP service at
`https://api.nodemp.com` that keeps the server list players see in the launcher. A **server key**
(a Host ID and a Host secret from your NodeMP account) is what lets your server announce itself to
the directory and get listed. **Direct Connect** is the launcher's form for joining a server by
`address:port` without the list.

## What you need

- A machine reachable from the internet on port **30814**, TCP and UDP. Behind a home router,
  forward both to the machine. That port is the only inbound requirement; the server talks to
  the directory over outgoing HTTPS.
- Linux x64 or Windows x64. The Linux build is made on Ubuntu 24.04 and needs a glibc at least
  that new; on an older distribution use the Docker image.
- To get the server into the launcher's list: a NodeMP account at [nodemp.com](https://nodemp.com)
  with a **verified e-mail address** (sign-in requires it) and a **linked Discord account** (a
  server key can only be created by an account with one - the link is used for nothing else).
  Without a server key the server still runs, and anyone you give the address to can join it
  through Direct Connect; it is just not listed, and players' names are not verified.
- For `VerifyGame = "strict"` only: a Windows PC with a clean BeamNG.drive install, to generate
  the reference manifest ([Strict verification](/hosting/strict-verification/)). Every other
  level needs nothing beyond the server.

## Install and start

<Tabs>
<TabItem label="Binary">

The release archives are attached to tag `server-v1.4.1` at
[github.com/NodeMP-BeamNG/releases](https://github.com/NodeMP-BeamNG/releases):
`Node-Server-1.4.1-linux-x64.tar.gz` and `Node-Server-1.4.1-windows-x64.zip`, each with a
`.sha256` file. Both contain the executable and the `tools/` folder. `tools/` holds **Prometheus**,
a Lua program that obfuscates the *client scripts* - the Lua files a plugin streams to players'
games - before they leave the server; it has nothing to do with the monitoring system of the same
name, needs no configuration, and ships as its full source tree (`tools\prometheus\` with `web/`,
`tests/` and a `Dockerfile` inside is expected). The Windows archive also bundles the Lua 5.1
runner Prometheus needs (`tools\lua515\lua5.1.exe`); the Linux archive does not, so install the
distribution's `lua5.1` package and point `NODE_LUA` at it. Without a runner the server starts
anyway and delivers client scripts as plain source. Both archives also carry the example
resources under `examples/` (with a `README.txt` that says what each one does, their `LICENSE`,
and `EXAMPLES_COMMIT` next to the executable naming the commit they came from), and the Windows
zip adds `cacert.pem` - Mozilla's bundle of public root certificates, with its `cacert.LICENSE` -
next to `Node-Server.exe` (see [Get listed](#get-listed)).

**Linux**

```bash
sudo mkdir -p /opt/nodemp && sudo chown "$USER" /opt/nodemp
cd /opt/nodemp
curl -LO https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.4.1/Node-Server-1.4.1-linux-x64.tar.gz
curl -LO https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.4.1/Node-Server-1.4.1-linux-x64.tar.gz.sha256
sha256sum -c Node-Server-1.4.1-linux-x64.tar.gz.sha256
tar -xzf Node-Server-1.4.1-linux-x64.tar.gz
sudo apt install -y lua5.1
export NODE_LUA=/usr/bin/lua5.1
./Node-Server
```

**Windows** (PowerShell)

```powershell
New-Item -ItemType Directory -Force C:\NodeMP | Out-Null
Set-Location C:\NodeMP
Invoke-WebRequest https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.4.1/Node-Server-1.4.1-windows-x64.zip -OutFile Node-Server-1.4.1-windows-x64.zip
Invoke-WebRequest https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.4.1/Node-Server-1.4.1-windows-x64.zip.sha256 -OutFile Node-Server-1.4.1-windows-x64.zip.sha256
(Get-FileHash Node-Server-1.4.1-windows-x64.zip).Hash.ToLower() -eq (Get-Content Node-Server-1.4.1-windows-x64.zip.sha256).Split(' ')[0]
Expand-Archive Node-Server-1.4.1-windows-x64.zip -DestinationPath .
.\Node-Server.exe
```

The comparison line prints `True` when the download is intact.

The first start writes `server.toml` with every key at its default, generates the TLS
certificate `node_cert.pem` and its key `node_key.pem` next to the executable, creates `content/`
(with an empty hash cache `content/mods.json`), `logs/` and `.obfcache/`, and runs. Among the
lines the log shows - a banner with the version, name, port, map and player count comes first -
these six are the ones that matter:

```
No config file found! Generating one...
generated a new self-signed TLS certificate (node_cert.pem)
TLS 1.3 enabled — certificate fingerprint (SHA-256): …
client obfuscation ready · runner lua5.1 · Prometheus (cache .obfcache)
0 resources · 0 modules loaded
server is ready
```

(On Windows the runner line reads `runner lua5.1.exe`.) Two more lines are normal, not warnings:
`state relay interest management OFF (StateRelayRadius <= 0: every position relayed to everyone)`
describes the default of `[Network] StateRelayRadius`, and `listening on [::]:30814 (tcp, tls 1.3)`
with its `(udp)` twin says the server accepts IPv6 and IPv4 on that port.

Stop it with Ctrl+C and open the port. The Windows commands need a PowerShell opened **as
Administrator** - everything else on this page runs in a normal one:

```bash
sudo ufw allow 30814/tcp
sudo ufw allow 30814/udp
```

```powershell
New-NetFirewallRule -DisplayName "Node-Server TCP" -Direction Inbound -Protocol TCP -LocalPort 30814 -Action Allow
New-NetFirewallRule -DisplayName "Node-Server UDP" -Direction Inbound -Protocol UDP -LocalPort 30814 -Action Allow
```

Then edit `server.toml`. The keys most servers change:

```toml
[General]
Name = "My server"
Map = "/levels/west_coast_usa/info.json"
MaxPlayers = 16
MaxCars = 2
```

Settings are read at start, so start the server again. Every key is described in
[Configuration](/hosting/configuration/).

<TabItem label="Docker">

The image `ghcr.io/nodemp-beamng/server:v1.4.1` runs the same binary on Ubuntu 24.04 with
Lua 5.1 installed (`latest` follows the newest main-branch build, which may be ahead of the
latest release — pin a version tag). It has no `server.toml`: the image sets
`NODE_PROVIDER_DISABLE_CONFIG=true`, so every setting is an environment variable — `NODE_NAME`
for `[General] Name` and so on, listed in [Configuration](/hosting/configuration/). The process
runs as user id 10001 with `/data` as its working directory; `resources/`, `content/`,
`storage/`, `tls/`, `.obfcache/`, `logs/` and `bans.json` live there. The image is not yet
publicly pullable: until the package is made public, only accounts granted access by the
NodeMP-BeamNG organisation can `docker pull` it. Use the binary path meanwhile.

```bash
mkdir -p data && sudo chown 10001:10001 data
docker run -d --name nodemp-server --restart unless-stopped \
  -p 30814:30814/tcp -p 30814:30814/udp \
  -v "$PWD/data:/data" \
  -e NODE_NAME="My server" \
  -e NODE_MAP=/levels/west_coast_usa/info.json \
  -e NODE_MAX_PLAYERS=16 \
  -e NODE_MAX_CARS=2 \
  -e NODE_TLS_CERT=/data/tls/node_cert.pem \
  -e NODE_TLS_KEY=/data/tls/node_key.pem \
  ghcr.io/nodemp-beamng/server:v1.4.1
docker logs -f nodemp-server
```

Two lines matter more than they look. The data folder must belong to user 10001 before the
first start: the container creates its state folders in it and refuses to run when it cannot.
And `NODE_TLS_CERT` and `NODE_TLS_KEY` must point into `/data`: a relative path resolves next to
the executable, which is read-only inside the image, and the server then stops with
`TLS: failed to write /opt/node/node_key.pem`.

Open 30814 TCP and UDP in the host firewall, and forward them on a router, as for the binary.
To change a setting, remove the container (`docker rm -f nodemp-server`) and run it again with
the new variables; everything in `data/` stays. [Running the server](/hosting/running/) has the
same setup as a Compose file.

## Get listed

A server appears in the launcher's list once it announces itself to the directory at
`https://api.nodemp.com` with a **server key**. Create one at
[nodemp.com/hosts](https://nodemp.com/hosts) — it needs an account with a verified e-mail and a
linked Discord account; [Registering your server](/hosting/registering/) walks through it — and
give it to the server:

- binary: `server.toml` already has a `[Directory]` table (the first start wrote it, with every
  key empty). Set the values of its three keys `Url`, `HostId` and `HostSecret` to what the site
  shows. Do **not** paste a second `[Directory]` header under the existing one: TOML rejects a
  table defined twice and the server exits at the next start with
  `Error parsing config file value: server.toml, line …: the table [Directory] appears twice. Put the keys into the existing [Directory] table …`;
- Docker: add `-e NODE_DIRECTORY_URL=https://api.nodemp.com`, `-e NODE_DIRECTORY_HOST_ID=…` and
  `-e NODE_DIRECTORY_HOST_SECRET=…` to the `docker run` line.

Restart. The log first says `announcing this server to https://api.nodemp.com` and, once the
directory has accepted the key, `listed in the server browser` (the server's word for the server
list). If the second line never comes, the key is wrong or the directory cannot be reached; the
[troubleshooting table](/hosting/registering/#troubleshooting) on the registering page lists the
messages. On Windows the server verifies the directory's certificate against the Windows
certificate store and the `cacert.pem` from the archive, so nothing needs setting up; a host still
on 1.2.0 or 1.1.0 sees
`Could not reach the directory at https://api.nodemp.com: TLS handshake failed: certificate verify failed (SSL routines)`
instead, and the table says what to do until the update.

## Check from the launcher

Start the launcher, open **Servers** and find the server by name, or use **Direct Connect** with
`203.0.113.10:30814` (your public address). Direct Connect also works for a server without a
key. The first join takes longer while the launcher checks the player's game files
(`VerifyGame`) and downloads any content you put into `content/`. The default `size` check
compares file sizes with the game's own list; `scripts` and `full` hash more of it; `strict`
compares the whole install and the player's user folder with a reference manifest of a clean
game that you generate first, on a Windows PC with the game installed —
[Strict verification](/hosting/strict-verification/) has the steps.

## Add a resource

The server does nothing beyond driving together until a plugin says otherwise - chat included.
The archive's `examples/` folder holds the example resources the pages name (`chat`,
`demo-numbers`, `vehicle-cleanup`, …; `examples/README.txt` says what each one does): installing
one is a copy of its folder into `resources/` and a restart - `examples/chat` → `resources/chat`
first, since chat and the `/` commands live there
([Resources and content](/hosting/resources/#installing-a-resource)). The smallest resource to
write yourself is `hello` from [Getting started](/plugins/getting-started/).
