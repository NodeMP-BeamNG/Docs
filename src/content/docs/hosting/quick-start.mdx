import { Tabs, TabItem } from '@astrojs/starlight/components';

`Node-Server` is the dedicated game server that players connect to via the launcher. Follow these six steps to get your server running and publicly listed:

1. [Download and start](#1-download-and-start) the server.
2. [Open port 30814](#2-open-the-port), TCP and UDP.
3. [Set a name and a map](#3-name-map-and-slots).
4. [Get listed](#4-get-listed) with a server key.
5. [Join it](#5-join-it) from the launcher.
6. [Add chat and other resources](#6-add-chat-and-other-resources).

Core concepts:
- **Directory**: The master server service at `https://api.nodemp.com` that maintains the public server browser.
- **Server key**: Host ID and Host secret from your NodeMP account, used to authenticate your server to the directory.
- **Direct Connect**: Joining directly by `IP:port` without using the server browser.

More terms are in the [glossary](/reference/glossary/#for-hosts).

## What you need

- A host reachable on port **30814** (TCP and UDP). If running behind a home router, forward both protocols. The server connects to the directory via outbound HTTPS.
- Linux x64 or Windows x64. The Linux binary requires glibc 2.39+ (built on Ubuntu 24.04); use the Docker image on older distributions.
- To appear in the server browser: a NodeMP account at [nodemp.com](https://nodemp.com) with a **verified email** and **linked Discord**. Unlisted servers do not require an account or key; players can join via Direct Connect.
- Optional (for `VerifyGame = "strict"`): a Windows PC with a clean BeamNG.drive installation to generate a reference manifest ([Strict verification](/hosting/strict-verification/)).

## 1. Download and start

<Tabs>
<TabItem label="Binary">

The release archives are attached to tag `server-v1.5.0` at
[github.com/NodeMP-BeamNG/releases](https://github.com/NodeMP-BeamNG/releases):
`Node-Server-1.5.0-linux-x64.tar.gz` and `Node-Server-1.5.0-windows-x64.zip`, each with a
`.sha256` file.

**Linux**

```bash
sudo mkdir -p /opt/nodemp && sudo chown "$USER" /opt/nodemp
cd /opt/nodemp
curl -LO https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.5.0/Node-Server-1.5.0-linux-x64.tar.gz
curl -LO https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.5.0/Node-Server-1.5.0-linux-x64.tar.gz.sha256
sha256sum -c Node-Server-1.5.0-linux-x64.tar.gz.sha256
tar -xzf Node-Server-1.5.0-linux-x64.tar.gz
sudo apt install -y lua5.1
export NODE_LUA=/usr/bin/lua5.1
./Node-Server
```

**Windows** (PowerShell)

```powershell
New-Item -ItemType Directory -Force C:\NodeMP | Out-Null
Set-Location C:\NodeMP
Invoke-WebRequest https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.5.0/Node-Server-1.5.0-windows-x64.zip -OutFile Node-Server-1.5.0-windows-x64.zip
Invoke-WebRequest https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.5.0/Node-Server-1.5.0-windows-x64.zip.sha256 -OutFile Node-Server-1.5.0-windows-x64.zip.sha256
(Get-FileHash Node-Server-1.5.0-windows-x64.zip).Hash.ToLower() -eq (Get-Content Node-Server-1.5.0-windows-x64.zip.sha256).Split(' ')[0]
Expand-Archive Node-Server-1.5.0-windows-x64.zip -DestinationPath .
.\Node-Server.exe
```

The comparison line prints `True` when the download is intact.

<details>
<summary>What is in the archive</summary>

- The executable, `Node-Server` or `Node-Server.exe`.
- `tools/` — **Prometheus**, a Lua program that obfuscates the *client scripts* plugins stream to
  players before they leave the server. It has nothing to do with the monitoring system of the same
  name, needs no configuration and ships as its full source tree (`tools\prometheus\` with `web/`,
  `tests/` and a `Dockerfile` inside is expected). The Windows archive bundles the Lua 5.1 runner it
  needs (`tools\lua515\lua5.1.exe`); on Linux install the distribution's `lua5.1` and point
  `NODE_LUA` at it, as above. Without a runner the server starts anyway and sends client scripts as
  plain source.
- `examples/` — the example resources, with a `README.txt` that says what each one does, their
  `LICENSE`, and `EXAMPLES_COMMIT` next to the executable naming the commit they came from.
- Windows only: `cacert.pem` — Mozilla's bundle of public root certificates, with its
  `cacert.LICENSE`, used to verify the directory ([step 4](#4-get-listed)).

</details>

The first start writes `server.toml` with every key at its default, generates the TLS certificate
`node_cert.pem` and its key `node_key.pem` next to the executable, creates `content/` (with an empty
hash cache `content/mods.json`), `logs/` and `.obfcache/`, and runs. After a banner with the
version, name, port, map and player count, these are the lines that matter:

```
No config file found! Generating one...
generated a new self-signed TLS certificate (node_cert.pem)
TLS 1.3 enabled — certificate fingerprint (SHA-256): …
client obfuscation ready · runner lua5.1 · Prometheus (cache .obfcache)
0 resources · 0 modules loaded
server is ready
```

On Windows the runner line reads `runner lua5.1.exe`. Two more lines are normal, not warnings:
`state relay interest management OFF (StateRelayRadius <= 0: every position relayed to everyone)`
describes the default of `[Network] StateRelayRadius`, and `listening on [::]:30814 (tcp, tls 1.3)`
with its `(udp)` twin says the server accepts IPv6 and IPv4 on that port. Stop it with Ctrl+C.

</TabItem>
<TabItem label="Docker">

The image `ghcr.io/nodemp-beamng/server:v1.5.0` runs the same binary on Ubuntu 24.04 with Lua 5.1
installed (`latest` follows the newest main-branch build, which may be ahead of the latest release —
pin a version tag). It has no `server.toml`: the image sets `NODE_PROVIDER_DISABLE_CONFIG=true`, so
every setting is an environment variable — `NODE_NAME` for `[General] Name` and so on, listed in
[Configuration](/hosting/configuration/). The process runs as user id 10001 with `/data` as its
working directory; `resources/`, `content/`, `storage/`, `tls/`, `.obfcache/`, `logs/` and
`bans.json` live there.

:::caution[Not public yet]
Until the package is made public, only accounts granted access by the NodeMP-BeamNG organisation can
`docker pull` it. Use the binary meanwhile.
:::

```bash
mkdir -p data && sudo chown 10001:10001 data
docker run -d --name nodemp-server --restart unless-stopped \
  -p 30814:30814/tcp -p 30814:30814/udp \
  -v "$PWD/data:/data" \
  -e NODE_NAME="My server" \
  -e NODE_MAP=/levels/west_coast_usa/info.json \
  -e NODE_MAX_PLAYERS=16 \
  -e NODE_MAX_CARS=2 \
  -e NODE_TLS_CERT=/data/tls/node_cert.pem \
  -e NODE_TLS_KEY=/data/tls/node_key.pem \
  ghcr.io/nodemp-beamng/server:v1.5.0
docker logs -f nodemp-server
```

Two lines matter more than they look:

- The data folder must belong to user 10001 before the first start: the container creates its state
  folders in it and refuses to run when it cannot.
- `NODE_TLS_CERT` and `NODE_TLS_KEY` must point into `/data`: a relative path resolves next to the
  executable, which is read-only inside the image, and the server then stops with
  `TLS: failed to write /opt/node/node_key.pem`.

To change a setting, remove the container (`docker rm -f nodemp-server`) and run it again with the
new variables; everything in `data/` stays. [Running the server](/hosting/running/) has the same
setup as a Compose file.

</TabItem>

## 2. Open the port

Open 30814 TCP and UDP in the firewall, and forward both on your router if the machine is behind
one. On Windows the commands need a PowerShell opened **as Administrator**; everything else on this
page runs in a normal one.

```bash
sudo ufw allow 30814/tcp
sudo ufw allow 30814/udp
```

```powershell
New-NetFirewallRule -DisplayName "Node-Server TCP" -Direction Inbound -Protocol TCP -LocalPort 30814 -Action Allow
New-NetFirewallRule -DisplayName "Node-Server UDP" -Direction Inbound -Protocol UDP -LocalPort 30814 -Action Allow
```

## 3. Name, map and slots

Edit `server.toml` (Docker: the `-e` variables above). The keys most servers change:

```toml
[General]
Name = "My server"
Map = "/levels/west_coast_usa/info.json"
MaxPlayers = 16
MaxCars = 2
```

Settings are read at start, so start the server again. Every key is in
[Configuration](/hosting/configuration/).

## 4. Get listed

A server appears in the launcher's list once it announces itself to the directory with a **server
key**. Create one at [nodemp.com/account/servers](https://nodemp.com/account/servers) —
[Registering your server](/hosting/registering/) walks through it — and give it to the server:

- **Binary:** `server.toml` already has a `[Directory]` table (the first start wrote it, every key
  empty). Set its three keys `Url`, `HostId` and `HostSecret` to what the site shows.
- **Docker:** add `-e NODE_DIRECTORY_URL=https://api.nodemp.com`, `-e NODE_DIRECTORY_HOST_ID=…` and
  `-e NODE_DIRECTORY_HOST_SECRET=…` to the `docker run` line.

:::caution[Do not paste a second [Directory] block]
TOML rejects a table defined twice, and the server exits at the next start with
`Error parsing config file value: server.toml, line …: the table [Directory] appears twice. Put the keys into the existing [Directory] table …`.
Fill in the existing table instead.
:::

Restart. The log says `announcing this server to https://api.nodemp.com` and, once the directory
has accepted the key, `listed in the server browser`. If the second line never comes, the key is
wrong or the directory cannot be reached; the
[troubleshooting table](/hosting/registering/#troubleshooting) lists the messages. On Windows the
server verifies the directory's certificate against the Windows certificate store and the
`cacert.pem` from the archive, so nothing needs setting up; a host still on 1.2.0 or 1.1.0 sees
`Could not reach the directory at https://api.nodemp.com: TLS handshake failed: certificate verify failed (SSL routines)`
instead, and the table says what to do until the update.

## 5. Join it

Start the launcher, open **Servers** and find the server by name — or use **Direct Connect** with
your public address, `203.0.113.10:30814`. Direct Connect also works for a server without a key.

The first join takes longer while the launcher checks the player's game files (`VerifyGame`) and
downloads any content you put into `content/`. The default `size` check compares file sizes with the
game's own list; `scripts` and `full` hash more of it; `strict` compares the whole install and the
player's user folder with a reference of a clean game that you generate first —
[Strict verification](/hosting/strict-verification/) has the steps.

## 6. Add chat and other resources
 
By default, Node-Server only handles transport and vehicle state relaying. Chat and `/` commands are implemented via plugin resources. The release archive includes sample resources under `examples/` (`chat`, `demo-numbers`, `vehicle-cleanup`, etc.; see `examples/README.txt`). To install a resource, copy its folder into `resources/` and restart the server. Start with `examples/chat` → `resources/chat`: it provides chat and `/` commands ([Resources and content](/hosting/resources/#installing-a-resource)). The minimal custom resource is `hello` from [Getting started](/plugins/getting-started/).
