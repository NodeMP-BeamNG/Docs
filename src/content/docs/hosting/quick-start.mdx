import { Tabs, TabItem } from '@astrojs/starlight/components';

`Node-Server` is the program players connect to. Getting one running and into the launcher's list
takes five steps:

1. [Download and start it](#1-download-and-start).
2. [Open the port](#2-open-the-port), TCP and UDP.
3. [Give it a name, a map and slots](#3-name-map-and-slots).
4. [Get it listed](#4-get-listed) with a server key.
5. [Join it](#5-join-it) from the launcher.

## What you need

- A machine players can reach on one port, TCP and UDP (`30814` unless you pick another). At home,
  that means forwarding the port on your router.
- Windows x64, or a Linux x64 as new as Ubuntu 24.04 (the binary needs glibc 2.38 and the C++
  library of GCC 13). On an older Linux, use the Docker image.
- To be listed: a NodeMP account at [nodemp.com](https://nodemp.com). An unlisted server needs no
  account at all; players join it by address.

## 1. Download and start

The server is published on [GitHub releases](https://github.com/NodeMP-BeamNG/releases) under the
tag `server-v1.8.0`: `Node-Server-1.8.0-windows-x64.zip`, `Node-Server-1.8.0-linux-x64.tar.gz` and
the Docker image `nodemp-server-v1.8.0-image.tar`, each with a `.sha256` file to check the download
against.

<Tabs>
<TabItem label="Windows">

In PowerShell:

```powershell
New-Item -ItemType Directory -Force C:\NodeMP | Out-Null
Set-Location C:\NodeMP
$base = "https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.8.0"
Invoke-WebRequest "$base/Node-Server-1.8.0-windows-x64.zip" -OutFile Node-Server-1.8.0-windows-x64.zip
Invoke-WebRequest "$base/Node-Server-1.8.0-windows-x64.zip.sha256" -OutFile Node-Server-1.8.0-windows-x64.zip.sha256
(Get-FileHash Node-Server-1.8.0-windows-x64.zip).Hash.ToLower() -eq (Get-Content Node-Server-1.8.0-windows-x64.zip.sha256).Split(' ')[0]
Expand-Archive Node-Server-1.8.0-windows-x64.zip -DestinationPath .
.\Node-Server.exe
```

The comparison line prints `True` when the download is intact. Leave the window open while the
server runs; it doubles as the [server console](/hosting/administration/#the-console).

</TabItem>
<TabItem label="Linux">

```bash
sudo mkdir -p /opt/nodemp && sudo chown "$USER" /opt/nodemp
cd /opt/nodemp
base=https://github.com/NodeMP-BeamNG/releases/releases/download/server-v1.8.0
curl -LO "$base/Node-Server-1.8.0-linux-x64.tar.gz"
curl -LO "$base/Node-Server-1.8.0-linux-x64.tar.gz.sha256"
sha256sum -c Node-Server-1.8.0-linux-x64.tar.gz.sha256
tar -xzf Node-Server-1.8.0-linux-x64.tar.gz
sudo apt install -y lua5.1
NODE_LUA=/usr/bin/lua5.1 ./Node-Server
```

`lua5.1` is what the server uses to scramble the scripts plugins send to players; without it the
server still runs and sends those scripts as plain text.

</TabItem>
<TabItem label="Docker">

The release has the image as a file. Load it once:

```bash
docker load -i nodemp-server-v1.8.0-image.tar
```

Docker answers `Loaded image: nodemp-server:1.8.0-e11def6`; that tag is what you run. In the image
the server takes its settings from environment variables only (`NODE_NAME` for `[General] Name`,
and so on) and keeps everything it writes in `/data`, as user id 10001:

```bash
mkdir -p data && sudo chown 10001:10001 data
docker run -d --name nodemp-server --restart unless-stopped \
  -p 30814:30814/tcp -p 30814:30814/udp \
  -v "$PWD/data:/data" \
  -e NODE_NAME="My server" \
  -e NODE_MAP=/levels/west_coast_usa/info.json \
  -e NODE_MAX_PLAYERS=16 \
  -e NODE_MAX_CARS=2 \
  -e NODE_TLS_CERT=/data/tls/node_cert.pem \
  -e NODE_TLS_KEY=/data/tls/node_key.pem \
  nodemp-server:1.8.0-e11def6
docker logs -f nodemp-server
```

Two lines in there matter more than they look:

- `data/` has to belong to user 10001 before the first start, or the server can't write its files.
- `NODE_TLS_CERT` and `NODE_TLS_KEY` must point into `/data`. By default the certificate goes next
  to the executable, which is read-only in the image, and the server stops at start with
  `TLS: cannot write /opt/node/node_key.pem (…)`.

To change a setting, remove the container (`docker rm -f nodemp-server`) and run it again with new
variables; everything in `data/` stays. [Keeping it running](/hosting/running/#docker-compose) has
the same setup as a Compose file.

</TabItem>
</Tabs>

On the first start the server writes `server.toml` with every setting at its default, makes itself
a TLS certificate, creates `content/` and `logs/`, and starts. After a banner with its version,
name, port and map, these lines are the ones to look for:

```
no config file server.toml yet; writing one with every default
generated a new self-signed TLS certificate (node_cert.pem)
TLS 1.3 enabled — certificate fingerprint (SHA-256): …
listening on [::]:30814 (tcp, tls 1.3, dual-stack: IPv4 + IPv6)
client obfuscation ready · runner lua5.1.exe · Prometheus (cache .obfcache)
0 resources · 1 module loaded
server is ready
```

A warning that no database is configured is normal: the database module ships with the server and
waits until a plugin needs it. Stop the server with Ctrl+C, or type `stop` in its window.

## 2. Open the port

Allow port 30814, TCP and UDP, in the firewall, and forward both on your router if the machine is
behind one. On Windows, run this in a PowerShell opened **as administrator**:

```powershell
New-NetFirewallRule -DisplayName "Node-Server TCP" -Direction Inbound -Protocol TCP -LocalPort 30814 -Action Allow
New-NetFirewallRule -DisplayName "Node-Server UDP" -Direction Inbound -Protocol UDP -LocalPort 30814 -Action Allow
```

On Linux with `ufw`:

```bash
sudo ufw allow 30814/tcp
sudo ufw allow 30814/udp
```

## 3. Name, map and slots

Open `server.toml` (in Docker: the `-e` variables above). Most servers change only these:

```toml
[General]
Name = "My server"
Map = "/levels/west_coast_usa/info.json"
MaxPlayers = 16
MaxCars = 2
```

The server reads the file at start, so restart it after a change. The server writes this file only
once and never overwrites your edits. Everything else is on [server.toml](/hosting/configuration/).

## 4. Get listed

A server shows up in the launcher's list once it introduces itself to NodeMP with a **server key**.
Create one in your account at [nodemp.com/account/servers](https://nodemp.com/account/servers)
([Get listed](/hosting/registering/) walks through it), then:

- **Windows and Linux:** `server.toml` already has a `[Directory]` table with empty values. Fill in
  `Url`, `HostId` and `HostSecret` there.
- **Docker:** add `-e NODE_DIRECTORY_URL=https://api.nodemp.com`, `-e NODE_DIRECTORY_HOST_ID=…` and
  `-e NODE_DIRECTORY_HOST_SECRET=…`.

:::caution[Don't paste a second [Directory] table]
TOML doesn't allow the same table twice, and the server then refuses to start with
`the table [Directory] appears twice. Put the keys into the existing [Directory] table …`. Fill in
the table that is already there.
:::

Restart. The log says `announcing this server to https://api.nodemp.com` and, once NodeMP accepted
the key, `listed in the server browser`. If that second line never comes,
[Get listed → Troubleshooting](/hosting/registering/#troubleshooting) has the messages.

## 5. Join it

Start the launcher, open **Servers** and find your server by name, or use **Direct Connect** with
your public address and port, such as `203.0.113.10:30814`. Direct Connect also works for a server
without a key.
